# 2-1. 사용자 스토리

이 문서는 학생 사용자가 LinKHU로 무엇을 하려고 하는지를 스토리 단위로 고정한다. 각 스토리에는 현재 코드가 실제로 보장하는 완료 조건을 붙였다. 화면 동작을 바꾸는 PR은 여기 적힌 완료 조건을 깨지 않았는지 확인해야 한다.

여기 적힌 것은 "사용자가 기대하는 결과"이고, 그 결과를 만드는 구조는 [3-1 아키텍처](3-1-DESIGN-SOFTWARE-ARCHITECTURE.md)에 있다. 검증 방법은 [5-TESTING](5-TESTING.md)에 있다.

```text
§2-1-1   팝업 열기            툴바와 단축키로 진입
§2-1-2   바로가기 이동         클릭, 배경 탭, 휠 클릭
§2-1-3   검색                 이름·id·카테고리로 찾기
§2-1-4   숫자 단축키           손을 마우스로 옮기지 않고 열기
§2-1-5   내 바로가기 구성       설정 페이지에서 고르고 정렬
§2-1-6   버전 확인과 문의       업데이트 안내, 의견 보내기
§2-1-7   후속 과제
```

## 2-1-1 팝업 열기

> 학생으로서, 브라우저 어디에 있든 교내 서비스 목록을 즉시 열고 싶다.

- 툴바의 LinKHU 아이콘을 누르면 팝업이 열린다.
- 키보드 단축키로도 열 수 있다. 기본값은 `Ctrl+Shift+L`(macOS는 `Command+Shift+L`)이며, 매니페스트의 `_execute_action`에 제안값으로 등록되어 있다.
- 브라우저가 단축키를 자동 등록하지 않았을 수 있으므로, 설정 페이지는 단축키가 비어 있으면 안내 박스를 노출해야 한다 (MUST). 안내는 Chrome·Whale·Firefox의 단축키 설정 경로를 각각 제시한다.

> **제약**: 매니페스트의 단축키는 **제안일 뿐 보장이 아니다.** 다른 프로그램이 이미 쓰는 조합이면 등록되지 않고, 확장이 그 조합을 빼앗을 수도 없다. 따라서 "단축키가 동작하지 않는다"는 정상 범위의 상태이며, 제품은 이를 **감지해 안내하는 것까지만** 할 수 있다. 근거와 대안 검토는 [3-3](3-3-DESIGN-DECISIONS.md)에 있다.

**완료 조건**
- 팝업이 열리면 저장된 `userOrder` 순서대로 카드가 렌더링된다.
- `userOrder`가 없으면 기본 목록 10개가 이름 가나다순으로 표시된다([4-DATA](4-DATA.md) §4-3 기본 목록).
- 표시할 항목이 없으면 빈 상태 메시지를 보여준다.

## 2-1-2 바로가기 이동

> 학생으로서, 목록에서 서비스를 눌러 바로 이동하고 싶다. 여러 개를 한꺼번에 열어두고 싶을 때도 있다.

세 가지 입력을 구분해서 처리한다.

| 입력 | 동작 |
| --- | --- |
| 일반 클릭 | 새 탭을 **활성 상태**로 열고 팝업을 닫는다 |
| `Ctrl`/`Cmd` + 클릭 | 새 탭을 **배경**으로 열고 팝업을 **닫지 않는다** |
| 휠(가운데) 클릭 | 새 탭을 **배경**으로 연다 |

`Ctrl`/`Cmd` 클릭과 휠 클릭에서 팝업이 유지되는 것이 핵심이다. 학기 초처럼 여러 서비스를 연달아 열어야 할 때 팝업을 다시 열지 않아도 된다.

카드는 `<a href>`로 만들되 클릭 기본 동작은 막고 확장 API로 탭을 연다 (MUST). 팝업 안에서 링크가 그대로 열리면 팝업 화면 자체가 이동해버리기 때문이다.

**완료 조건**
- 세 입력이 위 표대로 동작한다.
- 서비스 아이콘 로딩에 실패하면 확장 기본 아이콘(`icons/icon48.png`)으로 대체되어, 깨진 이미지가 보이지 않는다.
- 같은 id가 중복 저장되어 있어도 카드는 한 번만 렌더링된다.

## 2-1-3 검색

> 학생으로서, 목록을 눈으로 훑지 않고 이름을 입력해 찾고 싶다.

- 검색 대상은 서비스 **이름, id, 카테고리** 세 가지다.
- 검색어와 대상 모두 소문자화(`ko-KR` 기준)하고 공백을 제거한 뒤 비교한다. "e campus"와 "ecampus"가 같게 취급된다.
- 검색 중에는 `userOrder`가 아니라 `MASTER_SITE_LIST` 전체를 대상으로 한다. 담아두지 않은 서비스도 찾을 수 있어야 하기 때문이다.
- 결과 정렬 우선순위는 다음과 같다 (MUST). 같은 점수 안에서는 `MASTER_SITE_LIST` 정의 순서를 유지한다.

```text
0  이름이 검색어로 시작
1  이름에 검색어 포함
2  id가 검색어로 시작
3  id에 검색어 포함
4  카테고리에 검색어 포함
```

- `/` 키를 누르면 검색창으로 포커스가 이동한다. 입력 요소 안이거나 조합 키가 눌린 상태면 동작하지 않는다.
- 검색창에서 `Enter`를 누르면 첫 번째 결과를 **현재 탭**에서 연다. 한글 입력 조합 중(`isComposing`)에는 동작하지 않아야 한다 (MUST).

**완료 조건**
- 일치하는 결과가 없으면 빈 상태 메시지를 보여준다.
- 검색 입력을 빠르게 연타해도 이전 렌더 결과가 뒤늦게 덮어쓰지 않는다.

## 2-1-4 숫자 단축키

> 학생으로서, 자주 쓰는 앞쪽 바로가기는 키보드만으로 열고 싶다.

- 팝업에서 `1`~`9` 키를 누르면 화면에 보이는 순서대로 n번째 카드를 연다.
- 입력 요소에 포커스가 있거나 `Ctrl`/`Alt`/`Cmd`가 함께 눌렸거나 키가 눌린 채 반복 중이면 동작하지 않는다 (MUST). 검색어에 숫자를 입력할 수 없게 되면 안 된다.
- 카드를 클릭한 것과 같은 경로를 타므로, 열리는 방식은 §2-1-2의 일반 클릭과 같다.

## 2-1-5 내 바로가기 구성

> 학생으로서, 내 전공과 학년에 맞는 서비스만 팝업에 두고 원하는 순서로 정렬하고 싶다.

설정 페이지는 두 열로 구성된다. 왼쪽은 담을 수 있는 전체 서비스를 카테고리별로 나눠 보여주고, 오른쪽은 내 바로가기다. 카테고리는 [4-DATA](4-DATA.md) §4-2가 정한 여덟 개이며, 화면의 영역 순서도 그 목록 순서를 따른다.

- 왼쪽 목록은 이름 기준 한국어 정렬(`localeCompare("ko-KR")`)로 표시한다.
- 이미 오른쪽에 담긴 서비스는 왼쪽에서 사라진다. 같은 항목이 양쪽에 동시에 보이지 않는다.
- 항목을 오른쪽으로 드래그하면 담기고, 왼쪽으로 드래그하면 원래 카테고리 자리로 되돌아간다.
- 오른쪽 안에서 드래그하면 순서가 바뀐다. 이 순서가 팝업 표시 순서다.
- 목록이 길어 화면을 넘어갈 때, 드래그 중 스크롤 영역의 위·아래 가장자리(40px 이내)로 포인터를 가져가면 자동으로 스크롤된다 (MUST). 이 보조가 없으면 학과 68개 목록에서 상단으로 항목을 옮길 수 없다.
- 항목 오른쪽 끝의 링크를 누르면 그 서비스가 **새 탭에서 열린다.** 이름만 보고 담을지 정하지 않아도 되도록, 어떤 사이트인지 먼저 확인할 수 있게 하는 장치다. 왼쪽 목록과 오른쪽 '내 바로가기' 양쪽에 같은 형태로 붙는다.
  - 링크에서 시작한 드래그는 취소한다 (MUST). 링크를 끌었을 뿐인데 항목이 딸려가면 담기·순서 바꾸기가 의도치 않게 일어난다.
- 설정 페이지에도 검색창이 있고 `/` 단축키가 동작한다.
- 검색창 아래에 카테고리 필터가 있다. 카테고리마다 칩 하나씩이며, 목록이 길어 검색만으로는 좁히기 어려운 경우를 위한 보조 수단이다.
  - **고른 카테고리가 하나도 없으면 전체를 표시한다.** 전부 끄는 것과 필터를 걸지 않은 것이 같은 상태다. 별도의 "전체" 버튼을 두지 않는다.
  - 카테고리 필터와 검색어는 **AND**로 걸린다 (MUST). 필터로 뺀 카테고리는 검색어가 일치해도 결과에 나오지 않는다.
  - 필터 상태는 저장하지 않는다. 페이지를 다시 열면 전체 표시로 돌아온다.
- 검색어나 필터로 좁혀 보는 중일 때, 결과가 없는 카테고리 그룹은 숨기고, 전체 결과가 0건이면 빈 상태 문구를 보여준다.
- **좁혀 보기는 왼쪽 목록의 표시에만 영향을 준다** (MUST). 오른쪽 '내 바로가기'는 검색어나 필터의 영향을 받지 않는다. 저장 순서는 오른쪽 목록에서 읽으므로, 왼쪽에서 숨겨진 항목 때문에 저장 데이터가 바뀌어서는 안 된다.

**완료 조건**
- **저장 버튼을 눌러야 저장된다.** 드래그만으로는 저장되지 않는다.
- 검색어나 카테고리 필터가 걸린 상태에서 저장해도, 저장되는 순서는 필터를 걸지 않았을 때와 같다.
- 저장에 성공하면 성공 알림을, 실패하면 실패 알림을 띄운다. 실패를 조용히 넘기지 않는다 (MUST).
- 저장 후 페이지를 새로고침하거나 팝업을 다시 열면 그 순서가 유지된다.

## 2-1-6 버전 확인과 문의

> 학생으로서, 내가 쓰는 버전이 최신인지 알고 싶고, 불편한 점을 개발자에게 알리고 싶다.

- 팝업 헤더에 현재 버전을 `v{version}` 형태로 표시한다.
- 최신 릴리스보다 낮으면 업데이트 안내 링크를 함께 보여준다. 링크는 사용자의 브라우저에 맞는 스토어로 연결한다 (Whale / Firefox / 그 외 Chrome). 스토어를 통해 설치하지 않은 개발 모드에서는 GitHub 릴리스 페이지로 연결한다.
- 최신 버전 조회는 12시간 캐싱한다 (MUST). GitHub API rate limit을 넘기지 않기 위해서다. 조회에 실패하면 캐시된 값을 쓰고, 그것도 없으면 안내를 표시하지 않는다. 버전 조회 실패가 팝업 사용을 막아서는 안 된다.
- 팝업과 설정 페이지 하단의 **문의하기**로 GitHub 계정 없이 의견을 보낼 수 있다. 답변받을 이메일은 선택 입력이다.

**완료 조건**
- 문의 내용이 비어 있으면 전송하지 않고 입력을 요구한다.
- 이메일을 입력했는데 `@`가 없으면 전송하지 않고 확인을 요구한다.
- 전송 중에는 버튼을 비활성화하고, 성공·실패 결과를 문구로 알린다.

## 2-1-7 후속 과제

**상태: 후속 과제 후보.** 확정된 계약이 아니며 착수 시점도 정해지지 않았다. 구현하지 않아도 규칙 위반이 아니다.

### 키보드로 순서 바꾸기

현재 설정 페이지의 순서 변경은 **드래그 앤 드롭 전용이다.** 마우스나 터치를 쓰기 어려운 사용자는 내 바로가기를 구성할 수 없다. 항목마다 새 탭 링크(§2-1-5)가 있어 Tab으로 도달할 수 있지만, 그 링크는 어떤 사이트인지 확인하는 용도이지 담기·빼기·순서 변경을 대신하지 않는다.

대안은 항목마다 위·아래 이동 조작을 두는 방식이다. 화면 구조와 조작 흐름이 함께 바뀌는 범위라 별도 작업으로 분리해 둔 상태다. 착수 시 다음을 만족해야 한다 (MUST).

- 드래그로 할 수 있는 모든 조작(담기, 빼기, 순서 변경)을 키보드만으로 할 수 있다.
- 현재 위치와 이동 결과를 스크린 리더가 읽을 수 있게 알린다.

착수하더라도 **드래그 조작을 대체하는 것이 아니라 병행한다.** 기존 사용자의 조작 방식이 바뀌면 안 된다.
