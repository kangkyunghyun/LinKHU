# 207. ADR·요구사항·설계 번호를 스펙과 같은 계층 번호로 바꾼다

```text
§207-1   배경
§207-2   만들 것
§207-3   완료 조건
§207-4   관련
```

## 207-1 배경

스펙과 가이드는 계층 번호를 쓴다(1, 2-1, 2-2). ADR은 `1-1-BUILDLESS-STATIC.md`처럼 네 자리 일련번호에 소문자 슬러그이고, 요구사항·설계는 이슈 번호에 소문자 슬러그다. 셋 다 섹션 맵과 번호 절이 없어 스펙·가이드와 같은 규칙으로 읽히지 않는다.

## 207-2 만들 것

- ADR 19건을 주제 계층(1 구성과 기술, 2 데이터와 제품, 3 릴리스와 플랫폼, 4 디자인, 5 랜딩과 기여, 6 문서와 작업 방식)으로 묶어 `N-M-UPPER-KEBAB.md`로 다시 매긴다. 옛 번호 대응표를 `docs/adr/README.md`에 남긴다.
- 요구사항·설계는 이슈 번호를 계층 번호로 삼아 `N-UPPER-KEBAB.md`로 바꾸고, 절을 `## N-K`로 매긴다.
- 세 계층 README를 가이드 README와 같은 뼈대로 맞춘다.
- 옛 번호·파일명을 가리키는 링크와 `ADR 00NN` 표기를 전부 갱신한다.

## 207-3 완료 조건

- ADR·요구사항·설계 본문 문장이 번호·제목·링크 외에 바뀌지 않는다
- 옛 파일명·`ADR 00NN` 참조 0곳 (옛 릴리스 노트 제외)
- 모든 번호 문서의 제목·절 번호가 파일명 번호와 일치
- `docs/` 상대 링크·앵커 깨짐 0
- `npm run build`, `git diff --check` 통과

## 207-4 관련

- 이슈: [#207](https://github.com/kangkyunghyun/LinKHU/issues/207)
- ADR: 없음. 번호 규칙은 [../spec/README.md](../spec/README.md)를 따른다. 이번 재번호는 결정이 아니라 표기 이관이다.
- 설계: 없음.
