# ADR 0016: 서비스 아이콘을 테마별 두 벌로 나눔

**상태: 확정 스펙.** 이슈 [#116](https://github.com/kangkyunghyun/LinKHU/issues/116).

**맥락**

서비스 아이콘 115장은 흰 배경에 검정 선화로 그려진 PNG였다. 라이트 테마에서는 문제가 없었지만 다크 테마([3-2-5](../spec/3-2-DESIGN-UI-RULES.md))를 넣자 **어두운 카드 위에 흰 사각형 115개가 떠 보였다.**

핵심 제약은 아이콘이 **래스터 자산**이라는 점이다. UI 아이콘은 SVG라 `currentColor`로 토큰을 상속받지만, 서비스 아이콘은 픽셀이므로 CSS 토큰이 닿지 않는다.

**한 벌로 해결하려던 시도 세 가지 — 모두 실패했다**

| 시도 | 방법 | 왜 실패했나 |
| --- | --- | --- |
| 흰 타일 | 아이콘 뒤에 흰 사각형을 깔아 사각형을 "의도된 것"으로 보이게 | 어두운 화면에서 **눈부시다.** 불투명도를 0.78로 낮춰도 밝은 판 115개라는 성질은 그대로였다 |
| CSS 반전 | 다크에서 `filter: invert(1) hue-rotate(180deg)` | 빨강이 **분홍(`#ffabaf`)으로 바뀐다.** 반전은 밝기를 제어할 수단이 없어 검정 선화가 순백이 된다 |
| 공용 중간톤 | 선화를 양쪽에서 통하는 중간 회색(`#767676`)으로 재색상 | 두 테마의 요구가 반대다. 라이트 대비가 **17:1에서 4.54:1로** 떨어져, 한 벌을 유지하려고 양쪽 다 나빠졌다 |

세 번째가 결정적이었다. 목표색을 `#a1a1aa`까지 밝히면 다크에서 7.06:1로 좋지만 **라이트에서는 2.56:1로 비텍스트 기준 3:1에도 못 미친다.** 반대로 라이트에 맞춰 어둡게 하면 다크가 무너진다. **하나의 색으로 두 배경을 만족시킬 수 없다.**

**결정**

**자산을 두 벌로 나눈다.** 라이트는 배경만 제거해 그대로 쓰고, 다크는 생성기가 `#a1a1aa`·`#d94a52` 두 색으로 다시 칠한다. 규칙은 [3-2-4](../spec/3-2-DESIGN-UI-RULES.md)에 있다.

> **이후 변경:** 라이트 벌의 "원본 도안 색 그대로"는 [ADR 0017](0017-icon-palette-three-colors.md)에서 폐기되었다. 라이트 벌도 정해진 팔레트를 따른다. **두 벌로 나눈다는 이 결정 자체는 유효하다.**

색을 옮길 때 **밝기를 곱하지 않고 알파로 옮긴다.** 이전 재색상 판은 원본의 음영을 보존하려고 목표색에 배율을 곱했는데, 상한에 걸린 픽셀이 `#767676 × 2.0 = #ececec`까지 증폭되어 불투명 픽셀의 43%가 `#cccccc`보다 밝아졌다. 지금은 선화를 단색으로 고정하고 원본의 밝음을 알파(=덮는 정도)로 옮기므로 **목표색보다 밝은 픽셀이 원리적으로 생기지 않는다.**

**영향**

- **자산이 2배가 된다** (115 → 230, 랜딩 사본까지 460). 이 프로젝트에서 감당 가능한 대가로 봤다 — PNG 총량이 작고, 사람이 두 벌을 손으로 관리하지 않기 때문이다.
- **생성기가 스펙의 일부가 된다.** 다크 벌은 손으로 만든 자산이 아니라 라이트 원본에서 재현되는 산출물이다. 그래서 `scripts/`에 커밋하고 `npm run generate:dark-icons`로 등록했다. 색을 조정하려면 상수를 바꾸고 다시 돌린다.
- **짝이 깨질 수 있다.** 새 서비스를 추가하며 라이트만 넣으면 다크에서 그 아이콘만 깨진다. 사람의 주의력에 맡기지 않고 `validate:dark-icons`를 `build`에 넣어 CI가 막는다.
- **아이콘 칸의 배경 하드코딩이 사라졌다.** 두 벌 모두 배경이 투명하므로 랜딩의 `.list-icon`을 `#ffffff` 고정에서 `var(--color-surface)`로 되돌렸다.
- **랜딩은 확장과 다른 방법을 쓴다.** 확장은 저장된 테마 모드가 있어 JS가 경로를 바꾸지만, 랜딩은 `prefers-color-scheme`만 따르므로 `<picture>` + `<source media>`에 맡긴다. 브라우저가 그리기 전에 고르므로 깜빡임이 없고, OS 설정이 바뀌어도 구독 코드가 필요 없다.
- 대가로 **아이콘 하나를 고치려면 두 벌을 다시 만들어야 한다.** 라이트 원본을 교체한 뒤 생성기를 돌리는 절차가 강제된다.
