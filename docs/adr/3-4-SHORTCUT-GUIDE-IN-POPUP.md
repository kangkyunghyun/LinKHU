## 3-4-1 배경

Aside에서 제안 단축키가 비밀번호 자동입력과 충돌해 등록되지 않았다는 문의가 있었다. 설정 페이지의 접힌 안내와 Chrome·Whale·Firefox만 나열한 문구로는 사용자가 자신의 브라우저에서 지정하는 방법을 찾기 어려웠다.

[ADR 3-3](3-3-SHORTCUT-GUIDANCE-NOT-ENFORCED.md)의 “강제하지 않고 감지해 안내한다”는 결정은 그대로 유효하다. 이번 결정은 그 원칙 안에서 안내의 노출 지점과 문구 방식을 넓힌다. 기존 ADR의 상태도 바꾸지 않는다.

## 3-4-2 대안

1. 브라우저별 단축키 제공 — 브라우저별 suggested_key를 따로 지정할 수 없으므로 채택하지 않는다.
2. 기본 조합 변경 — 충돌은 브라우저마다 다르고 기존 사용자의 설정과 사용 흐름을 흔들므로 권하지 않는다.
3. 설정에만 접힌 안내 유지 — 팝업에서 문제를 발견한 사용자에게 안내가 닿지 않는 문제가 남는다.
4. 팝업에 한 줄 안내를 추가하고 설정에서 주소 규칙을 펼쳐 보여준다 — 채택한다.

## 3-4-3 결정

팝업은 chrome.commands.getAll로 등록 여부를 먼저 확인하고, 미등록이며 shortcutNoticeDismissed가 true가 아닐 때만 헤더 아래 안내를 표시한다 (MUST). 브라우저 목록은 설정에만 둔다. 설정에서 지정 버튼은 options.html#shortcut-guide를 새 탭으로 연다.

닫기는 shortcutNoticeDismissed=true를 즉시 저장하고 화면에서 숨긴다. 저장 실패 시 배너를 복구하고 기존 theme-status 상태 줄로 실패를 알린다 (MUST). 성공적으로 닫은 안내는 이후 팝업에서 다시 보이지 않는다.

설정 안내는 접지 않고 미등록일 때만 표시한다. Chromium 기반 브라우저의 내부 주소와 /extensions/shortcuts 규칙을 설명하고 Chrome·Whale·Aside를 예로 든다. Firefox는 about:addons의 관리 경로를 별도로 제시한다. 내부 주소 열기가 실패하면 기존 클립보드 복사와 안내 흐름을 유지한다.

## 3-4-4 영향

미등록 사용자는 팝업에서 설정 안내에 바로 도달한다. 등록된 사용자는 추가 배너를 보지 않는다. 저장 키가 하나 늘어나며 저장 실패를 알리고 화면을 되돌리는 사용자 설정 계약을 따른다.

닫기 선택은 지속되므로 이후에도 미등록 상태여도 팝업 안내를 다시 띄우지 않는다. 설정 페이지 안내는 이 선택과 관계없이 미등록 시 계속 표시된다. 기본 제안키와 권한은 바꾸지 않는다.
