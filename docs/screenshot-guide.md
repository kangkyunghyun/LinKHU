# Screenshot Guide

랜딩 페이지(`docs/index.html`), README 두 개, 스토어 등록 정보에 쓰는 스크린샷의 촬영 기준입니다. **다음 릴리스에서 같은 구도로 다시 찍을 수 있도록** 해상도, 여백, 상태를 고정합니다.

파일은 `docs/assets/screenshots/`에 있고 **파일명을 바꾸지 않습니다** — 랜딩과 README가 경로를 하드코딩하고 있습니다.

## 촬영 대상과 규격

| 파일 | 크기 | 배율 | 내용 |
| --- | --- | --- | --- |
| `screenshot-popup.png` | 640×894 | **2배** (표시 320×447) | 팝업만 |
| `screenshot-options.png` | 1280×800 | 1배 | 설정 페이지 |
| `screenshot.png` | 1280×800 | 1배 | 히어로 — 포털 화면에 팝업을 합성 |

- 팝업만 2배로 찍는다. 랜딩에서 작게(폭 31%) 표시되는데 1배로는 흐려 보인다. 나머지 둘은 크게 표시되므로 1배로 충분하다.
- 랜딩의 `width`/`height` 속성은 **표시 기준 1배 치수**를 적는다(`320`/`447`). 파일 픽셀값을 적으면 두 배 크기로 자리를 잡는다.

## 공통 원칙

- **브라우저 탭바·주소창을 넣지 않는다** (MUST). 랜딩이 `.browser-dots`·`.browser-address`로 프레임을 직접 그리므로, 이미지에도 크롬이 있으면 두 겹이 된다.
- **라이트 테마로 찍는다** (MUST). 기존 이미지가 라이트이고 랜딩·README 레이아웃이 그에 맞춰져 있다. 다크 테마 스크린샷을 추가하려면 배치 자리를 먼저 정해야 한다.
- **검색창은 비운 상태로 찍는다** (MUST). 검색어가 남아 있으면 목록이 걸러진 상태가 찍힌다.
- 툴바 팝업을 띄울 필요가 없다. 확장을 로드한 뒤 확장 페이지를 **직접 열어** 찍는다.

```
chrome-extension://<확장 ID>/popup.html
chrome-extension://<확장 ID>/options.html
```

## 팝업 — `screenshot-popup.png`

- 뷰포트 **320×447**, `deviceScaleFactor: 2` → 결과 640×894.
- 기본 바로가기 9개가 3×3으로 들어차고, 상단 검색창과 하단 링크(`홈페이지 · 문의하기`)까지 잘리지 않아야 한다.
- 세로 447px은 v2.4.0의 자연 높이다. **UI 요소가 늘거나 줄면 이 값을 다시 재고, 랜딩의 `height` 속성도 같이 고친다** (MUST).

## 설정 — `screenshot-options.png`

- 뷰포트 **1280×800**, 1배.
- 왼쪽 `사용 가능한 사이트`와 오른쪽 `내 바로가기`가 모두 보이고, 아래 `변경사항 저장하기` 버튼까지 들어가야 한다.
- 스크롤은 맨 위에 둔다.

## 히어로 — `screenshot.png`

포털 화면 위에 팝업이 열린 것처럼 **합성**한다.

1. `portal.khu.ac.kr`을 뷰포트 **1280×800**으로 찍는다.
2. 팝업을 **우측 상단**에 올린다.

| 값 | 설정 |
| --- | --- |
| 여백 | 위 `20px`, 오른쪽 `16px` |
| 모서리 반경 | `12px` |
| 그림자 | spread `18px`, offset `6px` |

### ⚠️ 포털은 로그인이 필요한 페이지다 — 개인정보 처리 (MUST)

로그인 상태로 찍으므로 이름, 학번, 사진, 장학·메시지 내역이 화면에 있다.

**텍스트를 지우는 방식은 통하지 않는다.** 포털이 비동기로 다시 렌더해 되살아난다. 반드시 다음 순서로 한다.

1. **CSS 규칙으로 숨긴다** (`visibility: hidden`). 요소를 지우지 않으므로 레이아웃이 무너지지 않는다.
2. **스크립트를 멈춘다** — `Emulation.setScriptExecutionDisabled`. 이후 재렌더가 일어나지 않는다.
3. 그 상태에서 촬영한다.

숨김 대상 선택자입니다.

```text
.stu_info_w
li.name.bar_line
.main_user_w
.main_user_box
.comInfo
.user_text01, .user_text02, .user_text03
p.name
img[src*=userPhoto.do]
.portlet[class*=1003]    장학조회 패널 본문
.portlet[class*=1018]    메시지(PUSH) 패널 본문
```

4. **촬영 후 '보이는 텍스트'만 스캔해 개인정보가 없는지 확인한다** (MUST). 숨긴 요소를 제외한 실제 노출 텍스트를 훑는다.
5. 확대해서 눈으로도 한 번 더 확인한다. 작은 글씨는 1280×800에서 읽히지 않으므로 상단 바, 좌측 열, 패널 본문을 2배로 잘라 본다.

**공개 저장소와 스토어에 올라가는 이미지다.** 확신이 없으면 올리지 않는다.

## 촬영 후 확인

- 세 파일의 실제 픽셀 크기가 위 표와 같은지 확인한다.
- `npm run build`를 실행한다.
- 랜딩을 로컬 HTTP 서버로 열어 **라이트·다크 양쪽에서** 레이아웃이 깨지지 않는지 확인한다. 특히 `.popup-frame`은 고정 높이가 없어 이미지 종횡비가 그대로 프레임 높이가 된다.
- README 두 개의 이미지 표를 확인한다. `width`만 있고 `height`가 없으므로 종횡비가 바뀌어도 손댈 필요는 없지만, 표가 깨지지 않는지는 본다.

## 후속 과제 후보

- **다크 테마 스크린샷.** 3단계 테마 전환이 v2.4.0의 주요 기능인데 현재 스크린샷은 라이트만 있어 드러나지 않는다. 추가하려면 랜딩과 README에 배치 자리를 새로 만들어야 하므로 별도 작업으로 다룬다.
