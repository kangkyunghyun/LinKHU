# 4-2. UI 시스템

이 문서는 경희대 공식 색상의 사용 규칙, 디자인 토큰의 원본과 이름 규칙, 확장과 랜딩 중 무엇이 디자인 기준인지, UI 아이콘 규칙을 정한다.

테마별 색 토큰 값과 대비 기준은 테마에, 서비스 아이콘 규칙은 서비스 아이콘에, 문의 유형의 순서와 값은 계약에 있다. ([4-3-4 구현 방식과 토큰 계약](4-3-THEME.md#4-3-4-구현-방식과-토큰-계약), [4-3-5 대비 기준](4-3-THEME.md#4-3-5-대비-기준), [4-6 서비스 아이콘](4-6-SERVICE-ICON.md), [5-3 Google Forms](5-CONTRACT.md#5-3-google-forms))

<br>

## 4-2-1 경희대 공식 색상표

LinKHU는 경희대학교 공식 색상 체계를 쓴다. 주색은 **Kyung Hee Red**다.

| 이름 | PANTONE | RGB | HEX | 역할 |
| --- | --- | --- | --- | --- |
| **Kyung Hee Red** | 201C | 164, 15, 22 | `#a40f16` | **주색.** 로고, 강조 텍스트, 기본 버튼 |
| Kyung Hee Blue | 295C | 13, 50, 111 | `#0d326f` | 보조색 |
| Kyung Hee Gold | 872C | 192, 163, 83 | `#c0a353` | 보조색 |
| Cool Gray | 11C | 113, 113, 113 | `#717171` | 보조색 (중성) |
| Silver | 877C | 181, 181, 181 | `#b5b5b5` | 보조색 (중성) |

RGB(173, 29, 25)는 UI에 쓰지 않는다. 인쇄물 휘장 상단 Bar를 재현하려는 보정색이며 화면 UI의 브랜드 레드가 아니다. Kyung Hee Red와 눈으로 구분하기 어려워 섞이기 쉬우므로 명시해 금지한다.

| 규칙 | 내용 |
| --- | --- |
| 브랜드 레드 | 필요한 모든 자리에 `#a40f16` 계열을 쓴다 |
| 보조색 | Blue와 Gold는 UI에서 쓰지 않는다. 쓰지 않는 토큰은 팔레트를 읽는 사람이 실제 사용 색으로 오해하므로 두지 않는다 |
| 보조색 도입 | 용도를 먼저 정하고 토큰으로 추가한다. 일회성 하드코딩으로 넣지 않는다 |
| 중성 회색 | 공식 색상표 값에 묶이지 않는다. 텍스트와 테두리 회색은 가독성 기준으로 정한다 |
| 대학 상징 | 대학 로고나 휘장을 쓰지 않는다. LinKHU는 경희대학교 공식 산출물이 아니다 |
| 확장 로고 | 확장 아이콘(`src/icons/`), 랜딩 사본(`landing/assets/linkhu-icon.png`), 스토어 홍보 타일(`landing/assets/store/promotion-tile.png`)은 `#a40f16`을 쓴다 |

## 4-2-2 디자인 토큰 규칙

**1. 원본**

확장 화면의 색, 여백, 반경, 그림자, 글자 크기의 원본은 `src/theme.css`의 CSS 변수다. `popup.html`과 `options.html`은 각자의 스타일시트보다 `theme.css`를 먼저 불러온다.

| 규칙 | 내용 |
| --- | --- |
| 모든 색은 토큰을 거친다 | 브랜드 레드, 중성 회색, 기능색 모두 해당한다. 확장 CSS와 HTML 인라인 스타일에 hex나 `rgba()`를 새로 쓰지 않는다 |
| 색 토큰은 용도 이름이다 | 새 색이 필요하면 `theme.css`에 용도를 나타내는 이름으로 추가한다. `--red-2` 같은 값 기반 이름을 쓰지 않는다 |
| 기능색도 테마에 따라 달라지면 토큰이다 | 새 버전 안내처럼 브랜드와 무관한 색이라도 라이트와 다크에서 같은 값으로 대비를 만족할 수 없으면 토큰으로 둔다 |
| SVG 표현 속성 | `stroke`와 `fill` 표현 속성은 CSS 변수를 받지 못한다. 토큰이 필요하면 `style` 속성으로 쓴다. `fill="currentColor"` 아이콘은 부모의 `color`를 상속하므로 해당하지 않는다 |
| CSS를 해석하지 않는 자리 | 랜딩의 `<meta name="theme-color">`처럼 CSS를 해석하지 않는 자리에는 리터럴 hex를 쓴다 |

<br>

**2. 랜딩과의 값 동기**

`landing/landing.css`는 자체 CSS 변수에 같은 이름의 브랜드 토큰을 값만 복제해서 갖는다. GitHub Pages는 `landing/` 폴더만 배포하므로 랜딩에서 `src/theme.css`를 참조하면 배포된 사이트에서 파일을 찾지 못한다. 빌드 없는 구성을 지키려고 파일 공유 대신 값 동기를 쓴다.

| 토큰 | 동기 |
| --- | --- |
| `--color-primary` | 라이트와 다크 모두 필수 |
| `--color-primary-fill` | 라이트와 다크 모두 필수 |
| `--color-primary-fill-strong` | 라이트와 다크 모두 필수 |
| `--color-primary-strong` | 라이트와 다크 모두 필수 |
| `--color-primary-soft` | 라이트와 다크 모두 필수 |
| `--color-on-primary` | 라이트와 다크 모두 필수 |
| 표면과 중성 계열 | 하지 않음 |
| 확장 전용(`--color-primary-border`, `--color-primary-ring`, `--color-primary-shadow`, `--color-notice`) | 대상 아님 |
| 랜딩 전용(`--color-focus`, `--color-on-primary-muted`, `--color-flow-accent`) | 대상 아님 |

- 동기 토큰 여섯 개는 두 파일의 값이 같아야 한다. 한쪽을 바꾸면 같은 PR에서 다른 쪽도 바꾼다.
- 사용자는 랜딩에서 확장을 보고 설치하므로 두 화면의 브랜드 톤이 다르면 다른 제품처럼 보인다.
- 표면과 중성 계열은 값이 달라도 된다. 확장은 도구이고 랜딩은 홍보 페이지라 배경과 여백의 성격이 다르다.
- 두 파일의 토큰 정의에는 서로를 가리키는 동기 유지 주석이 있다. 토큰을 추가하거나 바꿀 때 이 주석을 지우지 않는다.

<br>

**3. 간격 스케일**

확장 CSS의 여백(`padding`, `margin`, `gap`)은 모두 이 스케일을 거친다. 색과 달리 테마별로 갈리지 않으므로 테마별로 재정의하지 않는다.

| 토큰 | 값 |
| --- | --- |
| `--space-4` | `4px` |
| `--space-8` | `8px` |
| `--space-12` | `12px` |
| `--space-16` | `16px` |
| `--space-20` | `20px` |
| `--space-24` | `24px` |
| `--space-32` | `32px` |

| 규칙 | 이유 |
| --- | --- |
| 새 여백은 이 스케일에서 고른다 | 값을 자리마다 따로 정하면 5px, 7px, 10px이 섞여 같은 성격의 여백이 화면마다 달라진다 |
| 4px 배수만 둔다 | 고를 수 있는 값이 몇 개뿐이라 고민 없이 집어도 화면이 어긋나지 않는다 |
| 이름은 값 그대로다. `--space-8`은 `8px`이다 | 단계 번호(`--space-2` = 8px)를 쓰면 읽을 때마다 곱해야 한다. 여백은 용도가 아니라 크기로 고른다 |
| 쓰는 값만 정의한다 | 새 크기가 필요하면 4px 배수로 토큰을 먼저 추가하고 참조한다 |
| 여백 전용이다. 반경, 글자 크기, 높이, 너비, 포커스 표시 간격에 쓰지 않는다 | 크기가 우연히 같다고 끌어다 쓰면 스케일을 조정할 때 무관한 것이 함께 움직인다 |

값은 가장 가까운 배수로 기계적으로 고르지 않고 그 자리가 하는 일로 고른다. 왜 그 값인지 한 줄로 답할 수 없으면 아직 정한 것이 아니다.

| 자리 | 값 | 이유 |
| --- | --- | --- |
| 설정 목록 스크롤 영역의 오른쪽 거터 | `8px` | 스크롤바(`6px`)를 피하는 자리다. `4px`이면 스크롤바와 내용이 겹친다 |
| 목록 항목의 새 탭 링크 안쪽 여백 | `4px` | 16px 아이콘에 더해 클릭 대상이 정확히 24×24가 된다. WCAG 2.2의 최소 타깃 크기다. 더 키우면 말줄임되는 이름의 폭을 뺏는다 |
| 아이콘 버튼 안쪽 여백 | `8px` | 클릭 대상 크기라 줄이지 않는다 |

목록 항목 높이처럼 여백과 함께 움직이는 값은 여백을 조정할 때 같이 본다.

<br>

**4. 반경과 그림자**

확장 CSS에 `border-radius`나 `box-shadow` 리터럴을 새로 쓰지 않는다.

| 토큰 | 값 | 쓰이는 곳 |
| --- | --- | --- |
| `--radius-4` | `4px` | 포커스 표시, 스크롤바 손잡이 |
| `--radius-8` | `8px` | 입력, 버튼, 아이콘 버튼, 목록 항목, 드롭 영역 |
| `--radius-12` | `12px` | 팝업 카드, 떠 있는 문의 패널 |
| `--radius-pill` | `999px` | 카테고리 필터 칩, 문의 유형 칩 |
| `--shadow-card` | `0 4px 6px var(--color-shadow)` | 팝업 카드 평상시 |
| `--shadow-card-hover` | `0 6px 12px var(--color-primary-shadow)` | 팝업 카드 hover |
| `--shadow-focus-ring` | `0 0 0 3px var(--color-primary-ring)` | 입력 요소 포커스 링 |
| `--shadow-panel` | `0 8px 24px var(--color-shadow)` | 떠 있는 문의 패널 |
| `--shadow-drop-target` | `inset 0 0 0 1px var(--color-primary-border)` | 드래그 중 놓을 수 있는 영역의 안쪽 윤곽 |

| 토큰 | 이름 규칙 | 이유 |
| --- | --- | --- |
| 반경 | 값 이름. `--radius-8`은 `8px` | 여백처럼 크기로 고르는 값이다 |
| 그림자 | 역할 이름. `--shadow-card`, `--shadow-panel` | 무엇을 띄우는지로 고르고, 오프셋과 번짐과 색의 조합이라 이름에 값을 담을 수 없다 |

`--radius-pill`은 완전히 둥근 모양이라는 의도를 이름으로 남긴 값이다. 상자 높이의 절반 이상이면 어떤 값이든 같은 알약 모양이 되고 브라우저가 상자 크기에 맞춰 반경을 잘라 낸다. 높이 32px인 칩은 `999px`이어도 `16px`로 그려진다.

랜딩은 자기 반경과 그림자 세트(`--radius-sm`, `--radius-md`, `--radius-lg`, `--shadow-sm`, `--shadow-md`)를 따로 가진다. 홍보 페이지라 반경과 그림자의 성격이 다르기 때문이다. 확장은 숫자 이름, 랜딩은 크기 이름이라 두 세트의 이름이 겹치지 않는다. 한쪽에 토큰을 추가할 때 다른 쪽 이름과 같아지지 않게 한다.

<br>

**5. 글자 크기**

확장 CSS에 `font-size` 리터럴을 새로 쓰지 않는다.

| 토큰 | 값 | 쓰이는 곳 |
| --- | --- | --- |
| `--text-title` | `20px` | 팝업 헤더의 제품 이름 |
| `--text-heading` | `16px` | 설정 화면의 단 제목, 저장 버튼 |
| `--text-body` | `13px` | 기본값. 입력, 버튼, 목록 이름, 안내 문단 |
| `--text-caption` | `12px` | 보조 문구. 버전 표시, 상태 알림, 푸터 링크 |
| `--text-card-label` | `12px` | 팝업 카드 이름. 카드 폭이 정하는 고정값 |

글자 크기 토큰은 역할 이름이다. 여백과 반경은 크기로 고르지만 글자는 용도로 고른다. 보조 문구가 12px이어서 `--text-caption`을 쓰는 것이 아니라 보조 문구여서 쓴다. 본문 크기를 한 단 올릴 때 "보조 문구는 본문보다 한 단 아래"라는 관계가 유지되려면 이름이 용도를 가리켜야 한다. 정리하면 크기로 고르는 것은 값 이름, 용도로 고르는 것은 역할 이름이다.

단계는 쓰는 것만 만든다. 2px 구간에 여러 단계를 두면 눈으로 구분되지 않으면서 고를 때만 헷갈린다.

`--text-card-label`은 `--text-caption`과 값이 같지만 성격이 달라 따로 둔다. 한 줄 70.67px에 한글 여섯 자(69px)가 들어가야 하는 카드 폭이 정하는 값이다. 본문 크기를 올려도 이 값은 함께 올리지 않는다. 데이터 검증이 줄바꿈 표의 두 줄이 각각 폭에 들어가는지 검사한다.

랜딩은 이 스케일을 쓰지 않고 자기 글자 크기를 따로 갖는다.

<br>

**6. 같은 기능은 같은 토큰**

팝업과 설정에 같은 기능을 그린 컴포넌트는 같은 토큰을 쓴다. 문의 패널(유형 칩, 본문, 이메일, 보내기, 상태)과 테마 상태 문구가 해당한다.

| 문의 유형 칩 | 규칙 |
| --- | --- |
| 모양 | 설정 페이지의 카테고리 필터 칩과 같은 알약 모양. 팝업과 설정은 `--radius-pill`을 쓰고 랜딩은 랜딩 토큰으로 같은 모양을 그림 |
| 처음 열었을 때 | 아무 유형도 선택하지 않음 |
| 선택 | 한 번에 하나만 선택함 |
| 상태 표시 | 선택한 칩은 `aria-pressed="true"`, 나머지는 `aria-pressed="false"` |

## 4-2-3 확장 우선 원칙

확장 프로그램 UI가 LinKHU의 디자인 기준이고, 랜딩 페이지가 확장을 따른다. 두 화면은 목적이 달라 시각 언어도 다르다.

| 화면 | 성격 | 쓰는 표현 |
| --- | --- | --- |
| 확장 | 제품 그 자체. 320px에서 바로 목표를 달성하는 도구 | 밀도 우선, 장식 없음 |
| 랜딩 | 제품을 소개하는 홍보 페이지. 넓은 화면에서 스크롤하며 읽음 | 큰 여백, 그라디언트, 글로우, 애니메이션 |

- 브랜드 색이 바뀌면 확장을 기준으로 정하고 랜딩이 따라온다.
- 랜딩의 표현(장식 그라디언트, 글로우, 큰 여백, 스크롤 연출)을 확장 UI로 가져오지 않는다.
- 랜딩 고유의 시각 요소는 랜딩 안에서만 쓴다. 랜딩을 확장과 똑같이 만들지 않아도 된다.
- 확장 UI는 정보 밀도와 조작 속도를 우선한다. 장식이 조작을 느리게 만들면 장식을 뺀다.

<br>

## 4-2-4 UI 아이콘

LinKHU에는 성격이 다른 두 종류의 아이콘이 있고, 둘을 섞어서 다루지 않는다.

| 종류 | 의미 | 위치 |
| --- | --- | --- |
| UI 아이콘 | 화면 기능을 나타내는 기호. 설정, 검색, 테마 전환 등 | 팝업, 설정, 랜딩 마크업의 인라인 SVG |
| 서비스 아이콘 | 교내 웹서비스를 나타내는 그림. 인포21, e-Campus 등 | `src/images/`, 랜딩 검색 결과 |

UI 아이콘의 출처는 [Reicon](https://github.com/huntiezz/reicon)이다(MIT, 24×24 그리드, Outline 굵기).

| 규칙 | 이유 |
| --- | --- |
| 새 UI 아이콘은 Reicon에서 고른다. 직접 그리거나 다른 아이콘 세트를 섞지 않는다 | 굵기와 모서리 처리가 달라지면 화면이 지저분해진다 |
| npm 패키지를 추가하지 않고 필요한 SVG 마크업만 인라인으로 가져온다 | 의존성 없는 구성을 지킨다 |
| 색은 `fill="currentColor"`로 두고 부모의 `color`를 상속하거나 `style="color: var(--color-...)"`로 준다 | 색 값을 직접 쓰지 않는다 |
| 돋보기와 홑화살괄호처럼 stroke 기반인 아이콘은 SVG 표현 속성 규칙을 그대로 지킨다 | 대부분의 Reicon 아이콘은 fill 기반이다 |
| `viewBox`는 `0 0 24 24`를 유지하고 표시 크기만 `width`와 `height`로 정한다 | |
| 장식 아이콘에는 `aria-hidden="true"`를 붙이고, 의미가 있는 아이콘은 인접 텍스트나 `aria-label`로 대체 텍스트를 준다 | |

설정 페이지의 제목과 카테고리 라벨을 포함해 화면의 모든 UI 기호는 Reicon 아이콘이다. 이모지를 UI 기호로 쓰지 않는다. 이모지는 운영체제와 글꼴에 따라 다른 그림으로 나오므로 아이콘 세트를 통일해도 이모지가 섞이면 일관성이 무너진다. 크기, 색, 정렬을 CSS로 다루기도 어렵다. 본문이나 안내 문구 속 이모지는 이 규칙의 대상이 아니다.

Chrome, Firefox, Whale 로고는 각 회사의 브랜드 자산이므로 Reicon으로 바꾸지 않고 공식 원본을 그대로 쓴다.
