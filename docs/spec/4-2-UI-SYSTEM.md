사용할 색, 색 값을 둘 곳, 확장과 랜딩 중 무엇이 기준인지를 정한다.

```text

§4-2-3   확장 우선 원칙       확장이 기준, 랜딩이 따른다
```

## 4-2-1 경희대 공식 색상표

LinKHU는 경희대학교 공식 색상 체계를 따른다. 주색은 **Kyung Hee Red**다.

| 이름 | PANTONE | RGB | HEX | 역할 |
| --- | --- | --- | --- | --- |
| **Kyung Hee Red** | 201C | 164, 15, 22 | `#a40f16` | **주색.** 로고, 강조 텍스트, 기본 버튼 |
| Kyung Hee Blue | 295C | 13, 50, 111 | `#0d326f` | 보조색 |
| Kyung Hee Gold | 872C | 192, 163, 83 | `#c0a353` | 보조색 |
| Cool Gray | 11C | 113, 113, 113 | `#717171` | 보조색 (중성) |
| Silver | 877C | 181, 181, 181 | `#b5b5b5` | 보조색 (중성) |

### 사용 금지색

| 값 | 이유 |
| --- | --- |
| RGB(173, 29, 25) | **휘장 상단 Bar 전용 보정색이다. UI에 사용하지 않는다.** 인쇄물 휘장 재현을 위한 보정값이며 화면 UI의 브랜드 레드가 아니다. Kyung Hee Red와 눈으로 구분이 어려워 혼입되기 쉬우므로 명시적으로 금지한다. |

### 적용 규칙

- 브랜드 레드가 필요한 모든 자리는 `#a40f16` 계열을 쓴다. 과거 값이던 `#9d2235`(확장)와 `#8f1d31`(랜딩)은 공식 색상이 아니며 코드에서 제거되었다. 다시 도입하지 않는다.
- **보조색(Blue, Gold)은 현재 UI에서 쓰지 않는다.** 확장과 랜딩 어디에도 사용처가 없다. 랜딩의 금색 토큰(`--color-accent`)도 참조하는 규칙이 없어 삭제했다. 쓰이지 않는 토큰은 팔레트를 읽는 사람이 실제 사용 색으로 오해할 수 있으므로 두지 않는다.
- 보조색을 도입하려면 용도를 먼저 정하고 토큰으로 추가한다. 일회성 하드코딩으로 넣지 않는다.
- 중성 회색은 공식 색상표 값에 얽매이지 않는다. 텍스트·테두리 회색은 가독성 기준으로 정한다.
- LinKHU는 경희대학교 공식 산출물이 아니다. 공식 색상을 쓰되 대학 로고나 휘장을 사용하지 않는다.

### 라이트 테마 대비 실측

주색을 쓰는 주요 조합의 명도 대비다 (WCAG 2.1 상대 휘도 기준). 색을 조정할 때의 기준선으로 삼는다.

```text
흰 텍스트  #ffffff  on 주색   #a40f16    7.90 : 1
주색      #a40f16  on 흰 배경 #ffffff    7.90 : 1
주색      #a40f16  on 화면 배경 #f8f9fa   7.49 : 1
주색      #a40f16  on soft   #fdeeef    7.02 : 1
흰 텍스트  #ffffff  on strong #790b11   11.24 : 1
```

전 조합이 일반 텍스트 기준(4.5:1)을 크게 상회한다. 다만 **`--color-primary-soft` 위의 주색 텍스트가 가장 여유가 적다.** soft 값을 더 진하게 바꾸면 이 조합부터 무너지므로, soft 계열을 조정할 때는 반드시 이 조합을 다시 측정한다.

## 4-2-2 디자인 토큰 규칙

### SSOT는 `src/theme.css`

확장 프로그램의 색상 단일 소스는 `src/theme.css`의 `:root` 변수다. `popup.html`과 `options.html`이 각자의 스타일시트보다 **먼저** 로드한다.

| 토큰 | 값 | 용도 |
| --- | --- | --- |
| `--color-primary` | `#a40f16` | 로고, 강조 텍스트, 기본 버튼 배경 |
| `--color-primary-strong` | `#790b11` | 기본 버튼 hover 등 눌린 상태 |
| `--color-primary-soft` | `#fdeeef` | 안내 박스, 드래그 중 항목 배경 |
| `--color-primary-border` | `#f4bfc3` | 옅은 배경 영역과 카드 hover 테두리 |
| `--color-primary-ring` | `rgba(164, 15, 22, 0.12)` | 입력 요소 focus ring |
| `--color-primary-shadow` | `rgba(164, 15, 22, 0.15)` | 카드 hover 그림자 |

파생값은 모두 주색과 같은 색상(hue 357°) 계열이다.

- 브랜드 레드 계열 색을 CSS나 인라인 스타일에 **직접 hex로 쓰지 않는다**. 토큰을 참조한다.
- 새 브랜드 색이 필요하면 `theme.css`에 **용도를 나타내는 이름**으로 토큰을 추가한다. `--red-2` 같은 값 기반 이름을 쓰지 않는다.
- **중성 회색도 토큰을 참조한다**. 표면·텍스트·테두리 색도 토큰으로 받으며, 하드코딩 예외를 두지 않는다.
- **기능색도 테마에 따라 달라져야 하면 토큰을 쓴다**. 새 버전 안내처럼 브랜드와 무관한 색이라도, 라이트와 다크에서 같은 값으로는 대비를 만족할 수 없으면 토큰이 필요하다.
- 결과적으로 **화면에 나타나는 모든 색이 토큰을 거친다.** `theme.css` 밖에 hex나 `rgba()`를 새로 쓰지 않는다.
- SVG의 `stroke`·`fill`은 표현 속성으로는 CSS 변수를 받을 수 없다. 토큰을 써야 하면 `style` 속성으로 옮긴다. **현재 UI 아이콘은 대부분 `fill="currentColor"` 방식이라 이 제약에 걸리지 않는다** — 부모의 `color`를 상속하면 된다. 이 규칙은 stroke 기반 아이콘이나 SVG를 직접 작성할 때만 적용된다.
- `<meta name="theme-color">`처럼 CSS를 해석하지 않는 자리에는 리터럴 hex를 쓴다. 이 예외는 문서에 남긴다.

### 랜딩은 파일 공유가 아니라 값 동기

`landing/landing.css`는 자체 `:root`에 같은 이름의 토큰을 **값만 복제**해서 갖는다.

GitHub Pages는 `landing/` 폴더만 서빙한다. 랜딩에서 `src/theme.css`를 참조하면 배포된 사이트에서 404가 난다. 심볼릭 링크나 빌드 단계도 쓸 수 있지만, 빌드리스 구성을 지키려고 값 동기를 택했다.

**동기 대상은 브랜드 색이다. 표면 색은 각자 갖는다.**

| 토큰 | 라이트 | 다크 | 동기 |
| --- | --- | --- | --- |
| `--color-primary` | `#a40f16` | `#ff4d52` | **필수** |
| `--color-primary-fill` | `#a40f16` | `#c4121b` | **필수** |
| `--color-primary-fill-strong` | `#790b11` | `#d7141e` | **필수** |
| `--color-primary-strong` | `#790b11` | `#ff7175` | **필수** |
| `--color-primary-soft` | `#fdeeef` | `#2a1214` | **필수** |
| `--color-on-primary` | `#ffffff` | `#ffffff` | **필수** |
| 표면·중성 계열 | — | — | 하지 않음 |
| 확장 전용 (`-border`, `-ring`, `-shadow`, `--color-notice`) | — | — | 대상 아님 |
| 랜딩 전용 (`--color-focus`) | — | — | 대상 아님 |

- 위 여섯 토큰은 **라이트와 다크 양쪽에서** 두 파일의 값이 같아야 한다. 한쪽을 바꾸면 같은 PR에서 다른 쪽도 바꾼다.
- **표면·중성 계열은 동기 대상이 아니다**. 확장은 도구, 랜딩은 홍보 표면이라 배경과 여백의 성격이 다르다. 값이 달라도 규칙 위반이 아니다.
- 두 파일의 `:root`에는 서로를 가리키는 동기 유지 주석이 있다. 토큰을 추가·변경할 때 이 주석을 지우지 않는다.

**브랜드 색은 테마와 무관하게 확장과 랜딩이 같은 값을 쓴다.** 사용자는 랜딩에서 확장을 보고 설치하므로, 두 화면의 브랜드 톤이 다르면 다른 제품처럼 보인다.

### 간격 스케일

스케일을 쓰는 곳은 `src/options.css`뿐이다. `src/popup.css`와 `landing/landing.css`는 아직 리터럴을 쓴다.

여백(`padding`·`margin`·`gap`)의 단일 소스도 `src/theme.css`다. 색 토큰과 달리 **테마별로 갈리지 않으므로 `data-theme`별로 재정의하지 않는다**.

| 토큰 | 값 |
| --- | --- |
| `--space-4` | `4px` |
| `--space-8` | `8px` |
| `--space-12` | `12px` |
| `--space-16` | `16px` |
| `--space-20` | `20px` |
| `--space-24` | `24px` |
| `--space-32` | `32px` |

- **새 여백은 이 스케일에서 고른다**. 값을 그때그때 정하면 5px, 7px, 10px이 섞여 같은 성격의 여백이 화면마다 달라진다. `.drop-zone`의 하이라이트가 한쪽만 떠 보이던 것(#173)이 그 증상이었다 — 존은 아래만 10px, 카드 사이는 8px, 카테고리는 14px, 제목은 5px이었다.
- **4px 배수만 둔다**. 배수를 좁게 잡으면 고를 수 있는 값 자체가 몇 개 안 되어, 고민 없이 집어도 화면이 어긋나지 않는다.
- 이름은 **값을 그대로 쓴다.** `--space-8`은 `8px`이다. 단계 번호(`--space-2` = 8px)를 쓰면 읽을 때마다 곱해야 한다. 색 토큰과 달리 여백은 용도가 아니라 크기로 고른다.
- **실제로 쓰는 값만 정의한다**. 쓰지 않는 단계를 미리 만들지 않는다. 새 크기가 필요하면 4px 배수로 토큰을 먼저 추가하고 참조한다.
- **이 스케일은 여백 전용이다**. `border-radius`, `font-size`, `height`, `width`, `outline-offset`은 대상이 아니다. 크기가 우연히 같다고 여백 토큰을 끌어다 쓰면 나중에 스케일을 조정할 때 무관한 것이 함께 움직인다.

**옮길 때는 반올림하지 않는다**

`src/options.css`는 여백 선언 전부가 토큰을 거친다. 옮기는 과정에서 5·6·7·10·14·18px이 사라졌는데, **가장 가까운 배수로 기계적으로 붙이지 않았다.** 그 자리가 무슨 일을 하는지가 답을 정한다.

- `.scroll-area`의 오른쪽 거터는 스크롤바(`6px`)를 피하는 자리다. `4px`이면 스크롤바보다 좁아 내용과 겹치므로 `8px`이 스케일 안의 유일한 답이다.
- `.open-link`의 패딩은 클릭 대상 크기를 정한다. 16px 아이콘에 `4px`을 더해 정확히 24×24가 되는데, 이는 WCAG 2.2의 최소 타깃 크기다. 더 키우면 말줄임되는 이름의 폭을 뺏는다.
- `.icon-button`의 패딩도 클릭 대상이라 **줄이지 않고 키웠다**(`6px` → `8px`).

`6px`처럼 두 배수의 한가운데 있는 값은 반올림 규칙으로 정해지지 않는다. **왜 그 값인지 한 줄로 답할 수 없으면 아직 정한 것이 아니다**.

모서리 반경, 글자 크기, 높이는 **이 스케일의 대상이 아니다**. 배수가 아니어도 그대로 둔다. 다만 목록 항목 높이처럼 여백과 함께 움직이는 값은 여백을 조정할 때 같이 본다.

### 반경과 그림자

모서리 반경과 그림자도 `src/theme.css`가 단일 소스다. **확장 CSS에 `border-radius`나 `box-shadow` 리터럴을 새로 쓰지 않는다**.

| 토큰 | 값 | 쓰이는 곳 |
| --- | --- | --- |
| `--radius-4` | `4px` | 포커스 표시, 스크롤바 썸 |
| `--radius-8` | `8px` | 입력, 버튼, 아이콘 버튼, 목록 항목, 드롭존 |
| `--radius-12` | `12px` | 팝업 카드, 떠 있는 문의 패널 |
| `--radius-pill` | `999px` | 카테고리 필터 칩 |
| `--shadow-card` | `0 4px 6px var(--color-shadow)` | 팝업 카드 평상시 |
| `--shadow-card-hover` | `0 6px 12px var(--color-primary-shadow)` | 팝업 카드 hover |
| `--shadow-focus-ring` | `0 0 0 3px var(--color-primary-ring)` | 입력 요소 포커스 링 |
| `--shadow-panel` | `0 8px 24px var(--color-shadow)` | 떠 있는 문의 패널 |
| `--shadow-drop-target` | `inset 0 0 0 1px var(--color-primary-border)` | 드래그 중 놓을 수 있는 영역의 안쪽 윤곽 |

**이름 규칙이 둘로 갈린다**.

- **반경은 값 이름**이다(`--radius-8`은 `8px`). 여백과 같이 **크기로 고르는** 값이라 이름이 곧 값이어야 읽을 때 곱하지 않는다.
- **그림자는 역할 이름**이다(`--shadow-card`, `--shadow-panel`). 크기가 아니라 **무엇을 띄우는가**로 고르고, 값이 여러 항(오프셋·번짐·색)의 조합이라 이름에 값을 담을 수 없다. 색 토큰이 역할 이름인 것과 같은 이유다.

**`--radius-pill`은 값이 아니라 의도다.** 상자 높이의 절반 이상이면 어떤 값이든 같은 알약 모양이 되고, 브라우저가 상자 크기에 맞춰 반경을 잘라낸다. 높이 32px인 칩은 `18px`이든 `999px`이든 실제로 `16px`로 그려진다. 그래서 "완전히 둥글다"는 의도를 이름으로 남기고 큰 수를 둔다.

**랜딩은 자기 반경·그림자 세트를 따로 가지며 확장과 어휘를 공유하지 않는다**. `landing/landing.css`의 `--radius-sm/md/lg`와 `--shadow-sm/md`는 확장과 값도 이름 체계도 다르다. 브랜드 색만 동기 대상이라는 위 절의 원칙이 여기에도 적용된다 — 여백과 마찬가지로 랜딩은 홍보 표면이라 반경과 그림자의 성격이 다르다. **두 세트의 이름이 겹치지 않게 유지한다**. 확장은 숫자 이름(`--radius-8`), 랜딩은 크기 이름(`--radius-md`)이라 지금은 겹치지 않는다. 한쪽에 토큰을 추가할 때 다른 쪽 이름과 같아지지 않는지 확인한다.

### 글자 크기

글자 크기도 `src/theme.css`가 단일 소스다. **확장 CSS에 `font-size` 리터럴을 새로 쓰지 않는다**.

| 토큰 | 값 | 쓰이는 곳 |
| --- | --- | --- |
| `--text-title` | `20px` | 팝업 헤더의 제품 이름 |
| `--text-heading` | `16px` | 설정 화면의 열 제목, 저장 버튼 |
| `--text-body` | `13px` | 기본값 — 입력, 버튼, 목록 이름, 안내 문단 |
| `--text-caption` | `12px` | 보조 문구 — 버전 표시, 상태 알림, 푸터 링크 |
| `--text-card-label` | `12px` | 팝업 카드 이름 (**고정**, 아래 참조) |

**이름은 역할 기반이다**. 여백(`--space-8`)과 반경(`--radius-8`)이 값 이름인 것과 반대다.

- 여백과 반경은 **크기로 고른다.** 8px이 필요해서 `--space-8`을 쓴다.
- 글자는 **용도로 고른다.** 보조 문구가 12px이어서 `--text-caption`을 쓰는 것이 아니라, 보조 문구여서 쓴다. 나중에 본문 크기를 한 단 올릴 때 "보조 문구는 전부 한 단 아래"라는 관계가 유지되려면 이름이 용도를 가리켜야 한다.
- 그림자가 역할 이름인 것과 같은 이유다. 정리하면 **크기로 고르는 것은 값 이름, 용도로 고르는 것은 역할 이름**이다.

**단계는 실제로 쓰는 것만 만든다**. 2px 구간에 여러 단계를 두면 눈으로 구분되지 않으면서 고를 때만 헷갈린다.

**두 화면의 같은 컴포넌트는 같은 토큰을 쓴다**. 문의 패널(`textarea`·`email`·`send`·`status`)과 테마 상태 문구는 팝업과 설정에 같은 기능을 그린 것이므로 값이 갈리면 안 된다.

`--text-card-label`은 스케일이 아니라 카드 폭이 정한다. 값은 `--text-caption`과 같지만 성격이 달라 별도 토큰으로 둔다. 한 줄 70.67px에 한글 여섯 자(69px)가 들어가야 한다. 12.5px이면 72px이 되어 줄바꿈 표 18건을 다시 정해야 한다. **본문 크기를 올려도 이 값은 함께 올리지 않는다.** 테스트가 두 줄이 각각 폭에 들어가는지 검사해 이 제약을 지킨다.

**`landing/landing.css`는 이 스케일을 쓰지 않는다.** 반경·그림자와 같은 이유로, 랜딩은 자기 글자 크기를 따로 갖는다.

## 4-2-3 확장 우선 원칙

> **확장 프로그램 UI가 LinKHU의 디자인 기준이고, 랜딩 페이지가 그것을 따른다.**

**두 표면은 목적이 달라 시각 언어도 다르다.**

| | 무엇인가 | 쓰는 표현 |
| --- | --- | --- |
| 확장 | 제품 그 자체. 320px에서 즉시 목표를 달성하는 도구 | 밀도 우선, 장식 없음 |
| 랜딩 | 제품을 소개하는 홍보 표면. 넓은 화면에서 스크롤하며 읽는다 | 큰 여백, 그라디언트, 글로우, 애니메이션 |

다음 원칙을 따른다.

- 브랜드 색이 바뀌면 **확장을 기준으로 정하고 랜딩이 따라온다**.
- 랜딩의 표현 방식(장식적 그라디언트, 글로우, 대형 여백, 스크롤 연출)을 확장 UI로 가져오지 않는다.
- 랜딩 고유의 시각 요소는 랜딩 안에서만 유지한다. 랜딩을 확장과 똑같이 만들 필요는 없다.
- 확장 UI는 정보 밀도와 조작 속도를 우선한다. 장식이 조작을 느리게 만들면 장식을 뺀다.

## 4-2-4 UI 아이콘

LinKHU에는 성격이 다른 두 종류의 아이콘이 있다. **섞어서 다루지 않는다**.

| 종류 | 무엇 | 어디 | 원본 |
| --- | --- | --- | --- |
| **UI 아이콘** | 화면 기능을 나타내는 기호 (설정, 검색, 테마 토글 등) | 팝업·설정·랜딩 마크업의 인라인 SVG | 이 절 |
| **서비스 아이콘** | 교내 웹서비스를 나타내는 그림 (인포21, e-Campus 등) | `src/images/**`, 랜딩 검색 결과 | 따로 다룬다 |

**출처는 [Reicon](https://github.com/huntiezz/reicon)이다** (MIT, 24×24 그리드, Outline 웨이트).

- **새 UI 아이콘은 Reicon에서 고른다**. 직접 그리거나 다른 아이콘 세트를 섞지 않는다. 굵기와 모서리 처리가 달라지면 화면이 지저분해진다.
- **npm 패키지를 추가하지 않는다**. 필요한 SVG 마크업만 인라인으로 가져온다. 제로 의존성 원칙을 지킨다.
- 색은 `fill="currentColor"`로 두고 **부모의 `color`를 상속시키거나 `style="color: var(--color-...)"`로 준다**. 색 값을 직접 쓰지 않는다.
- Reicon 아이콘은 대부분 fill 기반이라 §4-2-2의 SVG 표현 속성 제약에 걸리지 않는다. 다만 일부(돋보기, 홑화살괄호)는 stroke 기반이므로 그 경우에는 제약이 그대로 적용된다.
- `viewBox`는 `0 0 24 24`를 유지하고 **표시 크기만 `width`/`height`로 조절한다**.
- 장식용 아이콘에는 `aria-hidden="true"`를 붙인다. 의미를 지는 아이콘은 인접 텍스트나 `aria-label`로 대체 텍스트를 제공한다.

**이모지를 UI 기호로 쓰지 않는다**

이모지는 **플랫폼마다 모양이 다르다.** 같은 문자가 운영체제와 폰트에 따라 다른 그림으로 나오므로, 아이콘 세트를 통일해도 이모지가 섞여 있으면 일관성이 무너진다. 크기·색·정렬을 CSS로 다루기도 어렵다.

설정 페이지의 제목과 카테고리 라벨을 포함해 화면의 모든 UI 기호는 Reicon 아이콘이다.

이 규칙은 **UI 기호에 한정한다.** 본문이나 안내 문구 속 이모지는 대상이 아니다.

**예외: 브라우저 로고**

Chrome·Firefox·Whale 로고는 **각 사의 브랜드 자산이므로 Reicon으로 교체하지 않는다**. 공식 원본을 그대로 쓴다.

**확장 자체 로고의 색** — `src/icons/icon16·48·128.png`와 랜딩 사본(`landing/assets/linkhu-icon.png`), 스토어 홍보 타일(`landing/assets/store/promotion-tile.png`)은 브랜드 레드 `#a40f16`을 쓴다.
