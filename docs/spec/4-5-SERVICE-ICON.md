# 4-5. 서비스 아이콘

서비스 아이콘은 교내 웹서비스를 나타내는 그림이다. 팝업에서는 40px, 설정에서는 24px로 표시한다. **세부가 많은 도안은 이 크기에서 뭉개지므로** 한눈에 구분되는 단순한 상징을 쓴다.

화면 기능을 나타내는 UI 아이콘(설정·검색·테마 토글)은 성격이 다른 자산이다. **둘을 섞어서 다루지 않는다**.

```text
§4-5-1   기본 규칙          크기, 형식, 폴더, 파일명
§4-5-2   팔레트            라이트 세 색, 다크 두 색
§4-5-3   두 벌 체계         라이트 원본과 다크 생성
§4-5-4   생성기와 검증       무엇을 만들고 무엇을 막나
§4-5-5   SVG 원본          왜 src/ 밖에 두나
§4-5-6   추가·변경 절차      실행 순서
```

## 4-5-1 기본 규칙

| 항목 | 값 |
| --- | --- |
| 캔버스 | `70x70` |
| 배경 | **투명**. 라이트·다크 두 벌 모두 |
| 파일 형식 | PNG 권장 |
| 폴더 | `src/images/common/`, `src/images/colleges/`, `src/images/departments/` |
| 파일명 | `src/data.js`의 `id`와 맞춘다 |
| 데이터 연결 | `imgSrc`에 `src/` 기준 상대 경로 (예: `images/common/portal.png`) |

폴더 구분은 **파일을 나눠 담는 관례일 뿐 데이터의 `category`와 별개다.** 주제 카테고리가 여덟 개로 늘었을 때도 아이콘 파일은 옮기지 않았다. 경로는 `imgSrc`가 통째로 갖고 있으므로 카테고리에서 유도하지 않는다.

## 4-5-2 팔레트

| 벌 | 쓰는 색 | 그 위 배경 |
| --- | --- | --- |
| 라이트 | 브랜드 레드 `#a40f16`, 검정 `#1a1a1a`, 투명 — **세 가지뿐** | 밝은 표면 |
| 다크 | 무채 선화 `#a1a1aa`, 붉은 계열 `#d94a52` — **두 가지뿐** | 다크 카드 `#161616` |

- **회색 채움을 두지 않는다**. 면을 회색으로 채우는 대신 비우고 선화로 표현한다. 경계 안티에일리어싱은 검정의 알파로만 표현하며, 이때 흰 배경과 섞여 회색으로 합성되는 것은 정상이다.
- 다크 벌의 두 색은 다크 카드 위에서 각각 7.06:1, 4.35:1로 비텍스트 기준 3:1을 넘는다. 안티에일리어싱을 색이 아니라 알파로 표현하므로 **목표색보다 밝은 픽셀이 생기지 않는다.**
- **기존 자산도 이 팔레트와 일치한다**. 새 도안에만 적용하는 규칙이 아니다. 팔레트 밖의 색을 추가하지 않는다.

## 4-5-3 두 벌 체계

서비스 아이콘은 **테마별로 두 벌**이다. 한 벌을 두 테마에서 재사용하지 않는다. 직접 그리는 것은 라이트 한 벌뿐이다.

| 벌 | 위치 | 어떻게 만드나 |
| --- | --- | --- |
| 라이트 | `src/images/**` | 사람이 그린다 |
| 다크 | `src/images/dark/**` | `npm run generate:dark-icons`가 만든다 |

| 규칙 | 내용 |
| --- | --- |
| 경로 | 라이트 경로의 `images/`를 `images/dark/`로 바꾼다. 나머지 구조와 파일명은 같다 |
| 데이터 | `imgSrc`에는 **라이트 경로만** 적는다. 다크 경로는 `LinKHUShared.iconSrc(imgSrc, theme)`가 유도한다 |
| 다크 벌 수정 | **손으로 그리거나 고치지 않는다**. 생성기가 다시 만들므로 다음 실행에 덮인다 |
| 다크 벌의 색 | 원본 색과 무관하다. 생성기가 정해진 두 색으로 다시 칠한다 |
| 새 서비스 | **두 벌을 모두 만든다**. 라이트만 두면 다크 테마에서 그 아이콘만 깨진다 |

**두 벌 모두 배경을 투명하게 한다**. 불투명한 배경이 한 장이라도 섞이면 반대 테마의 카드에서 그 아이콘만 밝거나 어두운 사각형으로 떠 보인다. 배경이 투명하면 아이콘 칸에는 표면 토큰을 쓸 수 있어 테마별 칸 색이 필요 없다.

## 4-5-4 생성기와 검증

```
npm run generate:dark-icons    # 라이트 배경 제거 + 다크 벌 생성 (제자리 수정)
npm run validate:dark-icons    # 짝 검증만 (파일을 쓰지 않음)
```

- 생성기는 라이트 원본의 흰 배경도 함께 걷어낸다. 배경이 남아 있어도 실행 후에는 투명해진다.
- **여러 번 돌려도 결과가 같다.** 이미 투명해진 원본을 다시 처리해도 색이 어긋나지 않는다.
- `validate:dark-icons`는 `npm run build`에 포함되며 두 가지를 본다.

| 검사 | 막는 것 |
| --- | --- |
| 라이트 벌과 다크 벌의 **경로 집합이 정확히 일치**하는가 | 한쪽에만 있는 파일 |
| 두 벌 모두 **네 모서리가 투명**한가 | 배경이 남은 파일 |

모서리 검사는 알파 10/255까지 허용한다. 원본 도안의 경계 안티에일리어싱이 모서리까지 옅게 번지는 경우가 있어(관측 최대 9/255) 0을 요구하면 정상 자산이 걸린다.

## 4-5-5 SVG 원본

새로 그리는 아이콘은 **SVG 원본을 `assets/icons/<카테고리>/<id>.svg`에 남긴다**. 색 규칙이 바뀌면 다시 내보낼 수 있다. 기존 자산은 SVG 원본이 없으므로 소급 적용 대상이 아니다.

**`src/` 안에 두지 않는다**. `scripts/package-extension.js`가 `src/` 아래 모든 파일을 확장 패키지에 넣으므로, SVG가 그 안에 있으면 사용자에게 배포되는 확장에 함께 들어간다.

그리는 절차와 실측된 도안 규칙(선 두께, 여백, 붉은색 비중)은 `.claude/skills/service-icon/SKILL.md`에 있다.

## 4-5-6 추가·변경 절차

한 PR에서 너무 많은 아이콘을 한꺼번에 바꾸지 않는다. 되돌릴 단위를 작게 유지한다.

아이콘을 추가하거나 바꾼 뒤 순서대로 실행한다.

```
npm run generate:dark-icons     # 다크 벌 생성 + 라이트 배경 제거
npm run generate:landing-data   # 랜딩 사본 동기
npm run validate:data
npm run build                   # 두 벌 짝 검증 포함
```

아이콘 파일을 지울 때는 **다른 서비스가 그 파일을 참조하지 않는지 먼저 본다**. 아이콘은 여러 서비스가 공유할 수 있으므로, 확인 없이 지우면 남아 있는 서비스의 아이콘이 깨진다.
