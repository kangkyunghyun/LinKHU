# 4-3. 테마

이 문서는 테마 모드 세 가지와 저장 규칙, 선택 UI와 반영 범위, 다크 테마의 구현 방식과 색 토큰 값, 테마별 대비 기준, 랜딩 다크 팔레트를 정한다.

토큰의 원본과 이름 규칙, 확장과 랜딩의 값 동기는 UI 시스템에, 저장 키와 비동기 결과의 순서는 상태에, 초기 적용 순서는 인터랙션에, 저장 실패 시 화면 동작과 문구는 오류 처리에 있다. ([4-2-2 디자인 토큰 규칙](4-2-UI-SYSTEM.md#4-2-2-디자인-토큰-규칙), [4-5-1 저장 키 목록](4-5-STATE.md#4-5-1-저장-키-목록), [4-5-4 비동기 결과의 순서](4-5-STATE.md#4-5-4-비동기-결과의-순서), [6-1-5 테마 적용](6-1-INTERACTION.md#6-1-5-테마-적용), [7-1-3 저장소 실패](7-1-ERROR-HANDLING.md#7-1-3-저장소-실패))

<br>

## 4-3-1 테마 모드

| 값 | 동작 |
| --- | --- |
| `system` | 운영체제와 브라우저의 `prefers-color-scheme`을 따른다 |
| `light` | 항상 라이트 |
| `dark` | 항상 다크 |

- 기본값은 `system`이다.
- `light`나 `dark`를 고르면 시스템 설정보다 우선한다.
- `system`을 고른 상태에서 시스템 테마가 바뀌면 열려 있는 화면에 바로 반영한다. `prefers-color-scheme` 미디어 쿼리 변경을 구독한다.

<br>

## 4-3-2 저장

| 항목 | 확장 | 랜딩 |
| --- | --- | --- |
| 저장소 | `chrome.storage.local` | 브라우저의 도메인별 영구 저장소 |
| 읽기 | 비동기 | 동기 |
| 저장 실패 확인 | `chrome.runtime.lastError` | 저장 시 발생한 예외 |

확장과 랜딩은 같은 세 모드를 쓰지만 저장소가 달라 서로 동기화되지 않는다. 랜딩은 일반 웹페이지라 확장 저장소를 읽을 수 없다. 확장은 웹페이지 저장소를 읽지 않는다. 같은 기기에서 확장은 다크, 랜딩은 라이트일 수 있다.

| 규칙 | 이유 |
| --- | --- |
| 값이 없거나 문자열이 아니거나 유효값이 아니면 `system`으로 읽는다. 잘못 저장된 값을 지우거나 덮어쓰지 않아도 된다 | 읽는 시점의 대체로 충분하다 |
| 고르는 즉시 적용하고 저장한다. 저장 버튼을 두지 않는다 | 되돌리기 비용이 낮고 결과를 바로 눈으로 확인하는 설정이다 |

<br>

**1. 저장 실패 시 되돌리기**

확장과 랜딩이 같다.

| 규칙 | 이유 |
| --- | --- |
| 저장에 실패하면 적용한 테마와 토글 표시를 함께 되돌린다 | 화면만 새 테마로 남으면 다음 실행에서 조용히 이전 테마로 돌아가 사용자는 설정이 무시됐다고 느낀다. 화면과 컨트롤도 어긋나면 안 된다 |
| 되돌릴 기준은 저장소의 값으로 확인된 마지막 모드다. 가장 최근 요청의 저장 성공, 초기 읽기, 다른 화면의 저장 알림에서 갱신한다. 초기 읽기가 실패하면 `system`을 기준으로 둔다 | 테마는 먼저 적용하고 나중에 저장하므로 적용 직전 모드는 저장된 적 없는 중간값일 수 있다. 연달아 바꾼 두 요청이 모두 실패하면 화면이 저장소와 다른 값으로 남는다 |

<br>

## 4-3-3 선택 UI와 반영 범위

테마 컨트롤은 팝업, 설정 페이지, 랜딩 모두 헤더의 순환 토글 하나다. 화면마다 다른 컨트롤을 두지 않는다.

| 규칙 | 내용 |
| --- | --- |
| 순환 순서 | `system` → `light` → `dark` → `system`. 세 모드를 모두 거치므로 따로 고르는 단계 없이 `system`에 닿는다 |
| `system` 저장 | 순환이 `system`에 닿으면 그 값을 저장한다. 저장소를 비우지 않는다 |
| 저장 경로 | 하나다. 토글도 모드를 고르는 다른 경로와 같은 저장, 되돌리기, 경쟁 조건 방지를 지난다 |
| 반영 범위 | 설정에서 바꾸고 팝업을 열면 이미 적용되어 있다 |

<br>

**1. 동시에 열려 있을 때**

확장의 설정 페이지는 탭으로 열리므로 팝업과 동시에 떠 있을 수 있다. 각 화면이 초기화 때 한 번만 저장소를 읽으면 한쪽에서 바꾼 값이 다른 쪽에 반영되지 않는다. 아래 규칙은 확장 화면에 적용한다. 랜딩 탭끼리는 동기화하지 않아 다른 탭은 새로고침할 때 바뀐다.

| 규칙 | 이유 |
| --- | --- |
| 저장소 변경을 구독해 열려 있는 모든 화면의 테마, 토글 아이콘, 레이블을 갱신한다 | 두 화면이 갈라지지 않는다 |
| 받은 값은 정규화한 뒤 적용한다 | 다른 화면이 쓴 값도 손상돼 있을 수 있다 |
| 진행 중인 자기 요청이 있으면 외부 값으로 덮지 않는다 | 그 요청의 결과가 최종이다. 덮으면 사용자가 방금 고른 값이 되돌아간다 |
| 같은 화면의 토글 아이콘과 레이블은 적용과 동시에 바뀐다. 다른 화면은 저장이 끝난 뒤 저장소 변경 알림을 받아 바뀐다 | 저장 완료를 기다리지 않아야 누른 화면이 바로 반응한다 |
| 저장에 실패해 되돌리면 표시도 함께 되돌린다 | 표시가 되돌아간 값과 맞아야 한다 |

<br>

**2. 팝업 토글**

레이블 텍스트나 추가 컨트롤을 붙이지 않는다.

<br>

**3. 아이콘과 접근성**

아이콘은 현재 모드를 보여준다.

| 모드 | 아이콘 |
| --- | --- |
| `system` | 모니터 |
| `light` | 해 |
| `dark` | 달 |

순환 토글은 다음 모드가 버튼 모양에 드러나지 않으므로 아래로 보완한다.

| 규칙 | 내용 |
| --- | --- |
| 레이블 | `aria-label`과 `title`에 현재 모드와 다음 모드를 함께 담는다. 예: `테마: 시스템 설정. 누르면 라이트` |
| 갱신 | 모드가 바뀌면 레이블과 `title`을 갱신한다 |
| 알림 | 바뀐 결과를 `role="status"` 영역으로 알린다. 성공 문구 "테마: {모드 이름}"은 화면에 보이지 않고 스크린 리더만 읽는다. 실패 문구는 화면에 보이고 다음 성공 때 사라진다<br>다른 화면의 변경과 시스템 테마 변경은 알리지 않는다 |
| 눌림 상태 | `aria-pressed`를 쓰지 않는다. 눌림과 안 눌림 두 상태를 의미하는데 모드는 세 가지다 |
| 포커스 | 키보드 포커스 표시가 보인다 |

<br>

**4. 초기 적용 시점**

깜빡임 여부는 눈으로 판정할 수 없으므로 측정 가능한 조건으로 정한다.

| 화면 | 합격 조건 |
| --- | --- |
| 확장 | 첫 페인트 시점의 문서 루트에 시스템 설정 기준 표식이 있다. 저장된 모드가 다르면 값이 도착할 때 표식을 한 번 바꾼다 |
| 랜딩 | 저장된 모드를 동기로 읽어 첫 페인트 시점의 문서 루트에 최종 표식이 있다 |

`DOMContentLoaded` 이후에 표식이 붙으면 불합격이다.

<br>

## 4-3-4 구현 방식과 토큰 계약

| 규칙 | 이유 |
| --- | --- |
| 다크 테마는 토큰 값 교체만으로 구현한다. 확장은 `src/theme.css`, 랜딩은 자기 스타일시트를 쓴다 | 레이아웃과 컴포넌트를 테마별로 두 벌 만들지 않는다 |
| 어느 테마로 그릴지는 문서 루트의 표식이 정한다. 다크를 `prefers-color-scheme` 미디어 쿼리로 표현하지 않는다 | 미디어 쿼리는 시스템 설정만 보므로 사용자가 고른 모드를 반영하지 못한다. 시스템 설정은 `system` 모드를 해석할 때만 읽는다 |
| 표식이 없으면 라이트로 그린다 | 표식은 스크립트가 붙이므로 스크립트가 실행되지 않으면 라이트다 |
| 레이아웃, 크기, 간격, DOM 구조를 테마에 따라 바꾸지 않는다 | 다크 테마 때문에 카드 배치나 화면 구성이 달라지면 안 된다 |
| 서비스 아이콘 이미지를 반전하거나 필터를 걸지 않는다 | 도안이 제각각이라 일괄 반전은 결과를 예측할 수 없다. 테마별 아이콘은 두 벌로 둔다 |
| 토큰 값은 대비 기준을 먼저 만족시킨다 | 보조 텍스트 `#666666`은 놓이는 가장 어두운 라이트 바탕(soft) 위에서도 5.10:1이다 |
| 테마 블록마다 `color-scheme`을 함께 선언한다 | 스크롤바, 입력의 지우기 버튼, 기본 자리표시 문구 같은 브라우저 기본 UI도 테마를 따른다 |

아래 표의 이름과 값을 그대로 정의한다.

<br>

**1. 주색 계열**

주색은 텍스트와 강조용, 채움 배경용 두 토큰으로 나뉜다. 하나로 겸용하면 다크에서 채움 위 텍스트 대비를 맞추다 채도를 잃는다.

| 토큰 | 라이트 | 다크 | 쓰이는 곳 |
| --- | --- | --- | --- |
| `--color-primary` | `#a40f16` | `#ff4d52` | 텍스트와 강조 전용. 로고, 강조 텍스트, 입력 포커스 테두리, 키보드 포커스 윤곽선, 아이콘 버튼 기호, 드래그 중 항목 테두리 |
| `--color-primary-fill` | `#a40f16` | `#c4121b` | 채움 배경 전용. 기본 버튼, 배지, 브랜드 패널 배경 |
| `--color-primary-fill-strong` | `#790b11` | `#d7141e` | 채움의 hover 상태 |
| `--color-primary-strong` | `#790b11` | `#ff7175` | 확장: 쓰지 않음. 랜딩과 값을 맞추려고 정의함<br>랜딩: 검색 데모 입력의 포커스 테두리 |
| `--color-primary-soft` | `#fdeeef` | `#2a1214` | 단축키 안내 박스, 드래그 중 항목, 아이콘 버튼 hover, 선택된 칩, 드롭 대상의 배경 |
| `--color-primary-border` | `#f4bfc3` | `#5c1d20` | 안내 박스 테두리, 카드 hover 테두리, 드롭 대상의 안쪽 윤곽 |
| `--color-primary-ring` | `rgba(164, 15, 22, 0.12)` | `rgba(255, 77, 82, 0.28)` | 입력 요소 포커스 링 |
| `--color-primary-shadow` | `rgba(164, 15, 22, 0.15)` | `rgba(0, 0, 0, 0.45)` | 카드 hover 그림자 |
| `--color-on-primary` | `#ffffff` | `#ffffff` | `--color-primary-fill` 위의 텍스트 |

| 규칙 | 이유 |
| --- | --- |
| 채움의 hover에는 `--color-primary-fill-strong`을 쓴다 | 다크에서 `--color-primary-strong`(`#ff7175`)을 채움에 쓰면 흰 글자가 2.67:1로 미달한다 |
| 라이트에서는 두 주색이 같은 값이다 | 밝은 배경에서는 `#a40f16`이 텍스트로도 채움으로도 통한다. 갈라지는 것은 다크에서다 |
| 다크의 `--color-primary-shadow`는 붉은 계열이 아니다 | 어두운 배경에서는 붉은 그림자가 번짐으로 보이고 깊이를 만들지 못한다 |
| `--color-on-primary`는 두 테마 모두 흰색이다. 채움 위 텍스트에는 `--color-on-primary`를 쓴다 | `--color-primary-fill`이 두 테마 모두 짙은 빨강이라 글자색을 뒤집을 이유가 없다 |

<br>

**2. 중성 계열**

| 토큰 | 라이트 | 다크 | 쓰이는 곳 |
| --- | --- | --- | --- |
| `--color-surface` | `#f8f9fa` | `#0a0a0a` | 팝업 바탕 |
| `--color-surface-raised` | `#ffffff` | `#161616` | 팝업 카드, 설정 화면 바탕, 떠 있는 문의 패널, 목록 항목 |
| `--color-surface-sunken` | `#f1f3f5` | `#101010` | 설정 페이지 단 배경 |
| `--color-field` | `#ffffff` | `#1c1c1c` | 검색과 문의 입력 요소, 칩의 배경 |
| `--color-text` | `#333333` | `#f4f4f5` | 본문, 항목 이름 |
| `--color-text-muted` | `#666666` | `#a1a1aa` | 보조 설명, 빈 결과 문구, 푸터 링크, 드래그 손잡이, 선택 안 된 칩 글자, 검색과 새 탭 링크 아이콘 |
| `--color-border` | `#dddddd` | `#27272a` | 구분선, 카드 기본 테두리, 푸터 구분자, 입력과 칩의 평상시 경계 |
| `--color-border-strong` | `#8a8a8a` | `#71717a` | 스크롤바 손잡이, 칩 hover 테두리 |
| `--color-shadow` | `rgba(0, 0, 0, 0.05)` | `rgba(0, 0, 0, 0.45)` | 카드와 떠 있는 문의 패널의 그림자 |

## 4-3-5 대비 기준

| 대상 | 기준 |
| --- | --- |
| 일반 텍스트 | **4.5:1 이상** |
| 정보를 전달하는 비텍스트 요소. 포커스 표시, 상태 테두리, 컨트롤 경계. 포커스 표시는 키보드 사용자가 현재 위치를 아는 유일한 단서라 여기에 든다 | **3:1 이상** |
| 순수 장식. 구분선, 카드 기본 테두리, 그림자 | 기준 없음 |

## 4-3-6 랜딩 다크 팔레트

랜딩의 다크 토큰 값은 문서 루트의 다크 표식 아래 한 블록에 모은다. 그 뒤에 헤더, 히어로, 브라우저 목업, 버튼 그림자처럼 장식 표면의 컴포넌트별 다크 규칙이 따로 있다. 아래 랜딩 고유 토큰은 확장과 값이 달라도 된다.

| 랜딩 고유 | 이유 |
| --- | --- |
| `--color-background`, `--color-surface`, `--color-surface-muted`, `--color-foreground`, `--color-muted`, `--color-border` | 홍보 페이지의 배경 성격이 도구 화면과 다르다. 값은 중성이어야 한다 |
| `--color-focus` (파랑) | 랜딩에만 있는 역할 |
| 그라디언트, 글로우, 히어로 연출 | 확장 우선 원칙에 따른 랜딩 고유 표현 |

| 규칙 | 이유 |
| --- | --- |
| 채움은 크기와 무관하게 모두 `--color-primary-fill`을 쓴다. 버튼, 결과 표시 같은 작은 컨트롤과 기능 소개 강조 카드, 설치 권유 카드 같은 큰 브랜드 패널이 같은 토큰을 쓴다 | 채움 값이 두 테마 모두 짙은 빨강이라 큰 패널에도 그대로 쓸 수 있고 다크 전용 덮어쓰기가 필요 없다 |
| 배경이 테마와 무관하게 고정된 자리는 전용 토큰을 쓴다 | 고정 배경 위에 `--color-primary`를 쓰면 다크에서 `#ff4d52`로 바뀌어 대비가 깨진다 |
| 테마에 따라 뒤집히는 색 위에 고정 색 텍스트를 올리지 않는다. 키보드 스킵 링크는 배경이 `--color-foreground`이므로 글자를 `--color-background`로 둔다 | 함께 반전되지 않으면 한 테마에서 글자가 배경에 묻힌다 |

| 토큰 | 값 | 배경 | 쓰이는 곳 |
| --- | --- | --- | --- |
| `--color-on-primary-muted` | `#f7dee0` | 브랜드 패널 `--color-primary-fill` | 기능 소개 번호와 본문, 설치 권유 본문 |
| `--color-flow-accent` | `#ff4d52` | 사용 흐름 구역 `#1d1d1d` | 구역 머리말, 단계 번호 |

`--color-flow-accent`는 다크 주색과 같은 값이다. 사용 흐름 구역은 항상 어두워 "어두운 배경 위 브랜드 색"이라는 같은 문제를 풀기 때문이다. `--color-flow-accent`에는 다크 변형이 없다. `--color-on-primary-muted`는 채움 배경 위에 올라가므로 두 테마의 채움 값 모두에 대해 4.5:1을 만족한다.
