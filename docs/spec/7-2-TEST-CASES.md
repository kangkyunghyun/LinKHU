# 7-2 테스트 케이스

이 문서는 테스트 범위와 외부 의존성 대체, 자동 테스트가 검증하는 상황과 기대 결과, 자동화하지 않은 영역, 변경 유형별 수동 검증 항목, 검증 환경, 자동화로 잡지 못하는 실패의 확인 절차를 정한다.

테스트 실행 명령과 공개 폼 점검 스크립트는 스펙 세트 안내에, PR 본문에 검증 결과를 적는 절차는 작업 하네스에, 문의 폼의 조건은 계약에, 실패 시 동작은 오류 처리에 있다. ([AGENTS.md 명령](AGENTS.md#5-명령), [저장소 AGENTS.md 수동 검증 기준](../../AGENTS.md#수동-검증-기준), [5-4 Google Forms](5-CONTRACT.md#5-4-google-forms), [7-1 오류 처리](7-1-ERROR-HANDLING.md))

<br>

### 7-2-1 자동 테스트

| 종류 | 확인 범위 | 외부 호출 | 실행 |
| --- | --- | --- | --- |
| 단위 | 공용 규칙, 문의 요청 조립, 테마 해석, 릴리스 노트 가공, 휴대폰 판정 | 없음 | 자동 테스트, CI |
| 화면 동작 | 팝업, 설정, 랜딩 스크립트를 격리된 환경에서 실행해 렌더, 저장, 경쟁 조건 확인 | 대역 | 자동 테스트, CI |
| 데이터 | 저장소의 실제 지원 서비스 목록과 아이콘 파일 | 없음 | 자동 테스트, 검증, CI |
| 패키징 | 임시 폴더에서 만든 ZIP의 파일 목록과 재현성 | 없음 | 자동 테스트, CI |
| 수동 | 실제 브라우저의 화면 동작, 실제 폼 전송, 스토어 심사 | 실제 서비스 | 7-2-3, 7-2-5 |

| 외부 의존성 | 대체 방법 |
| --- | --- |
| 확장 API | 대역을 넣음. 저장소 콜백을 붙잡아 두었다가 원하는 순서로 불러 경쟁 조건을 재현함 |
| GitHub 릴리스 API | 고정 응답, 실패, HTTP 오류 응답을 돌려주는 대역 |
| Google Forms | 요청을 보내지 않고 조립한 주소와 본문만 비교함 |
| 브라우저 웹 저장소 | 대역 저장소로 쓰기 실패와 막힌 저장소를 재현함 |
| 릴리스 노트 | 저장소의 실제 릴리스 노트 파일을 읽음 |

| 규칙 | 내용 |
| --- | --- |
| 도구 | Node.js 내장 테스트 러너. 별도 테스트 프레임워크를 두지 않음 |
| 통과 기록 | 실행된 테스트 수가 0이 아닌지 함께 봄 |
| 경쟁 조건 | 콜백을 바로 부르는 대역으로는 검증하지 않음 |
| 방어 코드 판단 | 막는 상황을 테스트로 먼저 재현함. 재현되면 규모만 줄이고, 재현되지 않으면 근거를 남기고 걷어 냄 |

**1. 확장과 랜딩의 일치**

| 상황 | 기대 결과 |
| --- | --- |
| 같은 검색어를 팝업과 랜딩에 넣음 | 결과 순서가 같음 |
| 확장과 랜딩에서 같은 문의를 보냄 | 같은 폼 주소, 같은 필드, 같은 유형 값과 순서 |
| 릴리스 노트에 `### Internal` 절이 있음 | 랜딩과 Firefox 제출 노트 모두에서 빠지고 결과가 같음. 마지막 절이 아니어도 뒤 절은 남음 |

<br>

**2. 외부 응답과 실패**

| 상황 | 기대 결과 |
| --- | --- |
| 릴리스 조회가 실패하거나 HTTP 오류 응답이 옴 | 업데이트 구역이 숨고 예외가 페이지로 새지 않음 |
| 릴리스 본문에 마크업이 들어 있음 | 글자로 남고 실행되지 않음 |
| 릴리스 본문의 백틱 짝이 맞지 않음 | 짝이 맞는 부분만 코드가 되고 나머지는 글자로 남음 |
| 릴리스가 다섯 개보다 많음 | 최근 다섯 개만 그림 |
| 릴리스를 받음 | 업데이트 구역이 드러나고 가장 최근 하나만 펼침. `### Internal` 항목은 화면에 없음 |
| 문의 폼 주소가 설정되지 않음 | 문의 기능이 꺼진 것으로 판정 |
| 이메일 필드가 설정되지 않음 | 이메일을 보내지 않음 |
| 랜딩 문의의 유형 값이나 유형 필드가 비었음 | 유형을 싣지 않음 |
| 분석 스크립트가 아직 없음 | 휴대폰 설치 안내의 이벤트를 보내지 않음 |
| 클립보드 API가 없는 브라우저 | 주소를 직접 복사하라는 안내를 보임 |

**3. 저장 실패와 경쟁 조건**

| 상황 | 기대 결과 |
| --- | --- |
| 테마 저장이 실패함 | 확인된 모드로 화면과 알림 모드를 되돌리고 상태 줄을 보임. 다음 저장이 성공하면 상태 줄을 숨김 |
| 연달아 고른 두 모드의 저장이 모두 실패함 | 실패가 어느 순서로 와도 저장된 모드로 되돌림 |
| 먼저 보낸 저장이 늦게 실패하고 나중 저장은 성공함 | 성공한 최신 선택을 되돌리지 않음 |
| 저장된 모드를 읽는 사이 사용자가 모드를 고름 | 늦게 도착한 저장값이 사용자의 선택을 덮지 않음 |
| 저장된 모드가 도착하기 전 | 시스템 설정 기준으로 먼저 칠함 |
| 다른 화면에서 테마를 바꿈 | 이 화면도 따라감. 진행 중인 자기 저장이 있으면 덮지 않음 |
| 저장된 테마 값이 손상됐거나 저장소 API가 없음 | `system`으로 칠하고 화면이 뜸 |
| 단축키 안내 닫기 저장이 실패함. 콜백 오류와 동기 예외 모두 | 안내가 다시 보이고 실패를 알림. 재시도가 성공하면 실패 알림을 지움 |
| 설정 저장 | 성공과 런타임 오류를 구분해 보고함 |

**4. 화면 규칙**

| 상황 | 기대 결과 |
| --- | --- |
| 일반 클릭, 수식 키 클릭, 휠 클릭 | 6-1-3 표와 같음 |
| 같은 식별자가 두 번 저장됨 | 한 번만 그리고 순서를 유지함 |
| 설정에서 카테고리와 검색어를 함께 걺 | 둘 다 만족하는 것만. 필터만 걸어도 빈 결과 문구를 보일 수 있음 |
| 단축키가 등록됨 | 닫았는지 읽기 전에 팝업 안내를 숨김 |
| 단축키가 비어 있음 | 팝업 안내를 보임. 닫은 값이 정확히 `true`일 때만 숨김 |
| 팝업 안내의 닫기를 누름 | 바로 숨기고 `true`를 저장함 |
| 팝업 안내의 `설정에서 지정` | 설정 페이지의 단축키 안내 위치를 새 탭으로 엶 |
| 설정의 단축키 안내 | 펼쳐져 있고 Aside를 포함함 |
| 시스템 테마가 바뀜 | 모드가 `system`일 때만 다시 칠함 |
| 테마 토글을 누름 | `system` → `light` → `dark` → `system`. 레이블이 현재와 다음 모드를 말함. 결과를 알림 |
| 다크 테마의 서비스 아이콘 | 다크에서만 다크 경로. 고른 모드를 따르고 서비스 아이콘만 바꿈 |
| 고른 모드 노출 | 문서 루트에 고른 모드를 표시해 토글 아이콘이 따라옴 |
| 설정에서 이미 담은 서비스 | 어떤 검색어와 필터 조합에서도 왼쪽 목록에 나오지 않음 |
| 화면 단축키 | 입력 요소와 수식 키 입력은 받지 않음 |
| 휴대폰과 태블릿으로 랜딩을 엶 | 설치 안내를 보임. iPadOS는 터치 지원으로 판정. 데스크톱에서는 숨김 |
| 휴대폰 설치 안내의 링크 복사, QR 토글 | PC 주소를 복사하고 결과를 알림. QR을 펼치고 접음 |
| 휴대폰 설치 안내 마크업 | 안내 문구, QR 이미지, 안내하는 주소가 서로 맞음 |
| 버전 번호의 자리 수가 다름 | 올바르게 비교함 |

### 7-2-2 자동화하지 않은 영역

| 영역 | 이유 |
| --- | --- |
| 드래그 앤 드롭 정렬 | 드래그 이벤트와 포인터 좌표를 Node 환경에서 재현하는 비용이 큼 |
| 드래그 중 자동 스크롤 | 실제 레이아웃과 스크롤 위치가 필요함 |
| 팝업 렌더 결과 | 확장 저장소 콜백과 화면 렌더가 묶여 있음 |
| 테마와 색 표현 | 시각 판단. 모드 해석, 대체값, 되돌리기는 자동 테스트가 봄 |
| 브라우저 단축키 등록 | 브라우저가 정하는 영역 |
| 스토어 심사 요구사항 | 외부 시스템 |

화면 로직을 순수 함수로 옮길 수 있으면 공용 규칙으로 옮겨 자동 테스트 대상으로 만든다.

### 7-2-3 수동 검증 항목

**1. 팝업**

| 확인 항목 | 기대 결과 |
| --- | --- |
| 일반 클릭 | 새 탭이 앞에 열리고 팝업이 닫힘 |
| `Ctrl`/`Cmd` + 클릭 | 새 탭이 뒤에 열리고 팝업이 남음 |
| 휠(가운데) 클릭 | 새 탭이 뒤에 열리고 팝업이 남음 |
| 검색 입력 | 담지 않은 서비스까지 점수 순으로 보임 |
| 검색 후 `Enter` | 첫 결과가 현재 탭에서 열림 |
| 한글 조합 중 `Enter` | 조합만 확정되고 이동하지 않음 |
| `/` 키 | 검색창으로 포커스 |
| 숫자 `1`~`9` | n번째 카드가 열림 |
| 검색창에 숫자 입력 | 숫자 단축키가 동작하지 않음 |
| 빈 결과 | 빈 결과 문구가 보임 |
| 아이콘 로딩 실패 | 확장 기본 아이콘으로 바뀜 |
| 줄바꿈 표에 있는 긴 이름 카드 | 표의 지점에서 꺾임 |
| 목록이 길어 스크롤바가 뜬 상태 | 줄바꿈 지점이 그대로 |
| 저장소 응답이 늦는 상황 | 헤더, 검색창, 푸터가 보이고 카드 격자만 빔 |

**2. 설정 페이지**

| 확인 항목 | 기대 결과 |
| --- | --- |
| 오른쪽으로 드래그 | 내 바로가기에 담기고 왼쪽 목록에서 사라짐 |
| 왼쪽으로 드래그 | 원래 카테고리 묶음의 이름순 자리로 돌아감 |
| 내 바로가기 안에서 드래그 | 순서가 바뀜 |
| 긴 목록의 위아래 가장자리로 드래그 | 스크롤 영역이 저절로 스크롤됨 |
| 항목의 새 탭 링크 클릭 | 그 서비스가 새 탭에서 열림 |
| 새 탭 링크 위에서 드래그 | 항목 드래그가 시작되지 않음 |
| 저장 버튼 | 성공 알림 창이 뜸 |
| 저장 후 새로고침 | 순서가 그대로 |
| 저장 후 팝업 열기 | 같은 순서로 보임 |
| 검색 | 결과가 없는 카테고리 묶음이 숨음 |
| 단축키가 비어 있고 안내를 닫지 않음 | 팝업 안내와 설정 안내가 보임 |
| 단축키를 지정한 뒤 | 두 안내가 사라짐 |

| 확인 항목 | 기대 결과 |
| --- | --- |

| 레이아웃 | 색만 바뀌고 배치와 크기는 그대로 |
| 옛 색 값 | 확장 소스와 문서 전체에서 바꾼 색의 옛 값이 남지 않음. 다크 규칙 안의 고정 배경색, 문서에 적힌 색 값, 이미지에 그려 넣은 색까지 봄 |

| 첫 페인트 적용 | 본문이 시작되는 시점에 문서 루트에 테마 표식이 있음 |
| 아이콘 따라오기 | 시스템과 반대 모드를 고른 상태에서 서비스 아이콘이 고른 모드를 따름 |
| 모드 유지 | 새로고침하거나 다시 열어도 고른 모드로 열림 |

### 7-2-4 검증 환경

| 대상 | 방법 | 주의 |
| --- | --- | --- |
