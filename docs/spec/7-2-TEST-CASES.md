# 7-2 테스트 케이스

이 문서는 테스트 범위와 외부 의존성 대체, 자동 테스트가 검증하는 상황과 기대 결과, 자동화하지 않은 영역, 변경 유형별 수동 검증 항목, 검증 환경, 자동화로 잡지 못하는 실패의 확인 절차를 정한다.

PR 본문에 검증 결과를 적는 절차는 작업 하네스에, 문의 폼의 조건은 계약에, 실패 시 동작은 오류 처리에 있다. ([AGENTS.md 수동 검증 기준](../../AGENTS.md#수동-검증-기준), [5-4 Google Forms](5-CONTRACT.md#5-4-google-forms), [7-1 오류 처리](7-1-ERROR-HANDLING.md))

순수 로직은 자동 테스트로, 화면 동작은 수동 검증 항목으로 확인한다. 어느 쪽도 상대를 대신하지 않는다. 브라우저 확장 API와 드래그 앤 드롭은 Node 테스트 환경에서 재현하기 어렵기 때문이다.

<br>

### 7-2-1 자동 테스트

| 종류 | 확인 범위 | 외부 호출 | 실행 |
| --- | --- | --- | --- |
| 단위 | 공용 규칙, 문의 요청 조립, 테마 해석, 릴리스 노트 가공, 휴대폰 판정 | 없음 | `npm test`, CI |
| 화면 동작 | 팝업, 설정, 랜딩 스크립트를 격리된 환경에서 실행해 렌더, 저장, 경쟁 조건 확인 | 대역 | `npm test`, CI |
| 데이터 | 저장소의 실제 `src/data.js`와 아이콘 파일 | 없음 | `npm test`, `npm run validate:*`, CI |
| 패키징 | 임시 폴더에서 만든 ZIP의 파일 목록과 재현성 | 없음 | `npm test`, CI |
| 수동 | 실제 브라우저의 화면 동작, 실제 폼 전송, 스토어 심사 | 실제 서비스 | 7-2-3, 7-2-5 |

| 외부 의존성 | 대체 방법 |
| --- | --- |
| 확장 API | `chrome` 객체를 대역으로 넣는다. 저장소 콜백을 붙잡아 두었다가 원하는 순서로 불러 경쟁 조건을 재현한다 |
| GitHub 릴리스 API | `fetch`를 대역으로 바꿔 고정 응답, 실패, HTTP 오류 응답을 돌려준다 |
| Google Forms | 요청을 보내지 않고 조립한 주소와 본문만 비교한다 |
| 브라우저 웹 저장소 | 대역 저장소를 넣고 쓰기 실패와 막힌 저장소를 재현한다 |
| 릴리스 노트 | 저장소의 실제 `docs/releases/` 파일을 읽는다 |

`npm test`는 Node 내장 테스트 러너(`node --test`)로 저장소의 `*.test.js` 파일을 찾아 실행한다. 테스트 파일은 `tests/`에 `*.test.js` 이름으로 둔다. 의존성 없는 구성을 지키려고 별도 테스트 프레임워크를 두지 않는다. 데이터 검증 테스트가 저장소의 실제 데이터를 검사하므로 `npm test`만 실행해도 데이터가 깨졌는지 알 수 있다.

| 규칙 | 이유 |
| --- | --- |
| 통과를 기록할 때 실행된 테스트 수가 0이 아닌지 함께 본다 | Node 버전에 따라 테스트를 하나도 찾지 못했는데 성공으로 끝날 수 있다 |
| 경쟁 조건은 콜백을 붙잡아 두었다가 원하는 순서로 부르는 대역으로 재현한다 | 콜백을 바로 부르는 대역으로는 순서 문제를 검증하지 못한다 |
| 방어 코드가 막는 상황이 실제로 생기는지 테스트로 먼저 재현한 뒤 판단한다. 재현되면 규모만 줄이고, 재현되지 않으면 근거를 남기고 걷어 낸다 | 생기지 않는 상황을 막는 코드는 읽는 사람만 헷갈리게 한다 |

### 7-2-2 자동화하지 않은 영역

| 영역 | 이유 |
| --- | --- |
| 드래그 앤 드롭 정렬 | HTML5 드래그 이벤트와 포인터 좌표를 Node 환경에서 재현하는 비용이 크다 |
| 드래그 중 자동 스크롤 | 실제 레이아웃과 스크롤 위치가 필요하다 |
| 팝업 렌더 결과 | 확장 저장소 콜백과 DOM 렌더가 묶여 있다 |
| 테마와 색 표현 | 시각 판단은 사람이 본다. 모드 해석, 대체값, 되돌리기 같은 순수 로직은 자동 테스트가 본다 |
| 브라우저 단축키 등록 | 브라우저가 정하는 영역이라 확장 코드 밖이다 |
| 스토어 심사 요구사항 | 외부 시스템이다 |

화면 로직을 순수 함수로 옮길 수 있으면 공용 규칙 파일로 옮겨 자동 테스트 대상으로 만든다.

### 7-2-3 수동 검증 항목

**1. 팝업**

| 확인 항목 | 기대 결과 |
| --- | --- |
| 일반 클릭 | 새 탭이 앞에 열리고 팝업이 닫힌다 |
| `Ctrl`/`Cmd` + 클릭 | 새 탭이 뒤에 열리고 팝업이 남는다 |
| 휠(가운데) 클릭 | 새 탭이 뒤에 열리고 팝업이 남는다 |
| 검색 입력 | 담지 않은 서비스까지 전체 목록에서 이름, id, 카테고리가 맞는 서비스가 점수 순으로 보인다 |
| 검색 후 `Enter` | 첫 결과가 현재 탭에서 열린다 |
| 한글 조합 중 `Enter` | 조합만 확정되고 이동하지 않는다 |
| `/` 키 | 검색창으로 포커스가 옮겨진다 |
| 숫자 `1`~`9` | n번째 카드가 열린다 |
| 검색창에 숫자 입력 | 숫자 단축키가 동작하지 않는다 |
| 빈 결과 | 빈 결과 문구가 보인다 |
| 아이콘 로딩 실패 | 확장 기본 아이콘으로 바뀐다 |
| 줄바꿈 표에 있는 긴 이름 카드 | 표의 지점에서 꺾인다 |
| 목록이 길어 스크롤바가 뜬 상태 | 줄바꿈 지점이 그대로다 |
| 저장소 응답이 늦는 상황 | 헤더, 검색창, 푸터가 보이고 카드 격자만 빈다 |

**2. 설정 페이지**

| 확인 항목 | 기대 결과 |
| --- | --- |
| 오른쪽으로 드래그 | 내 바로가기에 담기고 왼쪽 목록에서 사라진다 |
| 왼쪽으로 드래그 | 원래 카테고리 묶음의 이름순 자리로 돌아간다 |

### 7-2-5 특별 검증 절차

**1. 문의 폼 실제 전송**

필드 id가 틀리거나 폼 설정이 어긋나면 화면에는 전송 완료 안내가 뜨고 응답만 수집되지 않는다. 아무도 모른 채 의견이 사라지므로 아래 절차로 확인한다.

| 언제 | 할 일 |
| --- | --- |
| 폼을 새로 연결하거나 질문 구성을 바꿨을 때 | 실제로 한 번 보내 응답이 수집됐는지 눈으로 확인한다. 코드 리뷰와 자동 테스트로 대신할 수 없다 |
| 위 확인을 할 때 | 확장과 랜딩에서 각각 보낸다. 두 경로가 같은 폼을 쓰는지는 테스트가 보지만 폼 자체가 살아 있는지는 보지 못한다 |
| 유형 질문을 고쳤을 때 | 세 유형을 각각 보내 응답 시트에 같은 값이 저장되는지, 유형 없는 요청도 수집되는지 확인한다 |
| 필드 id를 확인할 때 | 공개된 폼 페이지에서 직접 본다. 일반 공유 링크에는 필드 id가 없다 |

<br>

**2. 공개 폼 점검**

공개된 `viewform` 페이지에 폼 구조가 들어 있어 필드 id와 필수 여부를 한 번에 볼 수 있다.

```bash
FORM=https://docs.google.com/forms/d/e/<폼 ID>/viewform
curl -sL "$FORM" -o /tmp/form.html

python3 - /tmp/form.html <<'PYEOF'
import re, sys, json
html = open(sys.argv[1], encoding="utf-8").read()
data = json.loads(re.search(r'FB_PUBLIC_LOAD_DATA_ = (.*?);</script>', html, re.S).group(1))
for question in data[1][1]:
    for entry in (question[4] or []):
        print(f'"{question[1]}"  entry.{entry[0]}  필수={"O" if entry[2] else "X"}')
PYEOF
```

출력이 아래와 다르면 폼 계약이 깨진 것이다. 유형 질문의 객관식 선택지도 계약의 유형 값과 대조한다.

```text
"문의 내용"         entry.1096769292  필수=O
"답변 받을 이메일"  entry.491031779   필수=X
"문의 유형"         entry.275621407   필수=X
```

<br>

**3. 랜딩 색은 계산값으로 비교**

랜딩은 애니메이션이 계속 돌아 스크린샷 캡처가 안정적으로 끝나지 않는다. 색이나 테마를 검증할 때는 스크린샷 대신 계산된 스타일 값을 읽어 비교한다. 라이트와 다크는 시스템 설정을 바꾸지 않고 브라우저의 미디어 특성 강제 기능과 테마 토글로 바꿔 가며 각각 측정한다.
