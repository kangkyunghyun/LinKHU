# 4-6. 서비스 아이콘

이 문서는 서비스 아이콘의 크기와 형식, 팔레트, 라이트와 다크 두 벌 체계, 생성기와 검증, SVG 원본의 위치, 추가와 변경 절차를 정한다.

UI 아이콘 규칙은 UI 시스템에, 데이터의 아이콘 경로 형식과 삭제 절차는 데이터에, 그리는 절차와 실측한 도안 규칙(선 두께, 여백, 붉은색 비중)은 `.claude/skills/service-icon/SKILL.md`에 있다. ([4-2-4 UI 아이콘](4-2-UI-SYSTEM.md#4-2-4-ui-아이콘), [6-2-2 필드 규칙](6-2-DATA.md#6-2-2-필드-규칙), [6-2-5 변경 절차](6-2-DATA.md#6-2-5-변경-절차))

서비스 아이콘은 팝업에서 40px, 설정에서 24px로 보인다. 세부가 많은 도안은 이 크기에서 뭉개지므로 한눈에 구분되는 단순한 상징을 쓴다.

<br>

## 4-6-1 기본 규칙

| 항목 | 값 |
| --- | --- |
| 캔버스 | `70x70` |
| 배경 | 투명. 라이트와 다크 두 벌 모두 |
| 파일 형식 | PNG. 다크 벌 생성기와 짝 검증이 PNG만 다룬다 |
| 폴더 | `src/images/common/`, `src/images/colleges/`, `src/images/departments/` |
| 파일명 | 새 아이콘은 서비스 `id`와 맞춤. 검증하지 않으며 다른 이름의 기존 아이콘도 있음 |
| 데이터 연결 | `imgSrc`에 `src/` 기준 상대 경로 (예: `images/common/portal.png`) |

폴더 구분은 파일을 나눠 담는 관례이며 데이터의 `category`와 별개다. 경로는 `imgSrc`가 통째로 가지므로 카테고리에서 유도하지 않고, 카테고리가 바뀌어도 아이콘 파일을 옮기지 않는다.

<br>

## 4-6-2 팔레트

| 벌 | 쓰는 색 | 그 위 배경 |
| --- | --- | --- |
| 라이트 | 브랜드 레드 `#a40f16`, 검정 `#1a1a1a`, 투명. 세 가지뿐 | 밝은 표면 |
| 다크 | 무채 선화 `#a1a1aa`, 붉은 계열 `#d94a52`. 두 가지뿐 | 다크 카드 `#161616` |

| 규칙 | 이유 |
| --- | --- |
| 회색 채움을 두지 않는다. 면을 회색으로 채우지 않고 비운 채 선화로 표현한다 | 격자 안의 아이콘이 같은 무게로 보인다 |
| 경계의 안티에일리어싱은 검정의 알파로만 표현한다. 흰 배경과 섞여 회색으로 합성되는 것은 정상이다 | 팔레트 밖의 색을 만들지 않는다 |
| 다크 벌의 두 색은 다크 카드 위에서 각각 7.06:1, 4.35:1이다 | 비텍스트 기준 3:1을 넘는다 |
| 다크 벌의 안티에일리어싱도 알파로 표현한다 | 목표색보다 밝은 픽셀이 생기지 않는다 |
| 모든 아이콘이 이 팔레트를 쓴다. 팔레트 밖의 색을 추가하지 않는다 | |

<br>

## 4-6-3 두 벌 체계

서비스 아이콘은 테마별로 두 벌이다. 한 벌을 두 테마에서 함께 쓰지 않는다. 사람이 그리는 것은 라이트 한 벌뿐이다.

| 벌 | 위치 | 만드는 방법 |
| --- | --- | --- |
| 라이트 | `src/images/` 아래 카테고리 폴더 | 사람이 그린다 |
| 다크 | `src/images/dark/` 아래 같은 구조 | 생성기가 만든다 |

| 규칙 | 내용 |
| --- | --- |
| 경로 | 라이트 경로의 `images/`를 `images/dark/`로 바꾼다. 나머지 구조와 파일명은 같다 |
| 데이터 | `imgSrc`에는 라이트 경로만 적는다. 다크 경로는 화면 스크립트가 유도한다 |
| 다크 벌 수정 | 손으로 그리거나 고치지 않는다. 생성기가 다시 만들어 덮는다 |
| 다크 벌의 색 | 원본 색과 무관하게 생성기가 정해진 두 색으로 다시 칠한다 |
| 새 서비스 | 두 벌을 모두 만든다. 라이트만 두면 다크 테마에서 그 아이콘만 깨진다 |

어느 벌을 그릴지는 화면이 고른 테마가 정한다. 확장과 랜딩 모두 스크립트가 현재 테마로 경로를 고르고, 테마가 바뀌면 이미 그려진 아이콘의 경로를 바꾼다. 마크업의 조건부 이미지 선택은 시스템 설정만 보므로 쓰지 않는다. 그 방식이면 사용자가 라이트를 골라도 시스템이 다크일 때 화면은 밝은데 아이콘만 다크 벌이 된다.

두 벌 모두 배경이 투명하다. 불투명한 배경이 한 장이라도 섞이면 반대 테마의 카드에서 그 아이콘만 밝거나 어두운 사각형으로 떠 보인다. 배경이 투명하면 아이콘 칸에 표면 토큰을 그대로 쓸 수 있어 테마별 칸 색이 필요 없다.

<br>

## 4-6-4 생성기와 검증

```text
npm run generate:dark-icons    # 라이트 배경 제거와 다크 벌 생성 (파일을 고쳐 씀)
npm run validate:dark-icons    # 짝 검증만 (파일을 쓰지 않음)
```

생성기는 라이트 원본의 흰 배경도 함께 걷어 낸다. 여러 번 돌려도 결과가 같고, 이미 투명해진 원본을 다시 처리해도 색이 어긋나지 않는다. 라이트 원본에 짝이 없는 다크 파일은 지운다.

짝 검증은 빌드에 포함된다.

| 검사 | 막는 것 |
| --- | --- |
| 라이트마다 같은 경로의 다크 파일이 있는가 | 다크 테마에서 깨지는 아이콘 |
| 라이트에 짝이 없는 다크 파일이 남았는가 | 지운 서비스의 다크 사본 |
| 다크 파일이 라이트 원본으로 다시 생성한 결과와 픽셀 단위로 같은가 | 손으로 고치거나 생성을 잊은 다크 파일 |
| 라이트 원본에 흰 배경이 남았는가 | 배경을 걷어 내지 않은 원본 |
| 두 벌 모두 네 모서리가 투명한가 | 배경이 남은 파일 |

모서리 검사는 알파 10/255까지 허용한다. 원본 도안의 경계 안티에일리어싱이 모서리까지 옅게 번지는 경우가 있어 0을 요구하면 정상 자산이 걸린다.

<br>

## 4-6-5 SVG 원본

새로 그리는 아이콘은 SVG 원본을 `assets/icons/<카테고리 폴더>/<id>.svg`에 남긴다. 색 규칙이 바뀌면 원본에서 다시 내보낸다. SVG 원본이 없는 기존 아이콘도 있다.

SVG 원본은 `src/` 안에 두지 않는다. 패키징이 `src/` 아래 모든 파일을 확장 패키지에 넣으므로, SVG가 그 안에 있으면 사용자에게 배포되는 확장에 함께 들어간다.

<br>

## 4-6-6 추가와 변경 절차

아이콘을 추가하거나 바꾼 뒤 차례로 실행한다.

```text
npm run generate:dark-icons     # 다크 벌 생성, 라이트 배경 제거
npm run generate:landing-data   # 랜딩 아이콘 사본 갱신
npm run validate:data
npm run build                   # 두 벌 짝 검증 포함
```
