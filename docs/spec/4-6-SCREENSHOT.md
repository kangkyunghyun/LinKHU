# 4-6. 스크린샷

랜딩 페이지, README 두 개, 스토어 등록 정보가 같은 이미지 세 장을 쓴다. **다음 릴리스에서 같은 구도로 다시 찍을 수 있도록** 해상도·여백·상태를 고정한다.

파일은 `landing/assets/screenshots/`에 있고 **파일명을 바꾸지 않는다**. 랜딩과 README가 경로를 하드코딩하고 있다.

```text
§4-6-1   규격             파일별 크기와 배율
§4-6-2   공통 원칙         테마와 촬영 방식
§4-6-3   팝업              치수와 표시 범위
§4-6-4   설정              치수와 표시 범위
§4-6-5   히어로            실제 창 촬영
§4-6-6   개인정보 처리      포털 로그인 화면을 찍을 때
§4-6-7   촬영 후 확인       산출물과 레이아웃
```

## 4-6-1 규격

| 파일 | 크기 | 배율 | 내용 |
| --- | --- | --- | --- |
| `screenshot-popup.png` | 640×894 | **2배** (표시 320×447) | 팝업만 |
| `screenshot-options.png` | 1280×800 | 1배 | 설정 페이지 |
| `screenshot.png` | 1280×800 | 1배 | 히어로 — 포털에서 팝업을 열고 브라우저 창을 촬영 |

- **팝업만 2배로 찍는다**. 랜딩에서 작게(폭 31%) 표시되는데 1배로는 흐려 보인다. 나머지 둘은 크게 표시되므로 1배로 충분하다.
- 랜딩의 `width`/`height` 속성에는 **표시 기준 1배 치수**를 적는다(`320`/`447`). 파일 픽셀값을 적으면 두 배 크기로 자리를 잡는다.

## 4-6-2 공통 원칙

| 규칙 | 왜 |
| --- | --- |
| **라이트 테마로 찍는다** | 기존 이미지가 라이트이고 랜딩·README 레이아웃이 그에 맞춰져 있다 |
| **검색창은 비운 상태로 찍는다** | 검색어가 남아 있으면 목록이 걸러진 상태가 찍힌다 |

히어로와 나머지 두 장은 **촬영 방식이 다르다.**

| 파일 | 방식 | 브라우저 UI |
| --- | --- | --- |
| 히어로 | 실제 툴바 팝업을 열고 **브라우저 창을 찍는다** | 포함 |
| 팝업·설정 | 확장 페이지를 **직접 열어** 찍는다 | 없음 |

팝업·설정은 툴바 팝업을 띄울 필요가 없다. 확장을 로드한 뒤 아래 주소를 직접 연다.

```
chrome-extension://<확장 ID>/popup.html
chrome-extension://<확장 ID>/options.html
```

## 4-6-3 팝업

- 뷰포트 **320×447**, `deviceScaleFactor: 2` → 결과 640×894.
- 기본 바로가기 9개가 3×3으로 들어차고, 상단 검색창과 하단 링크(`홈페이지 · 문의하기`)까지 잘리지 않아야 한다.
- 세로 447px은 v2.4.0의 자연 높이다. **UI 요소가 늘거나 줄면 이 값을 다시 재고 랜딩의 `height` 속성도 같이 고친다**.

## 4-6-4 설정

- 뷰포트 **1280×800**, 1배.
- 왼쪽 `사용 가능한 사이트`와 오른쪽 `내 바로가기`가 모두 보이고, 아래 `변경사항 저장하기` 버튼까지 들어가야 한다.
- 스크롤은 맨 위에 둔다.

## 4-6-5 히어로

**실제 브라우저 창을 찍는다. 합성하지 않는다**.

1. 확장을 브라우저에 로드한 상태에서 `portal.khu.ac.kr`을 연다.
2. 창을 **1280×800**에 맞춘다.
3. **툴바 아이콘을 눌러(또는 `Ctrl`/`Cmd`+`Shift`+`L`) 실제 팝업을 띄운다.**
4. §4-6-6의 개인정보 처리를 끝낸 뒤 창 전체를 찍는다.

팝업을 따로 찍어 합성하지 않는 이유는, 합성본은 팝업이 툴바에 매달려 있지 않아 **붙여넣은 티가 나기** 때문이다. 실제 팝업은 툴바 아이콘 아래에 화살표 없이 붙어 나오고 그림자도 브라우저가 그리므로, 창을 그대로 찍는 편이 자연스럽다.

**히어로에는 브라우저 탭바·주소창이 포함된다.** 랜딩이 `.browser-dots`·`.browser-address`로 프레임을 또 그리므로 프레임이 두 겹으로 보인다. 알려진 사항이며 현재는 그대로 둔다.

## 4-6-6 개인정보 처리

포털은 **로그인이 필요한 페이지다.** 로그인 상태로 찍으므로 이름, 학번, 사진, 장학·메시지 내역이 화면에 있다.

**텍스트를 지우는 방식은 통하지 않는다**. 포털이 비동기로 다시 렌더해 되살아난다. 반드시 다음 순서로 한다.

1. **CSS 규칙으로 숨긴다**(`visibility: hidden`). 요소를 지우지 않으므로 레이아웃이 무너지지 않는다.

```js
document.head.insertAdjacentHTML("beforeend", `<style>
  .stu_info_w,
  li.name.bar_line,
  .main_user_w,
  .main_user_box,
  .comInfo,
  .user_text01, .user_text02, .user_text03,
  p.name,
  img[src*="userPhoto.do"],
  .portlet[class*="1003"] .portlet-body,
  .portlet[class*="1018"] .portlet-body { visibility: hidden !important; }
</style>`);
```

`1003`은 장학조회, `1018`은 메시지(PUSH) 패널이다.

2. **스크립트를 멈춘다**. 그래야 이후 재렌더가 숨긴 요소를 되살리지 않는다. DevTools `Sources`에서 일시 정지하거나, 자동화한다면 `Emulation.setScriptExecutionDisabled`를 쓴다.
3. 그 상태에서 촬영한다.
4. **촬영 후 실제로 보이는 텍스트를 훑어 개인정보가 없는지 확인한다**.
5. **확대해서 눈으로 한 번 더 확인한다**. 작은 글씨는 1280×800에서 읽히지 않는다. 최소한 네 곳을 2배로 잘라 본다.

| 확인 영역 | 무엇을 보나 |
| --- | --- |
| 상단 브라우저 크롬 | 탭 제목, 주소창, 프로필 이름 |
| 좌측 사용자 영역 | 이름·사진·학과·학번이 가려졌는지 |
| 팝업에 가린 뒤쪽 | 장학금 금액이 새어 나오는지 |
| 포털 우측 상단 | 이름이 붙는 자리인지 |

**확인 대상은 이름, 학번, 사진, 학과, 장학금 금액이다**. 하나라도 보이면 올리지 않는다.

날짜나 건수처럼 개인을 특정하지 않는 값은 남겨도 된다고 판단할 수 있다. 현재 히어로에는 `PUSH 39건`과 `지급일` 날짜가 의도적으로 남아 있다.

**공개 저장소와 스토어에 올라가는 이미지다**. 확신이 없으면 올리지 않는다.

## 4-6-7 촬영 후 확인

| 확인 | 내용 |
| --- | --- |
| 픽셀 크기 | 세 파일이 §4-6-1의 표와 같은지 |
| 빌드 | `npm run build` 실행 |
| 랜딩 | 로컬 HTTP 서버로 열어 **라이트·다크 양쪽에서** 레이아웃이 깨지지 않는지. 특히 `.popup-frame`은 고정 높이가 없어 이미지 종횡비가 그대로 프레임 높이가 된다 |
| README | 두 개의 이미지 표가 깨지지 않는지. `width`만 있고 `height`가 없으므로 종횡비가 바뀌어도 손댈 필요는 없다 |
