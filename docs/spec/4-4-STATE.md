# 4-4. 상태

이 문서는 LinKHU가 화면 밖으로 들고 나가는 값이 무엇이고, 그 값이 언제 쓰이고 언제 읽히는지를 고정한다. 서버가 없으므로 상태는 전부 `chrome.storage.local`에 있고, 키 다섯 개가 전부다.

키를 늘리는 변경은 **그 키가 사용자 설정인지 내부 캐시인지 먼저 정한 뒤**에 한다. 둘은 저장 시점, 실패 처리, 사용자 통지가 전부 다르다. 이 구분을 건너뛰면 사용자가 하지도 않은 일에 실패 문구가 뜨거나, 사용자가 한 선택이 조용히 사라진다.

외부 시스템과 주고받는 값은 여기가 아니라 5 계약에 있다.

```text
§4-4-1   저장 키 목록              무엇을 저장하는가
§4-4-2   사용자 설정과 내부 캐시   성격이 정반대인 두 부류
§4-4-3   즉시 반영형 설정          저장 버튼을 거치지 않는 사용자 설정
§4-4-4   비동기 렌더               늦게 도착한 콜백이 최신 화면을 덮지 않게
```

## 4-4-1 저장 키 목록

`chrome.storage.local`만 쓴다. `sync`는 쓰지 않는다.

| 키 | 값 | 쓰는 곳 | 성격 |
| --- | --- | --- | --- |
| `userOrder` | 서비스 id 배열 | 설정에서 저장, 팝업·설정에서 읽음 | 사용자 설정 |
| `themeMode` | `"system"` \| `"light"` \| `"dark"` | 설정에서 저장, 팝업·설정에서 읽음 | 사용자 설정 (즉시 반영형) |
| `shortcutNoticeDismissed` | boolean | 팝업에서 저장·읽음 | 사용자 설정 (즉시 반영형) |
| `latestReleaseVersion` | 최신 릴리스 버전 문자열 | `version.js` | 내부 캐시 |
| `latestReleaseVersionTime` | 위 값의 조회 시각(ms) | `version.js` | 내부 캐시 |

## 4-4-2 사용자 설정과 내부 캐시

두 성격이 **정반대로 움직인다.** 어느 쪽인지 정하지 않고 키를 늘리면, 사용자가 하지도 않은 일에 실패 문구가 뜨거나 사용자가 한 선택이 조용히 사라진다.

| | 사용자 설정 (`userOrder`) | 내부 캐시 (`latestReleaseVersion*`) |
| --- | --- | --- |
| 무엇인가 | 사용자가 의도적으로 만든 값 | 네트워크 호출을 줄이려는 파생 데이터 |
| 언제 쓰나 | **설정 페이지의 저장 버튼에서만** | 사용자 조작 없이 자동으로 |
| 저장 실패 | `chrome.runtime.lastError`로 확인해 **사용자에게 알린다** | **알리지 않는다**. 다음 조회에서 해소된다 |
| 값이 없으면 | `getDefaultOrder(MASTER_SITE_LIST)`로 폴백 | 다시 조회해 채운다 |
| 손상되면 | 사용자 설정이 날아간다. 그래서 덮어쓰기에 신중하다 | 기능이 깨지지 않아야 한다 |

드래그 도중에 저장하지 않는 이유는 **되돌릴 수 있는 조작과 확정을 분리**하기 위해서다. 저장 버튼을 누르기 전까지는 화면만 바뀐 상태이므로 사용자가 마음을 바꿀 수 있다.

폴백에는 두 가지 단서가 붙는다.

- 폴백은 **저장된 값이 없을 때만** 동작한다. 이미 저장한 사용자의 `userOrder`는 기본 목록이 바뀌어도 영향을 받지 않는다.
- `userOrder`에 있지만 `MASTER_SITE_LIST`에 없는 id는 **렌더링 단계에서** 걸러낸다. 저장소의 값을 고쳐 쓰지 않는다 — 서비스가 삭제돼도 기존 사용자 설정을 건드리지 않는다.

## 4-4-3 즉시 반영형 설정

`themeMode`와 `shortcutNoticeDismissed`는 사용자 설정이지만 저장 버튼을 거치지 않는다. 고르는 즉시 화면이 바뀌어야 의미가 있는 값이기 때문이다. 대신 **저장에 실패하면 화면을 직전 값으로 되돌리고 실패를 알린다**.

- `themeMode` — 저장 실패 시 화면과 컨트롤을 직전 값으로 되돌린다. 규칙과 근거는 §4-2에 있다.
- `shortcutNoticeDismissed` — 팝업 안내를 닫으면 즉시 숨기고 `true`를 저장한다. 저장에 실패하면 안내를 다시 보이고 `#theme-status` 상태 줄로 실패를 알려야 한다. 단축키 등록 여부를 먼저 확인하고, 미등록일 때만 이 키를 읽어 안내 노출을 결정한다. 근거는 DECISIONS 3-4에 있다.

## 4-4-4 비동기 렌더

팝업 렌더링은 `chrome.storage.local.get` 콜백 안에서 이뤄지는 비동기 흐름이다. 검색어를 빠르게 입력하면 이전 요청의 콜백이 나중에 도착할 수 있으므로, 렌더 토큰으로 최신 요청만 반영한다.

**쓰기 순서가 보장되어도 콜백 도착 순서는 보장되지 않는다.** 늦게 도착한 실패 콜백이 성공한 최신 저장을 되돌리거나, 늦게 도착한 읽기 결과가 사용자의 명시적 선택을 덮는다. 단조 증가 요청 번호와 콜백 진입부의 가드로 막는다.

**경쟁 상태는 테스트로 재현해 실재를 확인한 뒤 판단한다**. 콜백을 즉시 호출하는 테스트는 순서 문제를 검증하지 못하므로, 콜백을 보류했다가 원하는 순서로 발화시키는 스텁을 쓴다.
