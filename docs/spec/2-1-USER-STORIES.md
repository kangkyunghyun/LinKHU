# 2-1. 사용자 스토리

이 문서는 학생 사용자가 LinKHU로 무엇을 하려고 하는지와, 그때 화면이 무엇을 해주는지를 사용자의 말로 적는다. 저장 키 이름이나 함수 같은 내부 사정은 여기 적지 않는다. 그런 것은 4-x 설계와 6-x 구현이 맡는다.

화면 동작을 바꾸는 PR은 여기 적힌 완료 조건을 깨지 않았는지 확인한다.

```text
§2-1-1   팝업 열기            툴바와 단축키로 진입
§2-1-2   바로가기 이동         클릭, 배경 탭, 휠 클릭
§2-1-3   검색                 이름·영문 이름·카테고리로 찾기
§2-1-4   숫자 단축키           손을 마우스로 옮기지 않고 열기
§2-1-5   내 바로가기 구성       설정 페이지에서 고르고 정렬
§2-1-6   버전 확인과 문의       업데이트 안내, 의견 보내기
§2-1-7   홈페이지에서 변경 이력  릴리스마다 무엇이 바뀌었는지
```

## 2-1-1 팝업 열기

브라우저 어디에 있든 교내 서비스 목록을 즉시 열고 싶다.

| 여는 방법 | 동작 |
| --- | --- |
| 툴바의 LinKHU 아이콘 | 누르면 팝업이 열린다 |
| 키보드 단축키 | `Ctrl+Shift+L`, macOS는 `Command+Shift+L` |

**단축키가 비어 있는 경우가 있다.** 다른 프로그램이나 확장이 이미 그 조합을 쓰고 있으면 설치할 때 등록되지 않고, LinKHU가 그 조합을 빼앗을 수도 없다. 드물지 않게 일어나는 일이라, 제품은 이를 알아채서 어디서 직접 지정하면 되는지 알려준다.

| 화면 | 언제 보이나 | 무엇을 알려주나 |
| --- | --- | --- |
| 설정 | 단축키가 비어 있을 때 | 브라우저별로 단축키를 지정하는 화면으로 가는 길. Chrome·Whale·Aside는 주소 규칙과 예시를, Firefox는 부가 기능 관리 경로를 보여준다 |
| 팝업 | 비어 있고 사용자가 안내를 닫지 않았을 때 | 헤더 아래 한 줄. 누르면 설정의 안내로 이동한다. 한 번 닫으면 다음부터 보이지 않고, 닫기가 저장되지 않으면 안내가 다시 나타나며 그 사실을 알려준다 |

**완료 조건**

| 상황 | 기대 |
| --- | --- |
| 팝업이 열렸다 | 내가 정한 순서대로 바로가기가 보인다 |
| 아직 아무것도 고르지 않았다 | 기본 서비스 10개가 가나다순으로 보인다 |
| 보여줄 항목이 없다 | 빈 상태 메시지가 보인다 |

## 2-1-2 바로가기 이동

목록에서 서비스를 눌러 바로 이동하고 싶다. 여러 개를 한꺼번에 열어두고 싶을 때도 있다.

| 입력 | 새 탭 | 팝업 |
| --- | --- | --- |
| 일반 클릭 | 바로 보이게 연다 | 닫힌다 |
| `Ctrl`/`Cmd` + 클릭 | 뒤에서 연다 | 열린 채로 남는다 |
| 휠(가운데) 클릭 | 뒤에서 연다 | 열린 채로 남는다 |

`Ctrl`/`Cmd` 클릭과 휠 클릭에서 팝업이 남는 것이 핵심이다. 학기 초처럼 여러 서비스를 연달아 열어야 할 때 팝업을 다시 열지 않아도 된다.

**완료 조건**

| 상황 | 기대 |
| --- | --- |
| 세 가지 입력 | 위 표대로 동작한다 |
| 서비스 아이콘을 불러오지 못했다 | LinKHU 기본 아이콘으로 대신 보인다. 깨진 그림이 보이지 않는다 |
| 같은 서비스가 두 번 담겨 있다 | 카드는 한 번만 보인다 |

## 2-1-3 검색

목록을 눈으로 훑지 않고 이름을 입력해 찾고 싶다.

| 무엇이 되나 | 내용 |
| --- | --- |
| 무엇으로 찾히나 | 서비스 이름, 짧은 영문 이름, 카테고리 |
| 띄어쓰기 | 무시된다. "e campus"로도 "ecampus"로도 찾힌다 |
| 찾는 범위 | 담아둔 것만이 아니라 **전체 서비스**. 담아두지 않은 것도 찾아서 열 수 있다 |
| 결과 순서 | 이름 앞부분이 맞는 것이 먼저 온다. 그다음이 이름에 포함된 것, 영문 이름, 카테고리 순이다 |
| `/` 키 | 검색창으로 바로 이동한다. 이미 글을 쓰고 있는 중이면 동작하지 않는다 |
| `Enter` | 첫 번째 결과를 지금 보고 있는 탭에서 연다. 한글을 조합하는 중에는 동작하지 않는다 |

**완료 조건**

| 상황 | 기대 |
| --- | --- |
| 일치하는 결과가 없다 | 빈 상태 메시지가 보인다 |
| 검색어를 빠르게 연타했다 | 먼저 친 검색어의 결과가 뒤늦게 화면을 덮지 않는다 |

## 2-1-4 숫자 단축키

자주 쓰는 앞쪽 바로가기는 키보드만으로 열고 싶다.

| 무엇이 되나 | 내용 |
| --- | --- |
| 동작 | `1`~`9` 키로 화면에 보이는 순서대로 n번째 카드를 연다 |
| 동작하지 않을 때 | 검색창에 글을 쓰고 있거나, `Ctrl`·`Alt`·`Cmd`를 함께 눌렀거나, 키를 누른 채 있을 때. 검색어에 숫자를 칠 수 없게 되면 안 되기 때문이다 |
| 열리는 방식 | 카드를 클릭한 것과 같다 |

## 2-1-5 내 바로가기 구성

내 전공과 학년에 맞는 서비스만 팝업에 두고 원하는 순서로 정렬하고 싶다.

설정 페이지는 두 열이다. 왼쪽은 담을 수 있는 전체 서비스를 카테고리별로 나눠 보여주고, 오른쪽은 내 바로가기다.

**담기와 정렬**

| 조작 | 결과 |
| --- | --- |
| 왼쪽 목록 | 이름 가나다순으로 보인다 |
| 이미 담은 서비스 | 왼쪽에서 사라진다. 같은 항목이 양쪽에 동시에 보이지 않는다 |
| 오른쪽으로 드래그 | 담긴다 |
| 왼쪽으로 드래그 | 원래 카테고리 자리로 돌아간다 |
| 오른쪽 안에서 드래그 | 순서가 바뀐다. 이 순서가 팝업에 그대로 보인다 |
| 목록 끝까지 드래그 | 위·아래 가장자리에 포인터를 가져가면 저절로 스크롤된다. 학과 목록이 69개라 이 도움 없이는 위로 옮기기 어렵다 |
| 항목 끝의 링크 클릭 | 그 서비스가 새 탭에서 열린다. 이름만 보고 담을지 정하지 않아도 된다 |
| 링크를 끌었다 | 아무 일도 일어나지 않는다. 링크를 끌었을 뿐인데 항목이 딸려가면 안 되기 때문이다 |

**검색과 카테고리 필터**

설정 페이지에도 검색창이 있고 `/` 키가 동작한다. 검색창 아래에는 카테고리 필터가 있다. 카테고리마다 버튼이 하나씩 있어, 이름을 모르거나 이름만으로는 찾기 어려울 때 눌러서 그 분류만 본다.

| 상황 | 결과 |
| --- | --- |
| 카테고리를 하나도 고르지 않았다 | 전체가 보인다. 전부 끄는 것과 아무것도 고르지 않은 것이 같다 |
| 카테고리와 검색어를 함께 걸었다 | 둘 다 만족하는 것만 보인다. 고르지 않은 카테고리는 이름이 맞아도 나오지 않는다 |
| 페이지를 다시 열었다 | 고른 카테고리는 남지 않고 전체 표시로 돌아온다 |
| 결과가 없는 카테고리 | 그 묶음이 숨는다. 전체 결과가 없으면 빈 상태 문구가 보인다 |
| 달라지는 곳 | 왼쪽 목록뿐이다. 오른쪽 내 바로가기는 검색어와 카테고리 필터의 영향을 받지 않는다 |

**완료 조건**

| 상황 | 기대 |
| --- | --- |
| 드래그만 했다 | 저장되지 않는다. 저장 버튼을 눌러야 저장된다 |
| 검색어나 카테고리 필터를 건 채로 저장했다 | 저장되는 순서가 아무것도 걸지 않았을 때와 같다 |
| 저장에 성공했다 / 실패했다 | 각각 알림이 뜬다. 실패가 조용히 넘어가지 않는다 |
| 새로고침하거나 팝업을 다시 열었다 | 그 순서가 그대로다 |

## 2-1-6 버전 확인과 문의

내가 쓰는 버전이 최신인지 알고 싶고, 불편한 점을 개발자에게 알리고 싶다.

| 무엇이 보이나 | 내용 |
| --- | --- |
| 현재 버전 | 팝업 헤더에 `v2.8.0` 같은 형태로 |
| 업데이트 안내 | 최신 릴리스보다 낮을 때만 링크가 함께 보인다 |
| 링크가 가는 곳 | 내가 설치한 곳. Whale·Firefox·Chrome 각 스토어로 가고, 스토어로 설치하지 않았으면 GitHub 릴리스로 간다 |
| 최신 버전을 확인하지 못했다 | 안내가 보이지 않을 뿐 바로가기는 그대로 열린다 |
| 문의하기 | 팝업과 설정 페이지 아래에 있다. GitHub 계정 없이 보낼 수 있고, 답변받을 이메일은 써도 되고 안 써도 된다 |

**완료 조건**

| 상황 | 기대 |
| --- | --- |
| 문의 내용이 비어 있다 | 보내지 않고 입력을 요구한다 |
| 이메일을 썼는데 `@`가 없다 | 보내지 않고 확인을 요구한다 |
| 보내는 중 | 버튼을 누를 수 없고, 끝나면 성공·실패를 문구로 알려준다 |

## 2-1-7 홈페이지에서 변경 이력 보기

설치하기 전이나 업데이트된 뒤에 무엇이 바뀌었는지 홈페이지에서 보고 싶다.

| 무엇이 보이나 | 내용 |
| --- | --- |
| 위치 | 홈페이지 아래 **업데이트** 구역. 위 메뉴와 맨 아래에서 갈 수 있다 |
| 내용 | 릴리스마다 무엇이 바뀌었는지. 새 버전을 내면 홈페이지가 저절로 따라오므로 여기 보이는 이력이 실제와 어긋나지 않는다 |
| 보이지 않는 것 | 내부 정리 기록. 사용자가 겪는 변화가 아니다 |
| 펼침 | 가장 최근 것만 펼쳐져 있고 나머지는 제목 줄로 접혀 있다 |

**완료 조건**

| 상황 | 기대 |
| --- | --- |
| 이력을 불러오지 못했다 | 구역이 통째로 보이지 않는다. 빈 상자를 남기지 않고, 맨 아래 GitHub 릴리스 링크가 대신 받는다. 홈페이지의 나머지는 그대로 동작한다 |
| 이력 본문에 이상한 기호가 들어 있다 | 글자 그대로 보인다 |
