# 2-1. 사용자 스토리

이 문서는 학생 사용자가 LinKHU로 하려는 일과 각 일의 완료 조건을 사용자 관점에서 정한다.

검색 대상과 순위는 정보 구조에, 테마 모드와 저장 규칙은 테마에, 화면별 처리 순서는 인터랙션에, 실패 시 동작과 문구는 오류 처리에 있다. ([3-5 검색이 다루는 범위](3-INFORMATION-ARCHITECTURE.md#3-5-검색이-다루는-범위), [4-3 테마](4-3-THEME.md), [6-1 인터랙션](6-1-INTERACTION.md), [7-1 오류 처리](7-1-ERROR-HANDLING.md))

<br>

## 2-1-1 팝업 열기

브라우저 어디에 있든 교내 서비스 목록을 바로 열고 싶다.

| 여는 방법 | 동작 |
| --- | --- |
| 툴바의 LinKHU 아이콘 | 누르면 팝업이 열린다 |
| 키보드 단축키 | `Ctrl+Shift+L`, macOS는 `Command+Shift+L` |

다른 프로그램이나 확장이 이미 같은 조합을 쓰면 설치할 때 단축키가 등록되지 않는다. 확장은 그 조합을 가져올 수 없다. 그래서 LinKHU는 단축키가 비어 있는지 확인해 사용자가 직접 지정할 위치를 알려준다.

| 화면 | 언제 보이나 | 무엇을 알려주나 |
| --- | --- | --- |
| 설정 | 단축키가 비어 있을 때 | 브라우저별 단축키 설정 주소<br>Chrome, Whale, Aside 같은 Chromium 기반 브라우저: 주소 규칙과 예시<br>Firefox: 부가 기능 관리 경로<br>주소를 누르면 그 설정 화면을 연다. 열지 못하면 주소를 복사하고 붙여 넣으라고 알린다 |
| 팝업 | 단축키가 비어 있고 사용자가 안내를 닫지 않았을 때 | 헤더 아래 한 줄 안내<br>누르면 설정 안내로 이동<br>닫으면 다시 보이지 않음 |

<br>

**1. 완료 조건**

| 상황 | 기대 |
| --- | --- |
| 팝업이 열렸다 | 내가 정한 순서대로 바로가기가 보인다 |
| 아직 순서를 저장한 적이 없다 | 기본 목록이 보인다 |
| 보여줄 항목이 없다 | 빈 결과 문구가 보인다 |
| 팝업 안내 닫기를 저장하지 못했다 | 안내가 다시 보이고 검색창 아래 상태 줄이 실패를 알린다 |

<br>

## 2-1-2 바로가기 이동

목록에서 서비스를 눌러 바로 이동하고 싶다. 여러 개를 한꺼번에 열어 두고 싶을 때도 있다.

| 입력 | 새 탭 | 팝업 |
| --- | --- | --- |
| 일반 클릭 | 바로 보이게 연다 | 닫힌다 |
| `Ctrl`/`Cmd` + 클릭 | 뒤에서 연다 | 열린 채로 남는다 |
| 휠(가운데) 클릭 | 뒤에서 연다 | 열린 채로 남는다 |

학기 초처럼 여러 서비스를 연달아 열 때 팝업을 다시 열지 않아도 되도록 뒤에서 여는 입력은 팝업을 닫지 않는다.

<br>

**1. 완료 조건**

| 상황 | 기대 |
| --- | --- |
| 세 가지 입력 | 위 표대로 동작한다 |
| 서비스 아이콘을 불러오지 못했다 | 팝업에서 LinKHU 기본 아이콘이 대신 보인다. 깨진 그림이 보이지 않는다 |
| 같은 서비스가 두 번 담겨 있다 | 카드는 한 번만 보인다 |

<br>

## 2-1-3 검색

목록을 눈으로 훑지 않고 이름을 입력해 팝업에서 찾고 싶다.

| 무엇이 되나 | 내용 |
| --- | --- |
| 찾는 범위 | 담아 둔 것만이 아니라 전체 서비스. 담아 두지 않은 것도 찾아서 열 수 있다 |
| 띄어쓰기 | 달리 써도 찾힌다 |
| `/` 키 | 검색창으로 바로 이동한다. 입력란에 포커스가 있으면 동작하지 않는다 |
| `Enter` | 첫 번째 결과를 지금 보는 탭에서 연다. 검색어가 비어 있으면 내 바로가기의 첫 카드를 연다. 한글을 조합하는 중에는 동작하지 않는다 |

설정 페이지의 검색은 결과를 걸러 내기만 하고 `Enter`로 열지 않는다. 랜딩 검색은 `Enter`를 누르면 첫 결과를 새 탭에서 연다.

<br>

**1. 완료 조건**

| 상황 | 기대 |
| --- | --- |
| 일치하는 결과가 없다 | 빈 결과 문구가 보인다 |
| 검색어를 빠르게 연달아 바꿨다 | 먼저 친 검색어의 결과가 뒤늦게 화면을 덮지 않는다 |
| 팝업과 랜딩에서 같은 검색어를 넣었다 | 결과 순서가 같다 |

<br>

## 2-1-4 숫자 단축키

자주 쓰는 앞쪽 바로가기는 키보드만으로 열고 싶다.

| 무엇이 되나 | 내용 |
| --- | --- |
| 동작 | `1`~`9` 키로 화면에 보이는 순서의 n번째 카드를 연다 |
| 열리는 방식 | 카드를 일반 클릭한 것과 같다 |
| 동작하지 않을 때 | 검색창, 문의 본문, 이메일 같은 입력란에 포커스가 있음. 입력란에서 숫자를 칠 수 있어야 한다<br>`Ctrl`, `Alt`, `Cmd`를 함께 누름<br>키를 누른 채 반복 입력 |

<br>

## 2-1-5 내 바로가기 구성

내 전공과 학년에 맞는 서비스만 팝업에 두고 원하는 순서로 정렬하고 싶다.

설정 페이지 왼쪽에는 담을 수 있는 전체 서비스가 카테고리별로 보인다. 오른쪽은 내 바로가기다.

<br>

**1. 담기와 정렬**

| 조작 | 결과 |
| --- | --- |
| 왼쪽 목록 | 이름 가나다순으로 보인다 |
| 이미 담은 서비스 | 왼쪽에서 사라진다. 같은 항목이 양쪽에 동시에 보이지 않는다 |
| 오른쪽으로 드래그 | 담긴다 |
| 왼쪽으로 드래그 | 원래 카테고리 자리로 돌아간다 |
| 오른쪽 안에서 드래그 | 순서가 바뀐다. 이 순서가 팝업에 그대로 보인다 |
| 목록 위아래 가장자리로 드래그 | 저절로 스크롤된다. 학과 목록이 길어 이 도움 없이는 위로 옮기기 어렵다 |
| 항목 끝의 링크 클릭 | 그 서비스가 새 탭에서 열린다. 이름만 보고 담을지 정하지 않아도 된다 |
| 링크를 끌었다 | 아무 일도 일어나지 않는다. 링크를 끌었을 뿐인데 항목이 딸려 가면 안 된다 |

<br>

**2. 검색과 카테고리 필터**

설정 페이지에도 검색창이 있고 `/` 키가 동작한다. 이름을 모르거나 이름만으로 찾기 어려우면 카테고리 필터로 해당 분류만 볼 수 있다.

| 상황 | 결과 |
| --- | --- |
| 카테고리를 하나도 고르지 않았다 | 전체가 보인다. 전부 끄는 것과 아무것도 고르지 않은 것이 같다 |
| 카테고리와 검색어를 함께 걸었다 | 둘 다 만족하는 것만 보인다. 고르지 않은 카테고리는 이름이 맞아도 나오지 않는다 |
| 페이지를 다시 열었다 | 고른 카테고리는 남지 않고 전체 표시로 돌아온다 |
| 결과가 없는 카테고리 | 그 묶음이 숨는다. 전체 결과가 없으면 빈 결과 문구가 보인다 |
| 달라지는 곳 | 왼쪽 목록뿐이다. 오른쪽 내 바로가기는 검색어와 필터의 영향을 받지 않는다 |

<br>

**3. 완료 조건**

| 상황 | 기대 |
| --- | --- |
| 드래그만 했다 | 저장되지 않는다. 저장 버튼을 눌러야 저장된다 |
| 검색어나 필터를 건 채로 저장했다 | 저장되는 순서가 아무것도 걸지 않았을 때와 같다 |
| 저장에 성공했다 | 확인을 눌러야 닫히는 성공 알림 창이 뜬다 |
| 저장에 실패했다 | 확인을 눌러야 닫히는 실패 알림 창이 뜬다 |
| 새로고침하거나 팝업을 다시 열었다 | 저장한 순서가 그대로다 |

<br>

## 2-1-6 버전 확인과 문의

내가 쓰는 버전이 최신인지 알고 싶고, 불편한 점을 개발자에게 알리고 싶다.

| 무엇이 보이나 | 내용 |
| --- | --- |
| 현재 버전 | 팝업 헤더에 `v`와 버전 번호 |
| 업데이트 안내 | 최신 릴리스보다 낮을 때만 "새 업데이트" 링크가 함께 보인다 |
| 링크가 가는 곳 | 스토어에서 설치했으면 쓰는 브라우저의 스토어. Whale은 Whale Store, Firefox는 Firefox Add-ons, 그 밖의 브라우저는 Chrome Web Store<br>스토어 설치본이 아니면 GitHub 릴리스 |
| 최신 버전을 확인하지 못했다 | 마지막으로 확인한 최신 버전으로 판단한다. 확인한 적이 없으면 안내가 보이지 않는다. 바로가기는 그대로 열린다 |
| 문의하기 | 팝업, 설정, 랜딩에서 문의 유형을 고르고 GitHub 계정 없이 의견을 보낸다<br>답변받을 이메일은 선택 입력 |

<br>

**1. 완료 조건**

| 상황 | 기대 |
| --- | --- |
| 문의 유형을 고르지 않았다 | 보내지 않고 "문의 유형을 골라주세요." 문구로 고르기를 요구한다 |
| 문의 내용이 비어 있다 | 보내지 않고 입력을 요구한다 |
| 이메일을 썼는데 `@`가 없다 | 보내지 않고 확인을 요구한다 |
| 보내는 중 | 보내기 버튼과 유형 칩을 누를 수 없다. 끝나면 폼 아래 문구로 전송 결과를 알린다 |

<br>

## 2-1-7 랜딩에서 변경 이력 보기

설치하기 전이나 업데이트된 뒤에 무엇이 바뀌었는지 랜딩에서 보고 싶다.

| 무엇이 보이나 | 내용 |
| --- | --- |
| 위치 | 랜딩 아래쪽 **업데이트** 구역. 맨 아래 링크로 갈 수 있고, 창 폭이 900px보다 넓으면 위 메뉴로도 갈 수 있다 |
| 내용 | 최근 릴리스 다섯 개의 변경 내용<br>새 버전을 내면 랜딩이 저절로 따라온다 |
| 보이지 않는 것 | 내부 정리 기록. 사용자가 겪는 변화가 아니다 |
| 펼침 | 가장 최근 것만 펼쳐져 있고 나머지는 제목 줄로 접혀 있다 |
| 더 오래된 이력 | 구역 아래 GitHub 릴리스 링크로 본다 |

<br>

**1. 완료 조건**

| 상황 | 기대 |
| --- | --- |
| 이력을 불러오지 못했다 | 구역 전체를 숨긴다. 빈 상자를 남기지 않고 맨 아래 GitHub 릴리스 링크로 대신한다. 랜딩의 나머지는 그대로 동작한다 |
| 이력 본문에 HTML 태그 같은 기호가 들어 있다 | 글자 그대로 보인다 |

<br>

## 2-1-8 테마 고르기

화면을 밝게 볼지 어둡게 볼지 내가 정하고 싶다. 운영체제는 밝게 쓰지만 이 화면만 어둡게 보고 싶을 때가 있다.

| 무엇이 보이나 | 내용 |
| --- | --- |
| 위치 | 팝업, 설정 페이지, 랜딩의 머리에 있는 버튼 하나 |
| 누르면 | **시스템 설정 → 라이트 → 다크 → 시스템 설정** 순으로 돈다 |
| 지금 무엇인지 | 버튼 아이콘이 지금 모드를 보여주고, 스크린 리더는 지금 모드와 다음 모드를 함께 읽는다 |
| 바뀌는 범위 | 배경, 글자, 테두리와 서비스 아이콘 |

<br>

**1. 완료 조건**

| 상황 | 기대 |
| --- | --- |
| 라이트나 다크로 고정했다 | 운영체제 설정을 바꿔도 화면이 따라가지 않는다 |
| 시스템 설정으로 두었다 | 운영체제를 어둡게 바꾸는 즉시 열려 있는 화면이 따라온다 |
| 고르고 나서 다시 열었다 | 고른 대로 열린다 |
| 시스템 설정으로 두고 다시 열었거나 랜딩을 다시 열었다 | 밝은 화면이 한 번 스쳤다가 어두워지는 깜빡임이 없다 |
| 확장에서 라이트나 다크를 고르고 다시 열었다 | 화면이 바뀌더라도 한 번으로 끝난다 |
| 운영체제는 어두운데 라이트를 골랐다 | 서비스 아이콘도 밝은 화면용으로 보인다 |
| 확장에서 다크, 랜딩에서 라이트를 골랐다 | 각자 고른 대로 유지된다 |

<br>

## 2-1-9 휴대폰에서 랜딩 열기

휴대폰으로 랜딩을 봤을 때 PC에서 설치할 방법을 알고 싶다.

| 무엇이 보이나 | 내용 |
| --- | --- |
| 언제 | 브라우저가 알려 주는 기기 정보가 휴대폰이나 태블릿일 때. 데스크톱 모드로 연 Android 태블릿은 PC로 본다 |
| 안내 | 확장은 PC 브라우저에서 설치한다는 문구와 랜딩 주소 |
| 링크 복사 | 주소를 복사해 PC로 옮긴다 |
| QR 코드 보기 | 누르면 QR 코드를 펼치고 다시 누르면 접는다 |

<br>

**1. 완료 조건**

| 상황 | 기대 |
| --- | --- |
| PC 브라우저로 열었다 | 안내가 보이지 않는다 |
| 복사하지 못했다 | 화면의 주소를 길게 눌러 복사하라는 문구가 보인다 |
