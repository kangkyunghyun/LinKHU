# 결정 기록

LinKHU가 "왜 이렇게 되어 있는가"를 남긴다. 코드를 읽으면 무엇을 했는지는 알 수 있지만 무엇을 **하지 않기로 했는지**는 알 수 없다. 이 기록은 같은 논쟁을 반복하지 않게 한다.

이 파일은 **스펙이 아니라 로그다.** 번호가 붙은 스펙 문서(`1`~`7`)는 현재 동작을 설명하며 코드와 함께 갱신되지만, 여기는 결정 시점의 기록이라 뒤에 덧붙이기만 한다. 스펙과 어긋나면 스펙이 현재다.

## 쓰는 규칙

1. **다른 설계 방향을 놓고 고른 것만 적는다.** 실패한 시도, 측정 결과, 리뷰 회고는 여기 쓰지 않는다.
2. **쓴 뒤 고치지 않는다.** 결정이 바뀌면 새 줄을 덧붙이고 옛 줄의 상태만 바꾼다.
3. 구현 PR과 같은 PR에서 덧붙인다.
4. **대안에는 거부한 방향과 거부한 이유를 함께 적는다.**
5. 날짜순으로 맨 아래에 쌓는다.
