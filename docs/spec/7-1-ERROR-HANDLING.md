# 7-1 오류 처리

이 문서는 데이터 검증, 저장소, 네트워크, 자산 로딩, 브라우저 기능이 실패했을 때 사용자와 메인테이너가 보는 동작과 문구, 메인테이너가 대응하는 상황을 정한다.

저장 키의 성격은 상태에, 테마의 되돌리기 기준은 테마에, 외부 호출의 계약과 문의 전송의 성공 판정은 계약에, 처리 순서는 인터랙션에 있다. ([4-5-2 사용자 설정과 내부 캐시](4-5-STATE.md#4-5-2-사용자-설정과-내부-캐시), [4-3-2 저장](4-3-THEME.md#4-3-2-저장), [5 계약](5-CONTRACT.md), [6-1 인터랙션](6-1-INTERACTION.md))

<br>

### 7-1-1 공통 원칙

| 원칙 | 예 |
| --- | --- |
| 부분 실패가 바로가기 열기를 막지 않음 | 버전 조회가 실패해도 바로가기는 열림 |
| 사용자가 한 일의 실패만 알림 | 저장 실패는 알리고 캐시 기록 실패는 알리지 않음 |
| 실패 문구는 다음 조치까지 안내함 | "잠시 후 다시 시도해주세요." |

<br>

### 7-1-2 데이터 검증 실패

| 상황 | 동작 |
| --- | --- |
| 데이터 검증에 오류가 있음 | 오류와 경고를 나눠 출력하고 실패 종료 |
| 오류 메시지 | 서비스 식별자와 함께 어느 필드가 왜 잘못됐는지 표시함. 식별자가 없으면 목록 안의 순번 |
| 랜딩 산출물이 낡음 | 생성 방법을 메시지에 넣어 실패 |
| 다크 아이콘 짝이 맞지 않음 | 어긋난 파일 경로를 보이며 실패 |

<br>

### 7-1-3 저장소 실패

| 상황 | 동작 | 문구 |
| --- | --- | --- |
| 저장소 응답이 늦거나 오지 않음 | 헤더, 검색창, 푸터는 보이고 카드 격자만 빔. 화면 전체를 가리는 로딩 화면을 두지 않음 | |
| 저장한 순서가 없음 | 기본 목록 | |
| 저장한 순서에 목록에 없는 식별자 | 빼고 그림 | |
| 저장한 순서에 같은 식별자가 두 번 | 한 번만 그림 | |
| 설정 저장 성공 | 확인을 눌러야 닫히는 알림 창 | "성공적으로 저장되었습니다." |
| 설정 저장 실패 | 확인을 눌러야 닫히는 알림 창. 화면의 순서는 그대로 | "설정을 저장하지 못했습니다. 잠시 후 다시 시도해주세요." |
| 테마 저장 실패 | 화면과 토글을 마지막으로 확인된 모드로 되돌리고 상태 줄을 보임. 확장과 랜딩이 같음 | "테마를 저장하지 못했습니다. 이전 설정으로 되돌렸습니다." |
| 저장된 테마를 읽지 못하거나 값이 손상됨 | `system`으로 칠함 | |
| 단축키 안내 닫기 저장 실패 | 안내를 다시 보이고 상태 줄을 보임. 다음 저장이 성공하면 상태 줄을 비움 | "단축키 안내 숨김을 저장하지 못했습니다. 다시 시도해주세요." |
| 단축키 안내를 닫았는지 읽지 못함 | 안내를 보임 | |
| 버전 캐시 쓰기 실패 | 알리지 않음. 받은 버전으로 비교하고 다음에 열 때 다시 조회함 | |
| 버전 캐시를 읽지 못함 | 캐시가 없는 것으로 보고 조회함. 현재 버전은 보임 | |
| 랜딩 변경 이력 캐시를 읽을 수 없거나 깨짐 | 캐시가 없는 것으로 보고 다시 받음 | |
| 랜딩 변경 이력 캐시를 쓸 수 없음 | 받은 목록은 그대로 보이고 알리지 않음. 다음에 열 때 다시 받음 | |

### 7-1-4 네트워크 실패

| 상황 | 동작 | 문구 |
| --- | --- | --- |
| 최신 버전 조회 실패, GitHub 오류 응답 | 콘솔에 기록하고 이전 캐시 버전으로 비교. 캐시가 없으면 업데이트 안내 없음 | |
| 랜딩 변경 이력 조회 실패, 응답 형식 오류, 게시된 릴리스 없음 | 업데이트 구역 전체를 숨김 | |
| 랜딩 서비스 목록을 불러오지 못함 | 검색 상태 줄과 결과 목록 자리에 각각 알림 | 상태 줄: "서비스 목록을 불러오지 못했습니다."<br>결과 목록: "페이지를 새로고침한 뒤 다시 시도해주세요." |
| 랜딩 서비스 목록 응답이 배열이 아님 | 빈 목록으로 다룸 | 상태 줄: "자주 찾는 서비스 0개"<br>결과 목록: "검색 결과가 없습니다. 다른 이름이나 카테고리로 찾아보세요." |
| 분석 도구를 불러오지 못함 | 쌓인 이벤트를 보내지 않음 | |

**1. 문의 전송**

아래 순서의 검증에서 실패하면 문의를 보내지 않고 상태 문구로 알린다.

| 순서 | 상황 | 동작 | 문구 |
| --- | --- | --- | --- |
| 1 | 문의 유형을 고르지 않음 | 보내지 않음 | "문의 유형을 골라주세요." |
| 2 | 앞뒤 공백을 뺀 본문이 빔 | 보내지 않음 | "문의 내용을 입력해주세요." |
| 3 | 이메일을 썼는데 `@`가 없음 | 보내지 않음 | "이메일 주소를 확인해주세요." |
| 4 | 확장에서 폼 주소나 본문 필드가 비어 있음 | 보내지 않음 | "문의 채널이 아직 준비되지 않았습니다. 잠시 후 다시 시도해주세요." |
| 5 | 보내는 중 | 보내기 버튼과 유형 칩을 누를 수 없음 | "전송 중..." |
| 6 | 성공으로 봄 | 본문을 비우고 유형 선택을 해제함. 이메일은 남김 | "전송되었습니다. 소중한 의견 감사합니다!" |
| 6 | 네트워크 오류 | 본문, 이메일, 고른 유형을 그대로 둠 | 확장: "전송에 실패했습니다. 잠시 후 다시 시도해주세요."<br>랜딩: "전송에 실패했습니다. GitHub 이슈로 남겨주세요." |

### 7-1-5 자산 로딩 실패

| 화면 | 서비스 아이콘을 불러오지 못하면 |
| --- | --- |
| 팝업 | 확장 기본 아이콘(48px)으로 바꿈 |
| 설정 | 대체 없음. 브라우저 기본 표시 |
| 랜딩 | 아이콘 자리에 서비스 이름의 첫 글자 |

데이터 검증이 파일 존재를 확인하므로 대체는 로딩 자체가 실패했을 때만 일어난다.

### 7-1-6 브라우저 기능 실패

| 상황 | 동작 | 문구 |
| --- | --- | --- |
| 휴대폰 설치 안내의 링크 복사 성공 | 상태 줄에 알림 | "링크를 복사했습니다. PC 브라우저에 붙여넣으세요." |

| 단축키 설정 주소의 클립보드 복사도 실패 | 알림 창 | "{주소} 주소를 직접 복사하여 주소창에 붙여넣어 이동해주세요." |

### 7-1-7 메인테이너 대응

| 상황 | 알게 되는 경로 | 조치 |
| --- | --- | --- |
| 교내 서비스 주소가 바뀌거나 닫힘 | 문의, 이슈, 직접 발견 | 6-2-6 기준으로 확인한 뒤 데이터 갱신 PR과 릴리스 |
| GitHub 릴리스 조회 한도 초과 | 알림 없음 | 없음. 팝업은 이전 캐시로 비교하고 랜딩은 구역을 숨김 |
| 문의 폼의 질문이나 설정이 바뀜 | 7-2-5 공개 폼 점검, 응답 시트에 새 응답이 없음 | 폼을 5-4의 조건으로 되돌림 |
| 랜딩 배포 실패 | Pages 워크플로 실패 | 7-4-5의 다시 배포 |

| 스토어 심사 중 재제출 | 제출 워크플로의 `NOT_UPDATEABLE` | 심사가 끝난 뒤 같은 입력으로 다시 실행 |
