# 4-7. 스크린샷

이 문서는 랜딩, README 두 개, 스토어 등록 정보가 함께 쓰는 스크린샷 세 장의 규격과 촬영 방식, 포털 화면을 찍을 때의 개인정보 처리, 촬영 후 확인 항목을 정한다.

스토어 등록 정보에 스크린샷을 올리는 절차는 스토어 제출에 있다. ([7-6 스토어 제출](7-6-STORE.md))

파일은 `landing/assets/screenshots/`에 있고 파일명을 바꾸지 않는다. 랜딩과 README가 경로를 직접 적어 쓴다. 다음 릴리스에서도 같은 구도로 찍도록 해상도, 여백, 상태를 고정한다.

<br>

## 4-7-1 규격

| 파일 | 크기 | 배율 | 내용 |
| --- | --- | --- | --- |
| `screenshot-popup.png` | 640×894 | 2배 (표시 320×447) | 팝업만 |
| `screenshot-options.png` | 1280×800 | 1배 | 설정 페이지 |
| `screenshot.png` | 1280×800 | 1배 | 히어로. 포털에서 팝업을 연 브라우저 창 |

| 규칙 | 이유 |
| --- | --- |
| 팝업만 2배로 찍는다 | 랜딩에서 폭의 31%로 작게 보여 1배로는 흐리다. 나머지 둘은 크게 보여 1배로 충분하다 |
| 랜딩의 `width`, `height` 속성에는 표시 기준 1배 치수(`320`, `447`)를 적는다 | 파일 픽셀값을 적으면 두 배 크기로 자리를 잡는다 |

<br>

## 4-7-2 공통 원칙

| 규칙 | 이유 |
| --- | --- |
| 라이트 테마로 찍는다 | 랜딩과 README의 레이아웃이 라이트 이미지에 맞춰져 있다 |
| 검색창은 비운 상태로 찍는다 | 검색어가 남으면 목록이 걸러진 상태가 찍힌다 |

| 파일 | 촬영 방식 | 브라우저 UI |
| --- | --- | --- |
| 히어로 | 실제 툴바 팝업을 열고 브라우저 창을 찍는다 | 포함 |
| 팝업, 설정 | 확장 페이지를 직접 열어 찍는다 | 없음 |

확장을 로드한 뒤 아래 주소를 연다.

```text
chrome-extension://<확장 ID>/popup.html
chrome-extension://<확장 ID>/options.html
```

<br>

## 4-7-3 팝업

| 항목 | 값 |
| --- | --- |
| 뷰포트 | **320×447**, 기기 배율 2. 결과 640×894 |
| 내 바로가기 | 설정에서 아홉 개를 이 순서로 저장한다. `info21`, `ecampus`, `everytime`, `swedu`, `software`, `cs`, `intern`, `sugang`, `chatkhu` |
| 보이는 범위 | 카드 아홉 개가 3×3으로 차고, 위의 검색창과 아래 링크(`홈페이지 · 문의하기`)까지 잘리지 않는다 |

세로 447px은 이 구성의 자연 높이다. 기본 목록 열 개로 찍으면 격자가 스크롤되어 이 높이가 나오지 않는다. 팝업의 UI 요소가 늘거나 줄면 세로 447px을 다시 재고 랜딩의 `height` 속성도 함께 고친다.

<br>

## 4-7-4 설정

| 항목 | 값 |
| --- | --- |
| 뷰포트 | **1280×800**, 1배 |
| 왼쪽 목록 | 2열, 왼쪽:오른쪽 2:1. 창 폭 1280px은 2열 구간에 든다 |
| 보이는 범위 | 왼쪽 `사용 가능한 사이트`와 오른쪽 `내 바로가기`가 모두 보이고 아래 `변경사항 저장하기` 버튼까지 들어간다 |
| 스크롤 | 맨 위 |

## 4-7-5 히어로

실제 브라우저 창을 찍는다. 팝업을 따로 찍어 합성하지 않는다. 실제 팝업은 툴바 아이콘 아래에 화살표 없이 붙고 그림자도 브라우저가 그리므로, 합성하면 툴바에 매달린 모습이 사라져 붙여 넣은 티가 난다.

| 순서 | 할 일 |
| --- | --- |
| 1 | 확장을 로드한 브라우저에서 `portal.khu.ac.kr`을 연다 |
| 2 | 창을 **1280×800**에 맞춘다 |
| 3 | 툴바 아이콘이나 `Ctrl`/`Cmd`+`Shift`+`L`로 실제 팝업을 띄운다 |
| 4 | 개인정보 처리를 끝낸 뒤 창 전체를 찍는다 |

히어로에는 브라우저 도구 막대(주소 표시)가 들어가므로 랜딩이 그리는 브라우저 틀과 겹쳐 틀이 두 겹으로 보인다.

<br>

## 4-7-6 개인정보 처리

포털은 로그인이 필요한 페이지라 로그인 상태로 찍으면 이름, 학번, 사진, 장학과 메시지 내역이 화면에 있다. 텍스트를 지우는 방식은 통하지 않는다. 포털이 비동기로 다시 그려 지운 내용이 되살아난다.

| 순서 | 할 일 | 확인 |
| --- | --- | --- |
| 1 | 아래 CSS 규칙으로 개인정보 요소를 숨긴다(`visibility: hidden`) | 요소를 지우지 않으므로 레이아웃이 무너지지 않음 |
| 2 | 스크립트를 멈춘다. DevTools `Sources`에서 일시 정지하거나, 자동화할 때는 `Emulation.setScriptExecutionDisabled`를 쓴다 | 이후 다시 그리기가 숨긴 요소를 되살리지 않음 |
| 3 | 그 상태에서 찍는다 | |
| 4 | 찍은 뒤 화면에 보이는 텍스트를 훑는다 | 개인정보 없음 |
| 5 | 아래 네 곳을 2배로 잘라 눈으로 다시 본다 | 작은 글씨는 1280×800에서 읽히지 않으므로 확대해서 확인 |

```js
document.head.insertAdjacentHTML("beforeend", `<style>
  .stu_info_w,
  li.name.bar_line,
  .main_user_w,
  .main_user_box,
  .comInfo,
  .user_text01, .user_text02, .user_text03,
  p.name,
  img[src*="userPhoto.do"],
  .portlet[class*="1003"] .portlet-body,
  .portlet[class*="1018"] .portlet-body { visibility: hidden !important; }
</style>`);
```

`1003`은 장학 조회, `1018`은 메시지(PUSH) 패널이다.

| 확인 영역 | 보는 것 |
| --- | --- |
| 위쪽 브라우저 영역 | 탭 제목, 주소창, 프로필 이름 |
| 왼쪽 사용자 영역 | 이름, 사진, 학과, 학번이 가려졌는지 |
| 팝업에 가린 뒤쪽 | 장학금 금액이 새어 나오는지 |
| 포털 오른쪽 위 | 이름이 붙는 자리인지 |

확인 대상은 이름, 학번, 사진, 학과, 장학금 금액이다. 하나라도 보이면 올리지 않는다. 알림 건수나 지급일처럼 개인을 특정하지 않는 값은 남겨도 된다. 공개 저장소와 스토어에 올라가는 이미지이므로 확신이 없으면 올리지 않는다.

## 4-7-7 촬영 후 확인

| 확인 | 내용 |
| --- | --- |
| 픽셀 크기 | 세 파일이 규격 표와 같다 |
| 빌드 | `npm run build`가 통과한다 |

| README | 두 이미지 표가 깨지지 않는다. `width`만 있고 `height`가 없어 종횡비가 바뀌어도 고칠 필요가 없다 |
