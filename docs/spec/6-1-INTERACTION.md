# 6-1. 인터랙션

이 문서는 화면이 입력을 받고 다시 그릴 때까지의 처리 순서와, 순서를 바꾸면 깨지는 지점을 정한다.

저장 시점과 늦게 도착한 결과의 처리는 상태에, 스크립트 로드 위치는 소프트웨어 아키텍처에, 검색 순위는 정보 구조에, 테마 저장 규칙은 테마에, 실패 시 동작과 문구는 오류 처리에 있다. ([4-5 상태](4-5-STATE.md), [4-4-2 스크립트 결합 방식](4-4-SOFTWARE-ARCHITECTURE.md#4-4-2-스크립트-결합-방식), [3-5 검색이 다루는 범위](3-INFORMATION-ARCHITECTURE.md#3-5-검색이-다루는-범위), [4-3 테마](4-3-THEME.md), [7-1 오류 처리](7-1-ERROR-HANDLING.md))

<br>

## 6-1-1 팝업 렌더

팝업은 처음 열릴 때와 검색어가 바뀔 때마다 같은 순서로 다시 그린다.

```mermaid
%%{init: {"flowchart": {"curve": "basis", "nodeSpacing": 24, "rankSpacing": 32}}}%%
flowchart TD
    A["`**문서 로드**
또는 검색어 입력`"] --> B["`**렌더 번호 발급**
격자 비움`"]
    B --> C["`**저장한 순서 읽기**
확장 저장소`"]
    C --> D{"`**번호가 최신인가**`"}
    D -->|아니오| X["`**결과 버림**`"]
    D -->|예| E{"`**검색어가 있는가**`"}
    E -->|아니오| F["`**저장한 순서**
없으면 기본 목록
목록에 없는 id 제외`"]
    E -->|예| G["`**전체 서비스 정렬**
검색 점수 순`"]
    F --> H["`**같은 id는 한 번만**`"]
    G --> H
    H --> I["`**카드 만들기**
줄바꿈 기회 문자
테마별 아이콘 경로`"]
    I --> J["`**격자 채움**
카드가 없으면
빈 결과 문구`"]
    classDef comp fill:#E8F2E8,stroke:#527A59,color:#182D1D
    classDef store fill:#F5D9C9,stroke:#B97450,color:#452B1D
    class A,B,D,E,X,F,G,H,I,J comp
    class C store
```

| 지킬 것 | 어기면 |
| --- | --- |
| 렌더 번호 발급이 저장소 읽기보다 먼저다 | 두 요청이 같은 번호를 나눠 갖는다 |
| 아이콘은 처음 그릴 때부터 현재 테마의 경로를 쓴다 | 라이트로 그린 뒤 바꾸면 한 번 깜빡인다 |

<br>

## 6-1-2 키 입력

| 키 | 동작 | 동작하지 않는 조건 |
| --- | --- | --- |
| 검색창 입력 | 앞뒤 공백을 뺀 검색어로 6-1-1을 다시 실행한다. 대상은 내 바로가기가 아니라 전체 서비스다 | |
| 검색창의 `Enter` | 화면의 첫 카드를 현재 탭에서 열고 팝업을 닫는다. 검색어가 비어 있으면 내 바로가기의 첫 카드다. 현재 탭을 찾지 못하면 새 탭으로 연다 | 한글 조합 중, 키를 누른 채 반복 입력, 카드 없음 |
| `/` | 검색창으로 포커스를 옮긴다 | 화면 단축키로 받지 않는 입력 |
| `1`~`9` | 화면에 보이는 n번째 카드를 일반 클릭한 것과 같이 연다 | 화면 단축키로 받지 않는 입력 |

팝업과 설정은 같은 화면 단축키 판정을 쓴다. 입력 요소(입력창, 여러 줄 입력, 선택 상자, 편집 가능한 영역)에 포커스가 있거나, `Ctrl`, `Alt`, `Cmd`가 함께 눌렸거나, 키를 누른 채 반복 입력이면 단축키로 받지 않는다. 한글 조합을 확정하려고 누른 `Enter`가 링크를 열면 글자를 지우고 다시 쳐야 하므로 조합 중에는 열지 않는다.

<br>

## 6-1-3 이동 처리

카드는 주소를 가진 링크로 만들되 기본 동작을 막고 확장 API로 연다. 링크의 기본 동작을 그대로 두면 팝업 화면 자체가 이동한다.

| 입력 | 여는 방법 | 팝업 |
| --- | --- | --- |
| 일반 클릭, `Shift` + 클릭 | 새 탭을 앞에 연다 | 닫힌다 |
| `Ctrl`/`Cmd` + 클릭 | 새 탭을 뒤에 연다 | 유지 |
| 휠(가운데) 클릭 | 새 탭을 뒤에 연다 | 유지 |
| 검색창의 `Enter` | 현재 탭에서 연다 | 닫힌다 |
| 푸터의 홈페이지 | 새 탭을 앞에 연다 | 닫힌다 |
| 헤더의 새 업데이트 | 링크 기본 동작으로 새 탭에 연다 | |
| 헤더의 설정 버튼 | 확장의 설정 페이지를 탭으로 연다 | |

| 지킬 것 | 이유 |
| --- | --- |
| 휠 클릭은 보조 버튼 클릭 이벤트로 받는다 | 휠 클릭은 일반 클릭 이벤트로 오지 않는다 |
| 카드의 링크 주소를 비워 두지 않는다 | 주소가 있어야 hover 때 주소가 보이고 접근성 트리에 링크로 잡힌다 |
| 현재 탭에서 여는 것은 검색창의 `Enter`뿐이다 | 그 밖의 경로는 모두 새 탭이다 |

## 6-1-4 설정 저장

```mermaid
%%{init: {"flowchart": {"curve": "basis", "nodeSpacing": 24, "rankSpacing": 32}}}%%
flowchart TD
    A["`**드래그**
화면 순서만 바꿈`"] --> B["`**저장 버튼**`"]
    B --> C["`**오른쪽 단 순서 읽기**
왼쪽 목록, 필터 무시`"]
    C --> D["`**userOrder 저장**
확장 저장소`"]
    D --> E{"`**저장 오류가 있는가**`"}
    E -->|없음| F["`**성공 알림 창**`"]
    E -->|있음| G["`**실패 알림 창**`"]
    classDef comp fill:#E8F2E8,stroke:#527A59,color:#182D1D
    classDef store fill:#F5D9C9,stroke:#B97450,color:#452B1D
    class A,B,C,F,G,E comp
    class D store
```

| 지킬 것 | 이유 |
| --- | --- |
| 순서는 오른쪽 단에 실제로 놓인 항목에서 읽는다 | 검색어와 필터는 왼쪽 표시에만 영향을 주므로 필터를 건 채 저장해도 결과가 같아야 한다 |
| 드래그 중에는 오른쪽 단과 끌고 있는 항목의 카테고리 묶음만 놓을 곳으로 강조한다 | 항목이 돌아갈 수 있는 곳만 보인다 |
| 오른쪽에서 왼쪽으로 옮긴 항목은 원래 카테고리 묶음의 이름순 자리로 돌아간다 | 왼쪽 목록은 항상 이름 가나다순이다 |
| 새 탭 링크를 누른 채 시작한 드래그는 취소한다 | 링크를 끌었을 뿐인데 항목이 딸려 가면 안 된다 |
| 스크롤 영역 위아래 가장자리 40px 안으로 끌면 그 방향으로 16ms마다 8px씩 자동 스크롤한다. 포인터가 영역을 벗어나도 마지막 영역을 기준으로 이어진다 | 이 도움이 없으면 긴 학과 목록에서 위쪽으로 항목을 옮기기 어렵다 |

<br>

## 6-1-5 테마 적용

아래 그림은 확장의 순서다. 테마 표식 적용과 토글 연결은 서로 기다리지 않는 두 갈래이고, 저장된 모드는 두 갈래 어느 쪽보다 늦게 도착할 수 있다.

```mermaid
%%{init: {"flowchart": {"curve": "basis", "nodeSpacing": 24, "rankSpacing": 32}}}%%
flowchart TD
    A["`**테마 스크립트**
head에서 동기 실행`"] --> B["`**표식 적용**
시스템 설정 기준
첫 페인트 전`"]
    B --> C["`**저장된 모드 읽기**
확장 저장소, 비동기`"]
    A --> T["`**본문 로드 후**
토글 연결
아이콘 경로 구독`"]
    C --> D{"`**읽는 사이 골랐는가**`"}
    D -->|아니오| E["`**저장된 모드로 보정**
대부분 system이라 변화 없음`"]
    D -->|예| F["`**사용자 선택 유지**
되돌릴 기준만 갱신`"]
    classDef comp fill:#E8F2E8,stroke:#527A59,color:#182D1D
    classDef store fill:#F5D9C9,stroke:#B97450,color:#452B1D
    class A,B,T,D,E,F comp
    class C store
```

| 지킬 것 | 이유 |
| --- | --- |
| 확장은 칠해진 테마가 바뀔 때 알림을 받아 이미 그려진 아이콘의 경로만 바꾼다 | 표식만 바꿔서는 이미 그려진 이미지가 따라오지 않는다 |
| 구독은 여러 개를 받고 각자 해지할 수 있다 | 팝업과 설정이 각자 아이콘 교체를 구독한다. 구독 자리가 하나면 나중 등록이 앞 등록을 조용히 덮는다 |

랜딩은 저장된 모드를 동기로 읽고 그 모드로 첫 페인트 전에 한 번 칠한다. 다시 칠할 때마다 이미 그려진 아이콘의 경로를 직접 바꾸고, 구독은 쓰지 않는다.

<br>

## 6-1-6 단축키 안내

팝업은 비동기 확인을 두 번 차례로 한다. 순서를 바꾸면 단축키를 등록한 사용자에게도 저장소를 읽는다.

```mermaid
%%{init: {"flowchart": {"curve": "basis", "nodeSpacing": 24, "rankSpacing": 32}}}%%
flowchart TD
    A["`**등록된 단축키 조회**
브라우저 명령 목록`"] --> B{"`**단축키가 있는가**`"}
    B -->|예| X["`**안내 없음**`"]
    B -->|아니오| C["`**닫은 적 있는지 읽기**
shortcutNoticeDismissed`"]
    C --> D{"`**닫은 적 있는가**`"}
    D -->|예| X
    D -->|"`아니오,
읽기 실패`"| E["`**헤더 아래 안내 표시**`"]
    classDef comp fill:#E8F2E8,stroke:#527A59,color:#182D1D
    classDef store fill:#F5D9C9,stroke:#B97450,color:#452B1D
    class B,D,X,E comp
    class A,C store
```

| 상황 | 동작 |
| --- | --- |
| 브라우저 명령 목록 API가 없는 환경 | 아무것도 하지 않는다. 안내가 없는 것이 잘못된 안내보다 낫다 |
| 명령 목록 조회가 실패했다 | 안내를 띄우지 않는다 |
| 닫기를 저장하는 중에 다시 눌렀다 | 무시한다 |
| `설정에서 지정`을 눌렀다 | 설정 페이지의 단축키 안내 위치(`options.html#shortcut-guide`)를 새 탭으로 연다 |

설정 페이지는 단축키가 비어 있을 때만 단축키 안내 구역을 보인다. 등록되어 있거나 명령 목록 API가 없으면 구역을 숨긴다. 주소에 `#shortcut-guide`가 붙어 열렸으면 그 구역으로 스크롤한다. 브라우저 목록은 설정 페이지에만 둔다.

| 브라우저 | 안내하는 곳 |
| --- | --- |
| Chrome | `chrome://extensions/shortcuts` |
| Whale | `whale://extensions/shortcuts` |
| Aside | `aside://extensions/shortcuts` |
| Firefox | `about:addons`의 톱니바퀴 메뉴에서 확장 기능 단축키 관리 |
| 그 밖의 Chromium 기반 | `<브라우저 이름>://extensions/shortcuts` 형식 |

목록의 주소 버튼을 누르면 그 주소를 새 탭으로 연다. 브라우저가 내부 주소 열기를 막으면 주소를 클립보드에 복사하고 알림 창을 띄운다.

<br>

## 6-1-7 문의 유형 선택

팝업, 설정, 랜딩의 문의 유형 칩은 같게 동작한다.

| 상황 | 동작 |
| --- | --- |
| 처음 열었을 때 | 아무 유형도 선택하지 않음 |
| 칩을 누름 | 그 칩만 선택한다. 한 번에 하나만 선택된다 |
| 상태 표시 | 선택한 칩은 `aria-pressed="true"`, 나머지는 `aria-pressed="false"` |
| 패널을 닫았다 다시 엶 | 이전 선택이 그대로 남는다 |
