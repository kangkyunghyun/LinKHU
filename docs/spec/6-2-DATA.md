# 6-2 데이터

이 문서는 지원 서비스 목록의 스키마와 필드 규칙, 항목 사이의 제약, 검증과 생성의 동작, 데이터를 바꾸는 절차를 정한다.

카테고리 목록과 서비스 수, 기본 목록은 정보 구조에, 아이콘 파일 규칙은 서비스 아이콘에, 랜딩 산출물의 형식은 계약에, 삭제된 식별자의 처리는 상태에, 검증 실패 출력은 오류 처리에 있다. ([3-2 카테고리](3-INFORMATION-ARCHITECTURE.md#3-2-카테고리), [3-4 기본 목록](3-INFORMATION-ARCHITECTURE.md#3-4-기본-목록), [4-6 서비스 아이콘](4-6-SERVICE-ICON.md), [5-2 랜딩 파생 산출물](5-CONTRACT.md#5-2-랜딩-파생-산출물), [4-5-2 사용자 설정과 내부 캐시](4-5-STATE.md#4-5-2-사용자-설정과-내부-캐시), [7-1-2 데이터 검증 실패](7-1-ERROR-HANDLING.md#7-1-2-데이터-검증-실패))

<br>

### 6-2-1 스키마

지원 서비스 목록은 서비스 객체의 배열이다. 각 객체의 필드는 정확히 다섯 개이며 값은 모두 비어 있지 않은 문자열이다. 빠진 값, 빈 문자열, 공백만 있는 값은 오류다.

| 필드 | 형식 | 제약 | 의미 | 배포한 뒤 |
| --- | --- | --- | --- | --- |
| 식별자 | 소문자 영문, 숫자, 하이픈 | 중복 불가 | 내 바로가기 순서에 저장되는 값 | 바꾸지 않음. 바꾸면 기존 사용자의 목록에서 조용히 사라짐 |
| 이름 | 문자열 | 중복 불가 | 화면에 보이는 이름 | 고쳐도 됨 |
| 주소 | `https:` 또는 `http:`로 시작하는 해석 가능한 주소 | 중복 불가 | 이동 주소 | 바꿀 때 HTTPS 지원을 다시 확인 |
| 아이콘 경로 | 확장 패키지 안의 라이트 서비스 아이콘을 가리키는 상대 경로 | 파일이 있어야 함. 중복 허용 | 서비스 아이콘 | |
| 카테고리 | 카테고리 목록의 값 하나 | | 카테고리 | 바꾸면 계약 변경 |

| 규칙 | 내용 |
| --- | --- |
| 필드 추가 | 하지 않음. 늘리면 데이터, 이 문서, 검증기, 랜딩 산출물을 함께 바꾸는 계약 변경 |
| 화면 표시용 값 | 기본 목록, 카드 줄바꿈처럼 화면이 쓰는 값은 서비스 필드가 아니라 공용 규칙에 둠 |
| 배열 순서 | 검색 점수가 같을 때의 순서. 재배치하면 검색 결과 순서가 바뀜 |
| 카테고리 목록 | 데이터와 함께 두고 검증기 허용 목록과 같은 값 |

<br>

### 6-2-2 필드 규칙

**1. 주소의 프로토콜**

| 대상 사이트 | 쓸 값 | 검증 |
| --- | --- | --- |
| HTTPS를 지원함 | `https://` | 통과 |
| HTTPS를 지원하지 않거나 인증서가 낡아 HTTPS가 실패함 | `http://` | 경고. 확인한 항목만 이렇게 둠 |
| 그 밖의 프로토콜 | 쓸 수 없음 | 오류 |
| 해석할 수 없는 주소 | 쓸 수 없음 | 오류 |

<br>

**2. 교외 도메인**

등록 기준은 도메인이 아니라 경희대학교 구성원이 학기 중 반복해서 쓰는 서비스인지 여부다. 교외 도메인을 등록하면 근거를 PR에 남긴다. 경희대와 무관한 학생 일반 서비스는 등록하지 않는다.

| 서비스 | 도메인 | 근거 |
| --- | --- | --- |
| 에브리타임 | `everytime.kr` | 학교 커뮤니티가 사실상 이곳에 있음 |
| 경희사이버대 포털 | `portal.khcu.ac.kr` | 학점교류로 경희사이버대 강의를 듣는 학생이 학기 내내 씀 |
| 경희사이버대 LMS | `lms.khcu.ac.kr` | 위와 같음 |

<br>

**3. 아이콘 경로**

| 규칙 | 내용 |
| --- | --- |
| 범위 | 확장 패키지 밖을 가리킬 수 없음. 상위 폴더로 벗어나는 경로와 절대 경로는 오류 |
| 확장자 | `.png`, `.jpg`, `.jpeg`, `.svg` 중 하나여야 검증을 통과함. 파일 형식은 4-6-1 |

<br>

### 6-2-3 컬렉션 규칙

| 규칙 | 내용 |
| --- | --- |
| 중복 | 식별자, 이름, 주소가 겹치면 오류. 아이콘 경로는 허용 |
| 쓰이지 않는 이미지 | 라이트 서비스 아이콘 중 어떤 서비스도 가리키지 않는 파일이 있으면 오류. 다크 벌은 짝 검증이 봄 |

<br>

### 6-2-4 검증 파이프라인

| 단계 | 하는 일 |
| --- | --- |
| 데이터 검증 | 지원 서비스 목록을 격리된 환경에서 읽어 아래 표를 검사함 |
| 랜딩 산출물 생성 | 서비스 목록 데이터와 아이콘 사본을 만들고 쓰이지 않는 사본을 지움 |
| 랜딩 산출물 검사 | 서비스 목록 데이터가 최신인지, 아이콘 사본이 원본과 바이트 단위로 같은지, 쓰이지 않는 사본이 남았는지 봄 |
| 패키징 | 확장 소스 전체에서 이름이 점으로 시작하는 파일과 폴더를 어느 깊이에서든 빼고 ZIP으로 묶음 |

| 데이터 검증 | 검사하는 것 |
| --- | --- |
| 오류 | 객체가 아님, 필수 필드, 식별자 형식과 중복, 이름과 주소 중복, 카테고리 허용값, 아이콘 경로의 확장자, 범위, 파일 존재, 쓰이지 않는 이미지, 줄바꿈 표와 한 줄 폭 |
| 경고 | `http://` 주소 |

### 6-2-5 변경 절차

```mermaid

```

| 서비스 삭제 시 | 확인 |
| --- | --- |
| 아이콘 파일 | 다른 서비스가 참조하지 않을 때만 지움. 어떤 서비스도 참조하지 않게 되면 지움 |
| 다크 짝 | 라이트를 지운 뒤 다크 아이콘 생성으로 지움 |
| 판단이 서지 않으면 | 데이터 검증을 돌림. 참조 중인 파일을 지우면 파일 없음 오류, 남기면 쓰이지 않는 이미지 오류 |
| 기존 사용자 | 저장된 순서에 삭제된 식별자가 남지만 그릴 때 걸러짐 |

<br>

### 6-2-6 URL 점검

| 규칙 | 내용 |
| --- | --- |
| 교체 대상 | 명시적인 404뿐. 봇 차단과 로그인 페이지는 접속 불가로 보지 않음 |
| TLS가 낡은 사이트 | HTTPS만 실패하고 HTTP로 열리면 `http://`로 둠 |
| 학과 홈페이지가 열리지 않음 | 폐쇄로 단정하기 전에 학교 통합 도메인의 하위 경로를 먼저 확인함 |
| 판단이 서지 않음 | 바꾸지 않고 보류함 |
| 실제로 바꿀 때 | 새 주소의 응답을 직접 확인하고 결과를 PR 본문에 남김 |

<br>

### 6-2-7 손으로 적은 서비스 수

서비스 수는 데이터에서 계산되지만 스펙 밖 문서에 손으로 적혀 있고 검증은 문서에 적힌 서비스 수를 확인하지 않는다.

| 적힌 곳 |
| --- |
| README 두 개 |
| 랜딩 본문 |
| 지원 서비스 목록 문서 |
| 스토어 설명 문구 |
| 커뮤니티 홍보 글 |

| 규칙 | 내용 |
| --- | --- |
| 서비스를 추가하거나 삭제하는 PR | 손으로 적은 서비스 수와 정보 구조의 카테고리 표를 함께 갱신함 |
| 기준값 | 지원 서비스 목록을 카테고리별로 센 값 |
