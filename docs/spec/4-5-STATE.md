# 4-5 상태

이 문서는 화면 밖에 보관하는 값의 목록과 성격, 읽고 쓰는 시점, 늦게 도착한 비동기 결과를 다루는 규칙을 정한다.

기본 목록은 정보 구조에, 테마의 되돌리기 기준은 테마에, 화면별 처리 순서는 인터랙션에, 저장 실패 시 화면 동작은 오류 처리에 있다. ([3-4 기본 목록](3-INFORMATION-ARCHITECTURE.md#3-4-기본-목록), [4-3-2 저장](4-3-THEME.md#4-3-2-저장), [6-1 인터랙션](6-1-INTERACTION.md), [7-1-3 저장소 실패](7-1-ERROR-HANDLING.md#7-1-3-저장소-실패))

서버가 없으므로 상태는 브라우저에만 남는다. 키를 늘리기 전에 사용자 설정인지 내부 캐시인지 먼저 정한다. 둘은 저장 시점, 실패 처리, 사용자 알림이 모두 다르다. 구분하지 않으면 사용자가 하지 않은 일에 실패 문구가 뜨거나 사용자의 선택이 조용히 사라진다.

<br>

### 4-5-1 저장 키 목록

확장은 `chrome.storage.local`만 쓰고 `chrome.storage.sync`는 쓰지 않는다.

| 키 | 값 | 쓰는 곳 | 성격 |
| --- | --- | --- | --- |
| `userOrder` | 서비스 id 배열 | 설정의 저장 버튼에서 저장<br>팝업과 설정에서 읽음 | 사용자 설정 |
| `themeMode` | `"system"`, `"light"`, `"dark"` 중 하나 | 팝업과 설정의 테마 토글에서 저장<br>팝업과 설정에서 읽음 | 사용자 설정, 즉시 반영 |
| `shortcutNoticeDismissed` | boolean | 팝업에서 저장과 읽음 | 사용자 설정, 즉시 반영 |
| `latestReleaseVersion` | 최신 릴리스 버전 문자열 | 팝업의 버전 안내에서 저장과 읽음 | 내부 캐시 |
| `latestReleaseVersionTime` | `latestReleaseVersion`을 조회한 시각(ms) | 팝업의 버전 안내에서 저장과 읽음 | 내부 캐시 |

랜딩은 확장 저장소에 닿을 수 없어 브라우저의 웹 저장소를 쓴다. 랜딩의 `themeMode`는 이름이 같아도 확장의 `themeMode`와 다른 값이다.

| 키 | 저장소 | 값 | 쓰는 곳 | 성격 |
| --- | --- | --- | --- | --- |
| `themeMode` | 도메인별 영구 저장소 | `"system"`, `"light"`, `"dark"` 중 하나 | 랜딩 헤더 토글 | 사용자 설정, 즉시 반영 |
| `linkhu-releases` | 탭 세션 저장소 | 릴리스 목록 응답 | 랜딩 업데이트 구역 | 내부 캐시. 탭을 닫으면 사라짐 |

<br>

### 4-5-2 사용자 설정과 내부 캐시

| 항목 | 사용자 설정 | 내부 캐시 |
| --- | --- | --- |
| 의미 | 사용자가 의도해서 만든 값 | 네트워크 호출을 줄이려는 파생 데이터 |
| 쓰는 시점 | 사용자 조작에서만 | 사용자 조작 없이 자동 |
| 저장 실패 | 사용자에게 알린다 | 알리지 않는다 |
| 값이 없을 때 | 정해진 기본값으로 대신한다. `userOrder`는 기본 목록, `themeMode`는 `system` | 다시 조회해 채운다 |
| 손상되면 | 사용자 설정이 사라지므로 덮어쓰기에 신중하다 | 기능이 깨지지 않는다 |

`userOrder`는 설정 페이지의 저장 버튼에서만 쓴다. 드래그 도중에는 저장하지 않아 되돌릴 수 있는 조작과 확정을 나눈다. 저장 버튼을 누르기 전에는 화면만 바뀌므로 사용자가 마음을 바꿀 수 있다.

`userOrder`에 있지만 지원 서비스 목록에 없는 id는 화면을 그릴 때 거르고, 저장된 값을 고쳐 쓰지 않는다. 서비스가 삭제돼도 사용자가 하지 않은 쓰기가 일어나지 않는다.

<br>

### 4-5-3 즉시 반영형 설정

`themeMode`와 `shortcutNoticeDismissed`는 사용자 설정이지만 저장 버튼을 거치지 않는다. 고르는 즉시 화면이 바뀌어야 의미가 있는 값이기 때문이다. 대신 저장에 실패하면 화면을 저장소와 같은 상태로 되돌리고 실패를 알린다.

| 키 | 고를 때 |
| --- | --- |
| `themeMode` | 새 모드를 먼저 적용하고 저장한다 |
| `shortcutNoticeDismissed` | 팝업 안내를 바로 숨기고 `true`를 저장한다 |

`shortcutNoticeDismissed`는 단축키가 비어 있을 때만 읽는다. 단축키가 등록된 사용자에게는 `shortcutNoticeDismissed`를 읽지 않고 안내를 보이지 않는다.

<br>

### 4-5-4 비동기 결과의 순서

저장소 읽기와 쓰기는 비동기로 끝난다. 사용자 설정과 테마는 콜백으로, 버전 캐시는 Promise로 기다린다. 쓰기 순서가 보장되어도 결과가 도착하는 순서는 보장되지 않는다.

| 위험 | 막는 방법 |
| --- | --- |
| 검색어를 빠르게 바꾸면 이전 요청의 읽기 결과가 나중에 도착해 최신 화면을 덮는다 | 팝업은 그릴 때마다 렌더 번호를 새로 발급하고, 결과가 도착하면 자기 번호가 최신일 때만 그린다 |
| 늦게 도착한 실패가 성공한 최신 저장을 되돌린다 | 테마는 요청마다 증가하는 번호를 붙이고, 결과가 도착했을 때 최신 요청이 아니면 버린다 |
| 다른 화면의 저장 알림이 사용자가 방금 고른 값을 덮는다 | 진행 중인 자기 쓰기가 있으면 외부 변경으로 덮지 않는다 |
| 늦게 도착한 초기 읽기 결과가 사용자가 방금 고른 값을 덮는다 | 읽는 사이 사용자가 고른 적이 있으면 화면은 그대로 두고 되돌릴 기준만 갱신한다 |
