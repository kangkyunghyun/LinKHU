# Icon Style Guide

LinKHU 서비스 아이콘은 팝업과 설정 화면에서 작은 크기로 표시되므로, 한눈에 구분되는 단순한 상징을 우선한다.

이 문서는 **아이콘을 실제로 그리고 추가하는 절차**를 다룬다. 크기, 파일 형식, 폴더 배치, 파일명은 이 문서가 원본이다.

그 밖의 규칙 — 두 벌 체계, 브랜드 색, 배경 투명 — 은 [스펙 3-2-4 아이콘](../spec/3-2-DESIGN-UI-RULES.md)이 원본이며, **둘이 어긋나면 스펙이 우선한다.** 스펙이 정한 값은 여기서 다시 적지 않고 링크한다. 같은 값을 두 곳에 적으면 한쪽만 바뀌어 어긋나는데, 이 문서가 실제로 그렇게 어긋나 있었다(이슈 [#106](https://github.com/kangkyunghyun/LinKHU/issues/106)).

## 기본 규칙

- 기본 크기는 `70x70`이다.
- **배경은 투명하게 유지한다.** 라이트·다크 두 벌 모두 해당한다. 파일 형식은 PNG를 권장한다.
- **팔레트는 브랜드 레드·검정·투명 세 가지뿐이다.** 값은 [스펙 3-2-4](../spec/3-2-DESIGN-UI-RULES.md)에 있다. 여기에 적지 않는 이유는 같은 값을 두 곳에 두면 갈라지기 때문이다(이슈 [#106](https://github.com/kangkyunghyun/LinKHU/issues/106)이 그 사례다).
- **회색을 쓰지 않는다.** 면을 회색으로 채우는 대신 비우고 선화로 표현한다.
- 파일명은 가능하면 `src/data.js`의 `id`와 맞춘다.
- 서비스 아이콘은 카테고리에 따라 `src/images/common/`, `src/images/colleges/`, `src/images/departments/` 폴더에 관리한다.
- 새로 그리는 아이콘은 SVG 원본을 `design/icons/<카테고리>/<id>.svg`에 남긴다. `src/` 안에 두면 확장 패키지에 함께 배포된다.
- 새 아이콘을 추가하면 `src/data.js`의 `imgSrc` 필드에 `src/` 폴더를 기준으로 한 상대 경로(예: `images/common/icon.png`)를 지정한다.

## 두 벌 체계

아이콘은 테마별로 두 벌이다. **직접 그리는 것은 라이트 한 벌뿐이고, 다크는 생성기가 만든다.**

| 벌 | 위치 | 어떻게 만드나 |
| --- | --- | --- |
| 라이트 | `src/images/**` | 사람이 그린다 |
| 다크 | `src/images/dark/**` | `npm run generate:dark-icons`로 파생 |

- **다크 아이콘을 손으로 그리거나 고치지 않는다.** 생성기가 라이트 원본에서 다시 만들므로 수정해도 다음 실행에 덮인다.
- **다크 벌은 원본의 색을 쓰지 않는다.** 생성기가 정해진 두 색으로 다시 칠하므로, 라이트 원본을 어떤 빨강으로 그렸든 다크 결과는 같다. 그 색 값과 대비 근거는 스펙에 있다.
- `imgSrc`에는 **라이트 경로만** 적는다. 다크 경로는 코드가 유도한다.
- 생성기는 라이트 원본의 흰 배경도 함께 걷어낸다. 배경이 남아 있어도 실행 후에는 투명해진다.

## 작업 단위

- 공통, 단과대, 학과처럼 카테고리별로 나누어 작업한다.
- 한 PR에서 너무 많은 아이콘을 한꺼번에 변경하지 않는다.
- 아이콘을 추가·변경한 뒤 순서대로 실행한다.

```
npm run generate:dark-icons     # 다크 벌 생성 + 라이트 배경 제거
npm run generate:landing-data   # 랜딩 사본 동기
npm run validate:data
npm run build                   # 두 벌 짝 검증 포함
```

## 팔레트는 전량 정합되어 있다

기존 아이콘은 도안마다 다른 빨강으로 그려져 있었고, 회색 채움도 섞여 있었다. 이슈 [#126](https://github.com/kangkyunghyun/LinKHU/issues/126)에서 **전량을 정합했다.**

따라서 위 색 규칙은 새로 그리는 아이콘뿐 아니라 **모든 아이콘에 적용된다.** 팔레트를 벗어난 색을 새로 들이지 않는다.

정합 근거와 실측은 스펙 [§3-3-17](../spec/3-3-DESIGN-DECISIONS.md)에 있다.
