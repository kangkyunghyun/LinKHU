# 설계

요구사항과 ADR을 바탕으로 **어떻게 구현할지**를 적는다. 구현 전에 쓰고, 구현이 끝나면 고치지 않는다.

## 규칙

- 파일명은 요구사항과 같은 `N-slug.md`.
- **구현 방법이 요구사항·ADR·스펙에서 자명하면 쓰지 않는다.** 한 파일 안의 문구 변경, 데이터 추가, 명백한 버그 수정은 PR 본문으로 충분하다. 파일이 여러 개 움직이거나 순서가 중요하거나 대안을 저울질했을 때 쓴다.
- **구현이 끝나면 수정하지 않는다** (MUST). 구현 중 방법이 바뀌면 본문을 고치지 말고 끝에 `## 구현 중 바뀐 것`을 덧붙인다. 그 뒤로는 손대지 않는다.
- 구현된 결과는 [스펙](../spec/README.md)에 적는다. 설계 문서는 "그때 이렇게 하려 했다"의 기록이다.

## 양식

```markdown
# N. 제목

요구사항: ../requirements/N-slug.md
ADR: ../adr/NNNN-slug.md (있으면)

## 바꾸는 파일
| 파일 | 무엇을 |

## 순서
1. ...

## 검증
- 명령
```
