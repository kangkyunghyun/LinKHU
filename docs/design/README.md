# 설계

요구사항과 ADR을 바탕으로 **어떻게 구현할지**를 적는다. 구현 전에 쓰고, 구현이 끝나면 고치지 않는다.

## 읽는 순서

```text
198   FOUR-LAYER-DOCS   문서 4계층 개편과 랜딩 분리
```

## 문서와 책임

| 문서 | 책임 |
| --- | --- |
| `N-UPPER-KEBAB.md` | 요구사항·ADR을 바탕으로 한 구현 방법과 검증 |
| [198-FOUR-LAYER-DOCS.md](198-FOUR-LAYER-DOCS.md) | 문서 4계층 개편과 랜딩 분리 |
| [요구사항](../requirements/README.md) | 만들 기능과 완료 조건 |
| [ADR](../adr/README.md) | 결정의 배경과 대안 |
| [스펙](../spec/README.md) | 구현된 현재 구조와 동작 |

## 변경 원칙

1. 파일명은 요구사항과 같은 `N-UPPER-KEBAB.md`.
2. **구현 방법이 요구사항·ADR·스펙에서 자명하면 쓰지 않는다.** 한 파일 안의 문구 변경, 데이터 추가, 명백한 버그 수정은 PR 본문으로 충분하다. 파일이 여러 개 움직이거나 순서가 중요하거나 대안을 저울질했을 때 쓴다.
3. **구현이 끝나면 수정하지 않는다** (MUST). 구현 중 방법이 바뀌면 본문을 고치지 말고 끝에 `## 구현 중 바뀐 것`을 덧붙인다. 그 뒤로는 손대지 않는다.
4. 구현된 결과는 [스펙](../spec/README.md)에 적는다. 설계 문서는 "그때 이렇게 하려 했다"의 기록이다.

§N-2   순서
§N-3   검증
```

## N-3 검증

````
