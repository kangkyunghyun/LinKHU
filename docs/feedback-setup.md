# 문의 채널(Google Forms) 설정 가이드

팝업/설정 페이지의 "문의하기"는 Google Forms의 `formResponse` 엔드포인트로 백그라운드 전송하는 방식입니다. 확장 소스에 비밀값이 들어가지 않아 공개 저장소에 안전합니다.

**이 방식은 조용히 실패합니다.** 응답 본문을 읽을 수 없어 잘못 설정해도 오류가 나지 않고, 잘못된 결과만 남습니다. 그래서 이 문서는 설정 절차뿐 아니라 **설정이 실제로 적용됐는지 확인하는 방법**(6절)을 함께 다룹니다.

## 1. Google Form 만들기

1. [Google Forms](https://forms.google.com)에서 새 폼을 만듭니다. 제목 예: `LinKHU 문의`.
2. 질문을 추가합니다.
   - 질문 1 — 유형: **장문형**, 질문: `문의 내용`, 필수 여부: **필수**
   - 질문 2(선택) — 유형: **단답형**, 질문: `답변 받을 이메일`, 필수 여부: **필수 아님**
     - 이 질문을 만들고 아래 4번에서 `emailEntry`까지 연결하면, 문의 폼에 "답변 받을 이메일 (선택)" 입력란이 표시됩니다.
3. 설정 탭에서 "이메일 주소 수집"은 **사용 안 함**으로 둡니다. (수집하면 확장에서 보내는 익명 전송이 필수 필드 누락으로 저장되지 않습니다. 답변용 이메일은 위 질문 2로 받습니다.)

## 2. 이메일 알림 켜기

1. 폼의 **응답** 탭 → ⋮ 메뉴 → **새 응답에 대한 이메일 알림 받기**를 켭니다.
2. 이후 문의가 들어올 때마다 폼 소유자 계정의 Gmail로 알림이 옵니다.

**이 알림에는 문의 내용이 담기지 않습니다.** "새 응답이 있습니다"와 응답 보기 링크뿐입니다. Google Forms 기본 알림의 동작이며 설정으로 바꿀 수 없습니다.

내용까지 메일로 받으려면 Apps Script 트리거(`양식 제출 시`)를 걸어 직접 보내야 합니다. **하지 않아도 됩니다** — 응답은 폼과 연결된 시트에 그대로 쌓이므로 유실되지 않고, 링크를 눌러 보면 됩니다.

## 3. 전송 주소와 entry ID 확인

1. 폼 편집 화면에서 ⋮ 메뉴 → **미리 채워진 링크 받기**를 선택합니다.
2. 문의 내용 칸과 (만들었다면) 답변 받을 이메일 칸에 아무 값이나 입력하고 **링크 받기 → 링크 복사**를 누릅니다.
3. 복사한 URL에서 값을 확인합니다.
   - `https://docs.google.com/forms/d/e/<긴 ID>/viewform?usp=pp_url&entry.123456789=...&entry.987654321=...`
   - **formUrl**: `viewform` 앞부분을 그대로 쓰되 `viewform`을 `formResponse`로 바꾼 값
     - 예: `https://docs.google.com/forms/d/e/<긴 ID>/formResponse`
   - **messageEntry**: 문의 내용에 해당하는 `entry.123456789` 부분
   - **emailEntry**: 답변 받을 이메일에 해당하는 `entry.987654321` 부분 (질문 순서대로 나타납니다)

## 4. 확장에 연결

`src/feedback.js`의 `FEEDBACK_CONFIG`에 두 값을 채웁니다.

```js
const FEEDBACK_CONFIG = {
  formUrl: "https://docs.google.com/forms/d/e/<긴 ID>/formResponse",
  messageEntry: "entry.123456789",
  emailEntry: "entry.987654321", // 이메일 질문을 만들지 않았다면 "" 유지
};
```

설정 전까지 문의 버튼을 누르면 "문의 채널이 아직 준비되지 않았습니다" 안내가 표시됩니다.
`emailEntry`를 비워두면 이메일 입력란은 화면에 나타나지 않습니다.

## 5. 동작 확인

1. 확장을 다시 로드한 뒤 팝업 → 문의하기 → 테스트 문의를 전송합니다.
2. 폼의 **응답** 탭에 내용이 도착했는지, 알림 메일이 왔는지 확인합니다.

## 6. 라이브 폼 점검

**설정했다고 믿지 말고 실제 폼을 확인합니다.** 3절의 "미리 채워진 링크 받기"는 처음 값을 알아내는 방법이고, 이것은 **그 설정이 지금도 그런지 검증하는 방법**입니다.

공개된 `viewform` 페이지에 폼 구조가 들어 있어 entry ID와 필수 여부를 한 번에 볼 수 있습니다.

```bash
FORM=https://docs.google.com/forms/d/e/<긴 ID>/viewform
curl -sL "$FORM" -o /tmp/form.html

python3 - /tmp/form.html <<'EOF'
import re, sys, json
html = open(sys.argv[1], encoding="utf-8").read()
data = json.loads(re.search(r'FB_PUBLIC_LOAD_DATA_ = (.*?);</script>', html, re.S).group(1))
for question in data[1][1]:
    for entry in (question[4] or []):
        print(f'"{question[1]}"  entry.{entry[0]}  필수={"O" if entry[2] else "X"}')
EOF
```

기대 출력입니다.

```text
"문의 내용"        entry.1096769292  필수=O
"답변 받을 이메일"  entry.491031779   필수=X
```

- **`문의 내용`이 `필수=X`면 빈 응답이 저장됩니다.** `formUrl`은 공개 페이지의 JS에 그대로 있어 누구나 `formResponse`에 직접 POST할 수 있고, 필수가 아니면 Google이 빈 요청을 그대로 받습니다. 확장과 랜딩이 빈 값을 막아도 그 경로는 우회됩니다. 실제로 응답 9개 중 8개가 빈 채로 쌓인 적이 있습니다(이슈 [#194](https://github.com/kangkyunghyun/LinKHU/issues/194)).
- **entry ID가 `src/feedback.js`·`docs/landing.js`의 값과 다르면** 보낸 내용이 존재하지 않는 필드로 들어가 `문의 내용`이 빈 채로 저장됩니다.

폼 질문을 고친 뒤에는 이 점검을 다시 돌립니다.

## 참고: 조용히 실패하는 것들

Google Forms는 CORS 응답 헤더를 제공하지 않아 응답 본문을 읽을 수 없습니다. 그래서 `fetch(..., { mode: "no-cors" })`로 보내고 네트워크 오류가 없으면 전송 성공으로 간주합니다.

**이 구조에서는 아래가 모두 오류 없이 잘못된 결과만 남깁니다.** 화면에는 "전송했습니다"가 뜹니다.

| 잘못된 것 | 결과 | 잡는 법 |
| --- | --- | --- |
| entry ID 오타 | 응답이 저장되지 않거나 빈 채로 저장 | 5절 테스트 전송, 6절 점검 |
| `문의 내용`이 필수가 아님 | 외부에서 온 빈 요청이 그대로 저장 | 6절 점검 |
| 설정 탭의 "이메일 주소 수집" 켜짐 | 익명 전송이 필수 필드 누락으로 저장 안 됨 | 5절 테스트 전송 |

설정을 바꿀 때마다 5절과 6절을 함께 확인하세요.
